Mutation Operator: Misuse of Structured Bindings with constexpr

Target Construct: Structured Bindings and constexpr variables

Mutation Rule:

1. Identify a structured bindings declaration in the seed program. This could look like:
   auto [x, y] = myStruct;

2. Modify the structured bindings declaration by introducing a constexpr source variable where the structured binding is resolved, ensuring the source variable is a constexpr of a struct type. For example:
   constexpr MyStruct myInstance{value1, value2};

3. Attempt to decompose the constexpr variable using structured bindings and ellipsis notation, which is not correctly supported, mimicking the bug situation:
   constexpr auto [x, ...rest] = myInstance;

Note: This mutation is intended to test the compiler's handling of structured bindings when applied to constexpr objects, especially when unnecessary or unsupported constructs (e.g., ellipsis in bindings) are introduced. This should reveal issues in the handling of the constexpr and structured bindings combination, potentially causing the compiler to crash or misbehave. This mutation aims to specifically exploit and test the constexpr and structured binding interaction.
