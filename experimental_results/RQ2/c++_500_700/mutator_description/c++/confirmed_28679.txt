Mutation Operator: Incorrect Usage of `decltype` with a Lambda Expression

Target: Lambda Expressions with `decltype` in Function Templates

Mutation Rule:
1. Identify a lambda expression within a function template.
2. Ensure the lambda incorrectly utilizes `decltype` that references a non-function type or improperly formed expression.
3. Modify the lambda expression to make use of `decltype` that does not correctly resolve to a valid type or function signature, thus introducing constructs that may confuse the compiler.

Example:
Original Code:
```
template <typename T>
void exampleFunction(T val) {
  [](int)->decltype(val) {
  };
}
```

Mutation:
1. Locate the lambda expression within the function template.
2. Alter the `decltype` in the return type specification of the lambda to an expression that is syntactically valid but semantically incorrect in the context.
3. For example, replace `decltype(val)` with `decltype(5 + val)` when `val` is of a type that doesn't support addition with an integer, such as a pointer or a user-defined type without an addition operator.

Mutated Code:
```
template <typename T>
void exampleFunction(T val) {
  [](int)->decltype(5 + val) {
  };
}
```

This mutation introduces a semantic error in the `decltype` usage, which could lead to unexpected behavior or crashes in the compiler when the template is instantiated with certain types, especially those that do not support the operations implied in the `decltype`.
