Mutation Operator: Lambda Expression With Requires Clause

Target Construct: Lambda functions within concept constraints.

Mutation Rule:
1. Identify a lambda function inside a concept constraint that employs a requires expression.
2. Modify the lambda function to introduce a nested requires expression, which includes using the same type parameter in a different context.

Step-by-Step Mutation Instructions:
- Locate the lambda function used within a concept constraint, for example:
  `[] { return requires(T t) { { t } -> doesnt_matter; }; }`
- Introduce a nested lambda within the original lambda that utilizes the requires clause:
  ```
  [] {
      return requires(T t) {
          { t } -> doesnt_matter;
          // New nested lambda with a separate requires clause
          [] {
              return requires(T inner) { { inner } -> doesnt_matter; };
          }();
      };
  }
  ```

Example Transformation:
Before Mutation:
```
template<class T>
concept test = 
    []{
        return requires(T t) {
            { t } -> doesnt_matter;
        };
    }();
```

After Mutation:
```
template<class T>
concept test = 
    []{
        return requires(T t) {
            { t } -> doesnt_matter;
            [] {
                return requires(T inner) { { inner } -> doesnt_matter; };
            }();
        };
    }();
```

Explanation:
By nesting a lambda within the existing lambda and applying a new requires clause that uses the same type parameter `T` in a different context, this mutation aims to explore complex interactions in the compiler's handling of concept constraints, potentially triggering more bugs related to type handling, scope management, and template instantiation. This mutation operator can be widely applied to any lambda expressions encountered in concept constraints, increasing its universality and coverage.
