Mutation Operator: Modify Use of Automatic Variables in `noexcept` within a Generic Lambda

Target: This mutation targets the use of automatic (local) variables within the `noexcept` clause of generic lambdas.

Mutation Rule:
1. Locate a generic lambda expression containing a `noexcept` specification.
2. Identify any automatic variables (local variables declared within the enclosing function) used directly within the `noexcept` clause.
3. Modify the `noexcept` clause to use a constant expression or a compile-time constant instead of the automatic variable.

Example:
Original Code:
```
struct true_type { constexpr operator bool() const { return true; } };

constexpr auto f() {
    true_type i;
    return [=](auto) noexcept(i) -> bool {
        return true;
    };
}
```

Mutated Code:
```
constexpr auto f() {
    true_type i;
    return [=](auto) noexcept(true) -> bool {  // Replace the use of the variable 'i' with 'true', a constant expression
        return true;
    };
}
```

By replacing the automatic variable `i` with a constant expression such as `true`, this mutation operator modifies the `noexcept` clause in a way that avoids the potential issue related to using local variables directly in this context. This operator is designed to target the specific code structure outlined in the bug report and applies generally to any similar use of automatic variables in `noexcept` clauses of generic lambdas.
