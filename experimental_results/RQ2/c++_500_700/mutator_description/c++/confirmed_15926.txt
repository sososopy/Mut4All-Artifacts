Mutation Operator: Modifying Nested Name Specifiers in Pointer-to-Member Expressions

Target: Code constructs involving nested-name-specifiers in pointer-to-member expressions.

Mutation Rule:
1. Identify any pointer-to-member expression within the code. This usually involves a syntax like `ClassName::*member`.
2. Introduce a nested-name-specifier that references a non-existent or irrelevant scope just before the pointer-to-member syntax. This could be another class or a namespace that does not contain the actual member being referenced.
3. Ensure that the introduced scope is syntactically valid but semantically incorrect in the context of the member access.

Example:
Original code:
```
class MyClass {
public:
    int member;
};

int MyClass::* ptr = &MyClass::member;
```

Mutated code:
```
namespace OtherNamespace {
    class MyClass {
    public:
        int anotherMember;
    };
}

// Introduce a nested-name-specifier "OtherNamespace::" that is irrelevant to the actual "MyClass"
int MyClass::* ptr = &OtherNamespace::MyClass::member;
```

Justification: This mutation exploits the compiler's handling of nested name specifiers when resolving pointer-to-member expressions. The mutation can potentially lead to crashes or undefined behavior due to semantic errors in scope resolution, which are common areas of vulnerability in compiler implementations. This operator is widely applicable in any codebase using pointer-to-member expressions.
