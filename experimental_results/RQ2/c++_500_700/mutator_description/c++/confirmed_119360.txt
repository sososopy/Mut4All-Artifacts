Mutation Operator

Target Construct: Variadic Function with Variable Argument Handling

Mutation Rule:
1. Identify a variadic function declaration using `va_list`, `va_start`, and `va_arg`.
2. Replace the `va_arg` type retrieval with a non-array type instead of an array or adjust the size of the array retrieval to ensure it doesn't match the expected size.
3. Ensure that the new type in `va_arg` is still compatible with the argument list of the function to avoid compilation errors.

Example of Mutation:
Given Seed Code:
```
void foo(uint32_t size, ...) 
{
    va_list args;
    va_start(args, size);

    (uint8_t*)va_arg(args, uint8_t[size]);

    va_end(args);
}
```

Mutation:
- Change the `va_arg` retrieval type to a pointer type directly or adjust the array size.

```
void foo(uint32_t size, ...) 
{
    va_list args;
    va_start(args, size);

    (uint8_t*)va_arg(args, uint8_t*); // Changed from array type to pointer type

    va_end(args);
}
```

Rationale:
This mutation targets the handling of variadic arguments, which is a complex part of C++ due to its reliance on runtime type interpretation. By altering the type expectation in `va_arg`, it manipulates how the compiler emits code for variadic functions, potentially exposing code generation bugs. This mutation is likely to cause issues when the codebase relies heavily on variadic functions, making it widely applicable across C++ programs that utilize such constructs.
