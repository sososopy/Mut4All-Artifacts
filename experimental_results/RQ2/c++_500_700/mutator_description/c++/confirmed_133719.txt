Mutation Operator: Nested Lambda with Init-Capture and Concept Constraints

Target Construct: Lambda expressions within function templates

Mutation Rule:
1. Identify a lambda expression within a function template in the seed program.
2. Modify the lambda to include an init-capture with a parameter that is another lambda expression.
3. Add a 'requires' clause with a trivial concept constraint to the innermost lambda to trigger potential inconsistencies with constraint satisfaction.
4. Ensure the lambda's return type is deduced with a simple return statement.

Example:
Given Seed Code:
```
template <typename T>
auto process(T value) {
    return [=](auto input) {
        return input + value;
    };
}
```

Apply Mutation:
1. Locate the lambda `[=](auto input)` within the function template.
2. Modify the lambda expression to include a nested lambda with init-capture:
```
template <typename T>
auto process(T value) {
    return [=](auto input) {
        return [captured{input}]() requires true {
            return captured + value;
        };
    };
}
```

This mutation operator targets the specific construct of nested lambdas with init-capture combined with trivial concept constraints, which are known to cause issues related to constraint satisfaction and capture instantiation in C++ compilers.
