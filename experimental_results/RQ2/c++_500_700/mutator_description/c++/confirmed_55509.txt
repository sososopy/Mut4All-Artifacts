
Mutation Operator: Modify Template Specialization and Function Signature Interaction

Target: Template class and function specialization constructs

Mutation Rule:
1. Identify a template structure with partial or full specialization, similar to 'struct A'.
2. Add a new member function within the specialized template that introduces a different function signature.
3. Ensure that the function signature involves default argument types or dependent types using templates or decltype, creating potential conflicts or ambiguities.

Steps:
1. Locate a specialized version of a template struct or class in the code. Example: struct A<0>.
2. Add a new member function to this specialized struct with a different signature that conflicts with an existing function. Use decltype for the return type to induce type deduction complexities.
3. Ensure the function signature includes parameters with default arguments or use of dependent types that might depend on template parameters.
4. The function should also interact with a template function or another template specialization, promoting complex type resolution.

Example in Pseudo-code:
```cpp
template<int N>
struct Container {
    template<typename T>
    friend auto process(const Container<N-1>&, T) {
        return N * 2;
    }
};

template<>
struct Container<0> {
    template<typename T>
    friend auto process(const Container<0>&, T);

    // New conflicting function signature
    template<typename T, typename U = decltype(process(declval<Container<1>>(), nullptr))>
    friend auto process(const Container<0>&, T, U = 0);
};
```

Explanation:
This mutation operator targets template specializations and creates situations where the function signatures within specialized templates might conflict or require complex type deductions, especially when interactions between multiple template instances using decltype or default parameters are involved. This can expose weaknesses in the compiler's template resolution mechanisms, potentially leading to crashes.
