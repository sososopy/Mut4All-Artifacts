Mutation Operator: Alter Const Generic Bounds

This mutation operator targets const generic parameter usage in function signatures and struct definitions where const generics are used to specify array lengths or other constant parameters. The mutation involves changing the bounds of the const generic parameter to a different valid compile-time constant expression. This applies to functions, trait methods, and structs using const generics.

Example:
Given the following code snippet in the seed program:
```rust
fn const_chunks_exact<const N: usize>(&self) -> ConstChunksExact<'_, T, {N}>
```

Mutation:
Change the `N` to be a different constant expression. If `N` is `{3}`, mutate it to `{2 + 1}` or another valid expression that results in the same value to check if the handling of expressions rather than direct constants triggers any compiler issues.

Mutated Content:
```rust
fn const_chunks_exact<const N: usize>(&self) -> ConstChunksExact<'_, T, {2 + 1}>
```

In the case of a struct definition:
Given:
```rust
struct ConstChunksExact<'a, T: 'a, const N: usize> {
    v: &'a [T],
    rem: &'a [T]
}
```

Mutation:
Change the `N` to a different expression that evaluates to the same value or to a different constant to observe if the compiler handles these correctly.

Mutated Content:
```rust
struct ConstChunksExact<'a, T: 'a, const N: usize> {
    v: &'a [T; N * 1], // Changed from using `N` directly
    rem: &'a [T]
}
```

This change leverages constant expressions in place of simple const values to uncover potential issues in Rust's const generics implementation, particularly in how expressions are evaluated and used in type layouts or method signatures.
