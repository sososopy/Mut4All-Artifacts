Mutation Operator: Async Function with Contrived Lifetime Bounds

Target: This mutation operator targets `async fn` definitions with lifetime parameters.

Description: This mutation operator introduces contrived lifetime bounds and conditions that can potentially trigger issues during the borrow checking or type checking phases of the Rust compiler. By adding unnecessary and conflicting lifetime parameters, we can explore how the compiler handles lifetime resolution in async contexts.

Application:
- Identify an `async fn` within the seed program that has lifetime parameters.
- Introduce additional lifetime parameters that are not connected to any existing references or data.
- Add conflicting or excessive lifetime bounds to these parameters.
- Ensure that the function body attempts to use these lifetimes in a nontrivial manner, such as by creating references that appear to depend on these lifetimes.

Example:
```rust
// Original async function
async fn example_function<'x, 'y>(param: &str) -> &str {
    // Some async code
    param
}

// Mutated content
async fn example_function<'x, 'y, 'z: 'y, 'a: 'b>(param: &'x str) -> &'a str {
    let temp: &'z str = param; // Create a reference with an unnecessary lifetime 'z
    let another_temp: &'b str = temp; // Attempt to use another conflicting lifetime 'b
    another_temp
}
```

Note: The mutation operator introduces lifetime `'_z'` which is redundant and `'_a: '_b'` which may create conflicting lifetime conditions. The body of the function attempts to use these lifetimes in a way that may not be logically necessary, potentially exposing compiler issues related to lifetime and async interactions.
