Mutation Operator: Insert a Non-Exhaustive Match Arm

This mutation operator targets match expressions, particularly those used in combination with enum types. It applies to any match statement in the code where all possible variants of an enum are handled.

Description:
Introduce a non-exhaustive match arm in an existing match statement. This mutation is likely to expose bugs related to enum handling, especially when the compiler does not properly enforce exhaustiveness or when logic errors occur in handling enums.

Steps for Mutation:
1. Identify a match statement that exhaustively covers all variants of an enum.
2. Introduce a new match arm with a wildcard pattern (`_`) that returns a default value or an error.
3. Ensure that the match arms still compile, and the program logic remains mostly unchanged for existing cases.

Example before mutation:
```
match width {
    One => { bytes.read_u8().ok()? as u64 },
    Two => { bytes.read_u16::<LittleEndian>().ok()? as u64 },
    Four => { bytes.read_u32::<LittleEndian>().ok()? as u64 },
    Eight => { bytes.read_u64::<LittleEndian>().ok()? as u64 }
}
```

Example after mutation:
```
match width {
    One => { bytes.read_u8().ok()? as u64 },
    Two => { bytes.read_u16::<LittleEndian>().ok()? as u64 },
    Four => { bytes.read_u32::<LittleEndian>().ok()? as u64 },
    Eight => { bytes.read_u64::<LittleEndian>().ok()? as u64 },
    _ => return None  // Introduced a non-exhaustive match arm
}
```

Note: This mutation introduces potential for undefined behavior or intentional fallbacks, which can help test the compiler's ability to handle match statements and exhaustiveness checks.
