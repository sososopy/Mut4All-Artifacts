Mutation Operator: Introduce Nested Lifetimes in `impl Trait`

This mutation operator targets function signatures using `impl Trait` with lifetimes. It applies specifically to situations where a function returns nested `impl Trait` types with explicit lifetime annotations. The goal is to introduce variations in lifetime structures to expose potential bugs related to lifetime handling within the compiler.

Where to Apply:
- In any function signature returning `impl Trait` types with lifetime parameters.

Mutation Description:
- Given a function returning a nested `impl Trait` with lifetime annotations, modify the existing lifetimes by introducing additional nested lifetimes or altering existing ones. The changes should maintain valid and coherent lifetime relationships to avoid compiler rejections based on incorrect lifetime usage.

Example of Mutation:
Original Function Signature:
fn complex_parser<'a>(input: &'a str) -> impl Iterator<Item = impl Iterator<Item = i32> + 'a> + 'a {
    // function body
}

Mutated Function Signature:
fn complex_parser<'a, 'b: 'a>(input: &'a str) -> impl Iterator<Item = impl Iterator<Item = i32> + 'b> + 'a {
    // function body
}

Explanation:
In this mutation, a new lifetime `'b` is introduced. It is specified that `'b` outlives `'a` (`'b: 'a`). The inner `impl Iterator` now uses `'b` as its lifetime, while the outer `impl Iterator` retains `'a`. By doing so, we create a scenario where the relationship between nested lifetimes is more complex, potentially uncovering issues in how the compiler manages such nested lifetimes within `impl Trait`.
