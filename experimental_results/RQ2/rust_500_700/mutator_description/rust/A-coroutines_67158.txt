Mutation Operator: Macro Expansion in Async Blocks with Yield

Targeted Construct: This mutation operator targets async blocks in Rust where the `yield` keyword is used in combination with a macro call. It applies in contexts where an async block contains a `yield` expression following or surrounded by macro invocations.

Description: This mutation operator aims to expose bugs related to the interaction between macros, the `yield` keyword, and async blocks. By altering the positions and interactions of these elements, the mutation can reveal issues in the Rust compiler's handling of coroutines and macros.

Transformation Steps:
1. Identify an async block in the code.
2. Look for occurrences of the `yield` keyword within this block.
3. Check if there is a macro invocation within the same async block.
4. Modify the code by:
   - Changing the order of `yield` and macro calls.
   - Nesting or unnesting macro calls within or around `yield`.
   - Adding additional trivial macro invocations around `yield` to increase complexity.
   - Altering the placement of `yield` relative to the `await` keyword, if present.

Example:
Original Code:
```
fn main() {
    async {
        yield some_macro_call();
    };
}
```

Mutation Example:
```
fn main() {
    async {
        some_macro_call();
        yield;
        another_macro!();
    };
}
```

In this mutation example, the `yield` expression is repositioned between two macro calls, and an additional macro is inserted. This modified structure challenges the compiler's capability to correctly handle coroutine transformations and macro expansions in async contexts. The mutation will utilize existing macros defined in the seed program, and if new macros are necessary, they should be declared in prior code sections.
