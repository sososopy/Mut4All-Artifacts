Mutation Operator: Generic Parameter in Array Patterns

Description:
This mutation operator targets array patterns where the size of the array is specified as a generic parameter. The mutation changes the use of a generic parameter in an array pattern to a concrete, compile-time constant, aiming to explore scenarios where generic parameters might lead to unexpected compiler behavior or internal errors. This is especially relevant in contexts where the compiler's resolution mechanism might struggle with generics.

Where it Applies:
This operator applies to function definitions or variable bindings where arrays are defined using generics as their size parameter, specifically in pattern matching contexts.

Mutation Steps:
1. Identify a variable binding or pattern where an array size is specified using a generic parameter (e.g., `let [T; N]`).
2. Replace the generic parameter `N` with a concrete constant value (e.g., `3`) that is valid in the context of the program.
3. Ensure that the replacement does not introduce undeclared lengths or types, requiring any new constants to be simple integer literals.

Example Before Mutation:
fn process<const N: usize>() {
    let [a, b]: [i32; N] = [1, 2];
}

Example After Mutation:
fn process<const N: usize>() {
    let [a, b]: [i32; 2] = [1, 2];
}

By forcing the array size to a concrete constant, the mutation operator tests whether the generic resolution logic that handles these patterns is robust against changes and appropriately raises errors when generic parameters are used in unexpected ways. The goal is to trigger potential edge cases in the compiler's handling of generics in patterns.
