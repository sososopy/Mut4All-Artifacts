Mutation Operator: Modify Pattern Matching Expressions with Additional Non-Exhaustive Patterns

This mutation operator targets pattern matching expressions in Rust code, specifically `match` statements. The operator applies to `match` expressions that utilize pattern matching with `or-patterns` or range patterns. The goal is to introduce additional non-exhaustive patterns to expose potential bugs related to pattern exhaustiveness checks, especially under code coverage instrumentation.

Example of a mutation:

1. Identify a `match` statement with patterns, such as:
   ```
   match (0u8, 0u8) {
       (0 | 1, 2 | 3) => { /* some code */ }
   }
   ```

2. Introduce an additional non-exhaustive pattern using a range or a value that is not currently covered by the existing patterns:
   ```
   match (0u8, 0u8) {
       (0 | 1, 2 | 3) => { /* some code */ }
       (4..=5, _) => { /* new block for additional pattern */ }
   }
   ```

3. Ensure that the new pattern does not overlap with existing ones and covers values not previously handled, potentially increasing the chances of triggering non-exhaustive pattern related bugs.

By introducing these mutations, the test coverage and pattern matching capabilities of the compiler can be stressed, especially when dealing with complex pattern scenarios or under special compiler flags like `-Z instrument-coverage`. This helps identify issues in the compiler's handling of patterns and exhaustiveness checks.
