Mutation Operator: Altering Lifetime Annotations in Function Signatures

This mutation operator targets function signatures where lifetime annotations are applied to references. It applies to functions that accept or return references with explicit lifetimes.

Description:
Identify functions in the seed program with explicit lifetime annotations on their parameters or return types. Modify the lifetime annotations by introducing mismatched or conflicting lifetimes that do not align with the original intent of the code. Specifically, change the lifetimes to either be identical (when they should differ) or introduce a new lifetime that does not match any existing lifetimes in the scope of the function.

Example of Mutated Content:
Consider a function signature in the seed program such as:

fn example<'a, 'b>(param1: &'a SomeType, param2: &'b SomeType) -> &'a SomeType {
    // function body
}

Apply the mutation by altering the lifetimes:

1. Make the lifetimes identical when they are supposed to be different:
fn example<'a>(param1: &'a SomeType, param2: &'a SomeType) -> &'a SomeType {
    // function body
}

2. Introduce a mismatching lifetime that is not defined in the current scope:
fn example<'c>(param1: &'c SomeType, param2: &'c SomeType) -> &'c SomeType {
    // function body
}

Rationale:
The mutation aims to expose bugs related to the lifetime management and borrow checking in Rust's type system. By creating mismatches and conflicts in lifetime annotations, the mutation can trigger issues in how the compiler reasons about lifetimes, potentially uncovering internal compiler errors or unexpected behavior in lifetime handling.
