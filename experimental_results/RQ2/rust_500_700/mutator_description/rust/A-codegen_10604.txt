Mutation Operator: Replace Enums with Structs Containing SIMD Vectors

This mutation operator targets enum definitions that contain SIMD (Single Instruction, Multiple Data) vectors within their variants. The goal is to replace such enums with equivalent structs that contain the same SIMD vectors to observe if the compilation or runtime behavior changes, potentially exposing code generation bugs.

Where it applies:
- This mutation is specifically applicable to enums where at least one of its variants includes a SIMD vector type. The SIMD vector type might be directly within a variant or nested within other types like tuples or arrays inside a variant.

Mutation Description:
- Identify enums that have one or more variants containing SIMD vector types (e.g., std::unstable::simd::i32x4).
- Convert the enum into a struct. If the enum has multiple variants, you can choose one of the variants (usually the problematic one) to refactor. The struct should contain a field for the SIMD vector, and any additional fields necessary to represent the data in the variant.
- If the enum had multiple variants, the corresponding struct will only reflect the chosen variant.

Example:
Given Seed Code:
enum ExampleEnum {
    Variant1,
    Variant2(std::unstable::simd::i32x4),
}

Mutation:
- Choose the Variant2 for transformation.
- Convert the enum into the following struct representation:

struct ExampleStruct {
    simd_vector: std::unstable::simd::i32x4,
}

- Update the usage of the enum in the code, if present, to reflect the new struct-based design.

This mutation operator encourages the exploration of how replacing enums containing SIMD vectors with equivalent structs impacts the compiler's code generation, potentially pinpointing issues related to how such structures are handled.
