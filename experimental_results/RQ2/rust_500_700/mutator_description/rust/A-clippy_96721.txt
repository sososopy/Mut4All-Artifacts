Mutation Operator: Literal Extraction Enhancement

Target: The mutation operator targets macro definitions, particularly those that involve literals.

Description: The operator modifies macro rules to include a greater variety of literal types beyond basic string literals. By introducing different literal types, such as integers, floating-point numbers, booleans, character literals, and expressions that result in literals, the macro processing logic within the compiler is tested for its ability to handle diverse token types and extract literals correctly.

Mutation Process:
1. Identify macro definitions in the seed program.
2. For each macro rule that contains a literal (e.g., a string like `"bar.rs"`), introduce additional literal types as alternative matches.
3. Ensure that these literals are incorporated in such a way that they expand to valid Rust code when the macro is invoked.

Example Mutation:
Original Macro:
```
macro_rules! foo {
    () => {"bar.rs"};
}
```

Mutated Macro:
```
macro_rules! foo {
    () => {42};                // integer literal
    () => {3.14};             // floating-point literal
    () => {'c'};              // character literal
    () => {true};             // boolean literal
    () => {5 + 10};           // expression resulting in a literal
}
```

Rationale: By expanding the types of literals used within macro definitions, the mutation operator increases the likelihood of triggering issues related to the compiler’s handling of macros and literal extraction. Testing these variations will help identify potential flaws in the compiler's ability to process different token types and ensure robust macro expansion handling.
