Mutation Operator: Modify Enum Variants with Uninhabited Types

Target: This mutation operator targets enum definitions that include variants with uninhabited types. It applies specifically to enums where one or more variants contain fields of types that cannot be instantiated, such as empty enums.

Description: In Rust, uninhabited types like empty enums (`enum Void {}`) are types that cannot have any valid values. When these types are used in enum variants, they can lead to unexpected behavior in transmutability checks. This mutation operator modifies the structure of such enum variants to include additional fields or change existing fields, potentially exposing issues in how the Rust compiler handles transmutability and layout calculations.

Mutation Steps:
1. Identify enum definitions in the seed program that contain variants with uninhabited types.
2. For each identified variant, add a new field of a primitive type (e.g., `u8`, `i32`) or replace an existing field with a different type.
3. Ensure that the modified enum is used in a context where transmutability is checked, such as in a function call to `assert::is_maybe_transmutable`.

Example:
Original Enum:
```
enum DistantVoid {
    A(Void, u128),
}
```

Mutated Enum:
```
enum DistantVoid {
    A(Void, u128, u8), // Added a new field of type `u8`
}
```

Usage in Transmutability Check:
```
assert::is_maybe_transmutable::<DistantVoid, ()>();
```

By modifying the enum variants in this way, the mutation operator can help uncover potential issues in the Rust compiler's handling of transmutability involving uninhabited types and their impact on layout calculations.
