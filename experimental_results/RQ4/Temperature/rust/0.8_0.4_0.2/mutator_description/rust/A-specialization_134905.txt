Mutation Operator: Add Unused Default Methods in Trait Implementations

Description:
This mutation operator targets trait implementations, particularly those using `default` type or methods within the context of specialization. The mutation involves adding unused `default` methods to existing trait implementations without affecting the current behavior of the code. The goal is to observe if the additional methods interfere with the specialization logic and trigger related compiler bugs.

Application:
This operator applies to any Rust code that implements traits and uses default types or methods, especially those employing specialization.

Steps to Apply:
1. Identify a trait implementation with a `default` type or method specified.
2. Introduce a new method within the implementation, ensuring it is marked as `default`.
3. The method should not be called or used within the existing code base, to maintain unused status.
4. Ensure the method signature is valid and adheres to the trait definition but introduces an arbitrary logic body.

Example:
Original Code:
```
trait MyTrait {
    type Item;
    fn do_something();
}

impl<T> MyTrait for T where T: SomeBound {
    default type Item = usize;
    default fn do_something() {
        println!("Doing something");
    }
}
```

Mutated Code:
```
trait MyTrait {
    type Item;
    fn do_something();
    fn unused_method();
}

impl<T> MyTrait for T where T: SomeBound {
    default type Item = usize;
    default fn do_something() {
        println!("Doing something");
    }
    
    default fn unused_method() {
        println!("This is an unused method");
    }
}
```

By integrating default methods that are not utilized, this mutation operator tests the Rust compiler’s handling of unused elements in specialized contexts, potentially uncovering issues related to specialization and method resolution.
