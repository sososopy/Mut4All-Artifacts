Mutation Operator: Modify Union Field Alignment

Target Code Construct: This mutation applies to union declarations that use the `#[repr(packed)]` attribute, specifically targeting unions with fields that have native alignment requirements different from the specified packed alignment.

Description: The mutation modifies the `#[repr(packed)]` attribute to change the packed alignment value to a different value. This is done to expose inconsistencies or misalignments in the union's field layout as interpreted by the Rust compiler, potentially triggering latent bugs related to layout computation.

Example:
Original Code:
```
#[repr(packed(1))]
union U {
    x: u32,
}

fn main() {
    let _ = U { x: 0 };
}
```

Mutated Code:
```
#[repr(packed(2))]
union U {
    x: u32,
}

fn main() {
    let _ = U { x: 0 };
}
```

Explanation: The mutation changes the `#[repr(packed(1))]` to `#[repr(packed(2))]`. This adjustment of the packing alignment from 1 to 2 bytes creates a potential mismatch between the specified packed alignment and the native alignment requirements of the field type (`u32`), which is typically 4 bytes. Such a mutation is likely to expose bugs related to alignment handling within the compiler's layout computation, especially in cases where the field's native alignment is a multiple of the packing alignment. This behavior is pertinent for internal compiler errors related to "alignment mismatch between ABI and layout."
