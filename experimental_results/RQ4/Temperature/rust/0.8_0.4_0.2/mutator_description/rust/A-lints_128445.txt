Mutation Operator: Insert Out-of-Range Literal in Macros

Description:
Target a macro definition in the seed program that generates a numeric literal. This mutation operator modifies the generated literal to be an out-of-range value for its type. This is intended to trigger bugs related to range checks and handling of numeric literals, which may expose issues similar to the one identified in the bug report where the Rust compiler crashes due to "literal out of range" diagnostics.

Application:
This mutation applies to macro definitions within Rust programs, specifically those that include numeric literals as part of their output.

How to Mutate:
1. Identify a macro definition within the seed program that generates a numeric literal.
2. Modify the numeric literal within the macro to be an out-of-range value for its specified type (e.g., change a u8 literal to a value greater than 255).
3. Ensure the mutated literal is syntactically valid but semantically incorrect due to being out of range.

Example:

Original Macro:
```rust
#[macro_export]
macro_rules! generate_value {
    () => { 100 }
}
```

Mutated Macro:
```rust
#[macro_export]
macro_rules! generate_value {
    () => { 300 } // Assuming the expected type is u8, 300 is out of range
}
```

The mutation operator targets macros that produce numeric literals, altering them to values exceeding the maximum for their assumed type (e.g., u8, i8, etc.). This tests the compiler's ability to handle out-of-range errors without crashing.
