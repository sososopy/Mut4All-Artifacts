Mutation Operator: Altering Lifetime Annotations in Function Signatures

Target: This mutation operator applies to function definitions that use lifetime annotations in their signatures, particularly when the function involves higher-ranked trait bounds or associated types with lifetimes.

Description: The mutation involves altering the lifetime annotations in the function signature to either remove the lifetime entirely or replace it with a different lifetime. The focus is on creating mismatches in expected lifetime bounds that can trigger latent bugs in the Rust compiler's handling of lifetime constraints.

Example of Mutation:

Original Function:
```
fn example(_: for<'a> fn(&'a u32, &'a str)) {}
```

Mutated Versions:
1. Remove the lifetime annotations:
   ```
   fn example(_: fn(&u32, &str)) {}
   ```
   
2. Replace lifetime `'a` with another lifetime:
   ```
   fn example(_: for<'b> fn(&'b u32, &'b str)) {}
   ```

Implementation Details:
- If the function signature already has multiple lifetimes, selectively alter one to create conflicts.
- If the lifetime is removed, ensure the function body (if any) is still valid or adjust accordingly to highlight the error at the signature level.
- If introducing a new lifetime, ensure it is declared in the function's scope and does not match any existing lifetimes used elsewhere in the function or struct definitions.

Purpose: This mutation operator aims to test the robustness of the compiler's lifetime inference and checking mechanisms. By creating situations where the compiler must resolve complex lifetime relationships or detect inconsistencies, this operator can help uncover bugs related to lifetime handling in the context of inherent associated types and higher-ranked trait bounds.
