Mutation Operator: Specialization Override

Target: This mutation operator applies to traits with associated types that use specialization.

Description: The specialization override mutation operator focuses on altering specialized implementations of trait associated types. Specifically, it introduces a more specific implementation of the associated type for a given concrete type, overriding the default. This mutation aims to uncover issues in the handling of specialized associated types and their interactions with default implementations.

Steps:
1. Identify a trait with an associated type and an existing default implementation that uses `specialization`.
2. Introduce a new implementation of the trait for a specific type that overrides the default associated type implementation.
3. Ensure the overriding implementation introduces a concrete, distinct type for the associated type.
4. Verify that this new implementation does not affect the generalization provided by other default implementations.

Example:

Consider a trait `SpecTrait` with a default associated type `Assoc`.

Original Code:
```
#![feature(specialization)]

pub(crate) trait SpecTrait {
    type Assoc;
}

impl<C> SpecTrait for C {
    default type Assoc = Vec<Self>;
}
```

Mutation:
Introduce a new implementation for a specific type, providing a different associated type:

```
impl SpecTrait for i32 {
    type Assoc = [i32; 3];
}
```

Explanation:
- The mutation introduces a specialized implementation of `SpecTrait` for the type `i32`, setting the associated type `Assoc` to an array with a fixed size, `[i32; 3]`, instead of the default `Vec<Self>`.
- This alteration tests the compiler's ability to handle multiple layers of specialization and the resulting MIR transformations, looking for potential issues in the overridden drop glue or handling of specialized types.
