Mutation Operator: Replace Const Generic with Non-const Generic

Target: This mutation operator targets trait definitions that use constant generics in associated types, specifically within the type bounds of associated types.

Where it applies: This operator applies to the definition of traits where associated types are constrained by another type that uses constant generics, as seen in the Rust code provided in the bug report.

Description: The mutation replaces the usage of constant generics in an associated type constraint with a non-const generic parameter. In this case, the constant `1i32` used in the type bound of the associated type `T` in trait `A` will be replaced with a generic parameter. This transformation explores how the compiler handles non-const generics in similar contexts, potentially revealing inconsistencies or additional bugs related to generic processing.

Example of Mutated Content:
Original Code:
```
trait A {
    type T: B<U<1i32> = ()>;
}
```

Mutated Code:
```
trait A {
    type T<const N: i32>: B<U<N> = ()>;
}
```

Explanation: In the mutated code, the specific constant `1i32` is replaced with a const generic parameter `N`. This transformation requires the introduction of a const generic parameter `N` in trait `A`. The constraint `U<1i32> = ()` is changed to `U<N> = ()`, maintaining the structure of the trait while altering how the generic is expressed. This encourages testing the compiler's handling of const generics versus non-const generics within associated type constraints.
