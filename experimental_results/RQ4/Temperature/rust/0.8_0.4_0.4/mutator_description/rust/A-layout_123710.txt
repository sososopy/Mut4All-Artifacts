Mutation Operator: Alter Union Field Types for ABI Compatibility

Description:
This mutation operator targets unions that contain fields with potentially differing ABI attributes, such as alignment or representation. The operator aims to modify the types of union fields to introduce a misalignment or ABI mismatch intentionally. This alteration can expose issues related to ABI compatibility, especially when enums or packed structs are involved.

Application:
The mutation applies to union definitions in the seed program that contain multiple fields of different types. The goal is to change one of the field types to one with a different, potentially conflicting ABI attribute.

Modification Steps:
1. Identify union definitions with multiple fields.
2. Select a field of type `u32` or similar primitive with a standard alignment.
3. Change this field to a type with a different ABI, such as a packed struct or a repr-packed enum.

Example:
Original Code:
```rust
union SampleUnion {
    int: u32,
    e: E,
}
```

Mutated Code:
```rust
union SampleUnion {
    int: S5, // Changed from `u32` to `S5`, which is a `#[repr(packed)]` struct
    e: E,
}
```

In this example, the `int` field's type is changed from `u32` to `S5`, a packed struct. This modification can lead to ABI compatibility issues when accessing the `int` field, especially when this union is used in contexts expecting standard alignment attributes. This change is intended to provoke the kind of assertion seen in the bug report by creating a deliberate ABI mismatch within the union.
