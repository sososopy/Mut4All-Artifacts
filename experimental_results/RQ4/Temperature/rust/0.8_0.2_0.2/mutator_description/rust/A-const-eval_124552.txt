Mutation Operator: Static Item Initialization with Different Struct Fields

Description: This mutation operator targets struct field initialization within static items. It applies to rust programs where a static item is initialized using a struct with multiple fields. The operator will modify the initialization of a static item by altering the type and values of the struct fields, especially focusing on type mismatches and missing fields, which are likely to trigger const-eval related bugs.

Application:
1. Identify a static item initialized with a struct that has multiple fields.
2. Modify the struct field initialization by:
   a. Swapping types of fields within the struct, ensuring that the new type is different from the original type to induce a potential type mismatch.
   b. Removing a required field from the initialization to simulate an incomplete struct initialization.
   c. Introducing a new field to the struct and omitting it during initialization to create a field mismatch.

Example in Pseudo-code:

Original Code:
```
struct Example {
    f1: i32,
    f2: bool,
}

static ITEM: Example = Example { f1: 10, f2: true };

fn main() {
    // Use ITEM
}
```

Mutated Code:
```
struct Example {
    f1: bool, // Field type swapped
    f2: i32, // Field type swapped
}

static ITEM: Example = Example { f1: 10 }; // Field f2 is removed, causing incomplete initialization

fn main() {
    // Use ITEM
}
```

In this example, the mutation operator swaps the field types within the `Example` struct, and the static item `ITEM` is initialized without the required field `f2`, likely triggering a type mismatch error during const evaluation.
