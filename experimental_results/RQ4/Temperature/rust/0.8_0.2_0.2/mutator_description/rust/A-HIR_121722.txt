Mutation Operator: Duplicate Field Names with Different Types

Description:
This mutation operator targets struct and union definitions within a Rust program. Specifically, it introduces a new field with the same name as an existing field but with a different type. This operator applies to both named and unnamed fields within structs and unions. The goal of this mutation is to expose issues related to field uniqueness and type handling in hierarchical data structures.

Where It Applies:
- In any struct or union definition, particularly those involving nested or anonymous fields.
- Both named and unnamed fields within the struct or union can be targeted for duplication.

Mutation Steps:
1. Identify a field within a struct or union that already has a defined name and type.
2. Duplicate this field by adding another field with the same name but specify a different type. 
3. Ensure the duplicated field is placed within the same struct or union, either directly or nested within another anonymous struct or union.

Example (Pseudo-code):
Given a seed program with a struct definition:

```
struct Example {
    field1: u8,
    field2: i32,
}
```

Apply the mutation:

```
struct Example {
    field1: u8,
    field1: f64, // Duplicate field name with a different type
    field2: i32,
}
```

Considerations:
- Ensure that the newly introduced field type (e.g., f64) is compatible with the Rust syntax and semantics.
- The mutation should maintain the overall program structure to ensure it remains compilable for testing purposes.
- When duplicating fields within nested or complex structures, take care to avoid excessive nesting that would obfuscate the mutation's intent.
