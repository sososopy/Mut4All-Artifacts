Mutation Operator: Introduce Range-Bound Literals in Macros

Target Code Construct: Macros that produce literal values.

Description: This mutation operator targets macros that output literal values, such as numbers, strings, or other primitives. It introduces literals that are close to boundary values, potentially triggering logic regarding "literal out of range" checks. The focus will be on altering existing numeric literals to edge cases or introducing new macro rules that include such edge cases.

Where it Applies: This mutation applies to any macro definition within the seed program that outputs literal values. It is particularly suited for macros that are used in computations or assignments where boundary values can affect logic or trigger compiler checks.

Mutation Description:
1. Identify macros within the seed program that produce literal values. If none exist, a new macro can be introduced with a clear definition.
2. Modify existing numeric literals in these macros to be boundary values. For example, if a macro contains a literal `1000`, mutate it to `i32::MAX`, `i32::MIN`, or similar boundary constants from different numeric types (`u8`, `u16`, etc.).
3. If introducing a new macro, define it to return boundary values. The macro should be declared within the context of the existing program, ensuring it's invoked somewhere appropriate.

Examples of Mutated Content:
Original Macro:
```
macro_rules! make {
    () => { 1000 }
}
```

Mutated Macro:
```
macro_rules! make {
    () => { i32::MAX }
}
```

Or, if a new macro is introduced:
```
macro_rules! boundary_values {
    () => { u8::MAX }
}
```
Ensure that the mutation is coherent with the existing program structure, using types and constructs already present in the seed program for high compatibility and coverage across different program structures and features.
