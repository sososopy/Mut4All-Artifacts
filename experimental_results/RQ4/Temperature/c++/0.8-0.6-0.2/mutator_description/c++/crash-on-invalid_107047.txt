Mutation Operator: Template Function Specialization Targeting Constexpr Functions

Target Code Construct: Function templates, particularly those with `constexpr` and template specialization.

Mutation Rule:
1. Identify a function template in the seed program that is marked as `constexpr`.
2. Introduce incorrect template specialization by:
   a. Creating a function call to the template function, but specify an invalid template argument that cannot be deduced or doesn't match any valid type. This can be an integer or a type that doesn't exist.
   b. Ensure the function is within a class or namespace scope to mimic real-world complex usage.
3. Avoid using new types; use existing types or introduce simple ones like `int` if necessary to demonstrate the transformation.

Example:

Original Code:
```cpp
template <typename T>
struct Container {
    static constexpr auto getValue() {
        return 42;
    }
};

void test() {
    int x = Container<int>::getValue(); // Correct call
}
```

Mutated Code:
```cpp
template <typename T>
struct Container {
    static constexpr auto getValue() {
        return 42;
    }
};

void test() {
    int x = Container<int>::getValue<1>(); // Incorrect specialization
}
```

Explanation:
This mutation operator targets the function template specialization aspect of `constexpr` functions. By introducing an incorrect template argument where no specialization was intended, it exploits the compiler's handling of template arguments, which can result in assertion failures or crashes if not properly managed. This operator has a high potential for universality and coverage, as templates and constexpr are widely used in modern C++ code.
