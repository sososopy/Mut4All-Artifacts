Mutation Operator: Modification of Function Template Return Type

Target Code Construct: Function Template

Mutation Rule:
1. Identify a function template in the seed program with an undefined or generic return type, such as `auto` or `decltype(auto)`. The function template should be defined but not fully specified in terms of its return type.

2. Modify the return type of the function template to a concrete type. If the function template currently has `auto` or `decltype(auto)` as its return type, replace it with a specific type like `int`, `double`, or `void`.

3. Ensure that if the function body is defined, the return statements within the function are compatible with the newly specified return type. Adjust return statements as necessary to maintain type consistency.

Example in Pseudo-code:
Original:
```
template <typename T>
auto functionTemplate(int param);
```

Mutated:
```
template <typename T>
int functionTemplate(int param);
```

Explanation:
In this mutation operator, we focus on the return type of function templates that use `auto` or `decltype(auto)`. By replacing them with a concrete type like `int`, we prompt the compiler to resolve the function's return type at the template definition phase, potentially revealing issues in type deduction or template instantiation that could lead to compiler crashes. The use of concrete types helps ensure that the mutation is applicable across a wide range of seed programs and increases the likelihood of exposing bugs in the compiler's handling of return types.
