Mutation Operator: Misuse of Template Specializations in Function Parameters

Target Code Construct: Function Templates

Mutation Rule:
1. Identify a function template that takes a templated type as a parameter. For example, a function template `void f(B<const T> p)` where `B` is a template type.
2. Modify the template specialization in the function parameter in a way that causes the type system to infer incorrect or incomplete template arguments, leading to a type inconsistency.
3. Specifically, change the specialized type in the function parameter to a more constrained version that may not be handled by the current specialization logic, causing a crash or unexpected behavior.

Pseudo-code Example:
Original Function:
template<class T> void f(B<const T> p);

Mutation:
Template specialization could be changed from `const T` to another form that increases the complexity for type deduction without providing a complete definition:
template<class T> void f(B<T* const> p);

Explanation:
This mutation operator increases the potential for compiler crashes by manipulating the template parameter in a way that interacts improperly with the template specialization logic, potentially leading to a null type pointer retrieval as seen in the bug report. The choice to apply pointer const-qualification within the template argument introduces a new constraint that forces the compiler to navigate additional complexities during type resolution. This operator is versatile for testing compiler robustness against template misuse and complex specialization scenarios.
