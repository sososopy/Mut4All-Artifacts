Mutation Operator: Atomic Type Mismatch in Comparisons

Target Code Construct: Comparison operations within function bodies, specifically involving atomic types.

Mutation Rule:
1. Identify a comparison operation within a function body where one operand is an atomic type. For example, locate a comparison in the form `if (atomicVar == otherVar)`.
2. Ensure that the atomic variable is of a specific type, such as `std::atomic<unsigned int>`.
3. Replace the non-atomic operand in the comparison with a variable of a different non-matching type, such as a simple `int`, to create a type mismatch. For instance, change the comparison to `if (atomicVar == intVar)`.
4. Ensure both the atomic and non-atomic variables are declared and initialized in the program:
   - Declare `std::atomic<unsigned int> atomicVar = 0;`
   - Declare `int intVar = 0;`

Examples in Pseudo-Code:
Original:
```
void checkValues() {
    std::atomic<unsigned int> atomicVar = 10;
    unsigned int otherVar = 20;
    if (atomicVar == otherVar) {
        // Code block
    }
}
```

Mutated:
```
void checkValues() {
    std::atomic<unsigned int> atomicVar = 10;
    int intVar = 20; // Changed type to int
    if (atomicVar == intVar) { // Introduced type mismatch
        // Code block
    }
}
```

This mutation targets situations where the comparison of atomic and non-atomic types may lead to type mismatches, potentially triggering compiler assertion failures or crashes.
