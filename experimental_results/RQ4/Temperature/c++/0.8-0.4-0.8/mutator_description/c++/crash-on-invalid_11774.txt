Mutation Operator: Namespace Nesting Complexity

Target: Namespace declaration

Mutation Rule:
1. Identify a series of nested namespaces in the code.
2. Introduce an additional level of nested namespaces within the existing ones.
3. Use existing namespaces or create new ones with clear and distinct names.
4. Ensure that the newly introduced namespace does not already exist to prevent redeclaration conflicts.
5. Place a semicolon after the new namespace declaration to simulate the parser token issue often seen in clang.

Example:
Original Code:
namespace outer {
    namespace inner {
        // existing code
    }
}

Mutated Code:
namespace outer {
    namespace inner {
        namespace extra {
            // existing code
        }
    }
}

In this mutation, a new namespace 'extra' is introduced within the existing 'inner' namespace. This increases the complexity of the namespace nesting and may trigger existing issues within the parser's handling of deeply nested namespaces, particularly with semicolon placements. This type of mutation could potentially cause issues similar to those reported in the bug report.
