Mutation Operator

Target: Template Function Instantiation

Mutation Rule: Modify the usage of a template function instantiation to deliberately ignore the 'template' keyword when referring to a nested template within another template's member function. This mutation applies in contexts where a nested template needs to be explicitly specified.

Steps:
1. Identify a template class with a member function that itself is a template.
2. Inside this class, find a function or method that instantiates this member function template in a templated manner.
3. Remove the 'template' keyword in the expression where you instantiate the nested template function, making it ambiguous.

Example:
Consider a template class `Container` with a member template function `add`.

Original Code:
```cpp
template <typename T>
class Container {
public:
  template <typename U>
  void add(U element) {}
};

template <typename V>
void process() {
  Container<V> container;
  container.template add<int>(5); // correct usage
}
```

Mutated Code:
```cpp
template <typename T>
class Container {
public:
  template <typename U>
  void add(U element) {}
};

template <typename V>
void process() {
  Container<V> container;
  container.add<int>(5); // mutated usage, omitting 'template'
}
```

In this mutation, the explicit `template` keyword is removed, which can confuse the compiler, especially if `add` could be misinterpreted as a non-template member function or a different context entity. This mutation exploits the complexity of template syntax and dependent names.
