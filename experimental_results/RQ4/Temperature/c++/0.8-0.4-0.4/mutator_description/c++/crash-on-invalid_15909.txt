Mutation Operator: Atomic Type Comparison

Target: Comparison operations involving atomic types

Mutation Rule:
1. Identify a comparison operation in the seed program where an atomic type is compared with a non-atomic type. This could involve relational operators like `==`, `!=`, `<`, `>`, `<=`, `>=`.
2. Ensure that the atomic type is an atomic version of an integer type (e.g., `std::atomic<int>`, `std::atomic<unsigned int>`).
3. Introduce a mismatch in the comparison by explicitly converting the atomic type to a non-atomic type or vice versa. This can be done by either using `load()` method for atomic types or by casting the non-atomic type to its atomic equivalent.
4. For example, if the original comparison is `std::atomic<int> a == int b`, mutate it to `a.load() == b` or `a == static_cast<std::atomic<int>>(b)`.

Example in Pseudo-code Form:
Original:
```
std::atomic<int> atomicVal = 5;
int normalVal = 5;
if (atomicVal == normalVal) {
    // Some code
}
```

Mutated:
```
std::atomic<int> atomicVal = 5;
int normalVal = 5;
if (atomicVal.load() == normalVal) {
    // Some code
}
```

Note: Ensure that all variable declarations are adapted from existing seed program contexts, and avoid introducing undeclared or ambiguous types.
