Mutation Operator: Undefined Variable in Lambda

1. Target Code Construct:
   The mutation operator targets lambda expressions that attempt to infer a return type from an undefined variable. This operator applies specifically to lambda functions within the code.

2. Mutation Rule:
   a. Identify a lambda function in the seed program.
   b. Within the lambda block, introduce a return statement that uses a variable not declared within the lambda's scope or in any accessible scope.
   c. Ensure that this variable is used in a way that the compiler must infer the lambda's return type from it.

3. Example:
   Original Code:
   ```
   auto myLambda = []() {
       return 42;
   };
   ```

   Mutated Code:
   ```
   auto myLambda = []() {
       return undefinedVar; // 'undefinedVar' is not declared in any accessible scope
   };
   ```

4. Explanation:
   - The mutation introduces a return statement with an undefined variable within a lambda function, aiming to cause the compiler to crash while trying to infer the return type.
   - This mutation can be broadly applied to any lambda function within a seed program, increasing its universality and coverage.
   - The undefined variable 'undefinedVar' is deliberately not declared, ensuring that it triggers a type inference issue related to undefined variables.
