Mutation Operator:

Target Code Construct: Lambda Function

Mutation Rule:
1. Identify a lambda function with a defined return type.
2. Change the return type to a function type or an invalid type that is not permissible as a return from a lambda function.
3. Ensure that the lambda's body makes use of a variable that is not declared within the lambda or its enclosing scope.

Step-by-step Mutation Instructions:
- Locate a lambda function in the code, for example:
  `[] (Type1 param1, Type2 param2) -> ReturnType { /* body */ }`
- Change the return type to a non-permissible type, like a function type:
  `[] (Type1 param1, Type2 param2) -> int (int) { /* body */ }`
- Within the lambda body, introduce or use a variable that is not declared:
  `[] (int x) -> int (int y) { std::cout << x << y << std::endl; return x * y; }`

Example:
- Original lambda:
  `[] (int x) -> int { return x + 1; }`
- Mutated lambda:
  `[] (int x) -> int (int y) { std::cout << x << y << std::endl; return x * y; }`

Explanation:
1. The change in return type from a valid type (e.g., `int`) to a function type (e.g., `int (int)`) is intended to exploit the compiler's handling of invalid return types.
2. By introducing an undeclared variable `y` within the lambda, it triggers undeclared identifier errors, which may lead to complex parsing issues that could result in a compiler crash.
3. This mutation operator focuses on lambda expressions, which are commonly used and can exhibit a range of behaviors when incorrectly specified, providing a wide coverage for potential bugs.
