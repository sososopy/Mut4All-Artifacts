Mutation Operator: Modify Template Instantiation with Incorrect Template Argument

Target Code Construct: Template Class Instantiation and Member Access

Mutation Rule:
1. Identify a template class instantiation in the seed program. This is typically a section of code where a template class (e.g., `S<T2>`) is utilized with a specified type argument.
2. Locate a member access operation on the instantiated template class. For example, `&S<T2>::S<int>`.
3. Modify the member access to incorrectly specify a nested template, missing the `template` keyword required for dependent template names. This simulates the error from the bug report.
4. If the `template` keyword is present in the original code, remove it in a section where it is required to introduce the error.
5. Ensure the nested template instantiation lacks the keyword that would avoid the dependent template name error.

Example (Pseudocode):

Original Code:
```
template <typename T> struct Container {
  template <typename U>
  Container(U) {}
};

template <typename X>
auto create() {
  return &Container<X>::Container<int>;
}
```

Mutated Code:
```
template <typename T> struct Container {
  template <typename U>
  Container(U) {}
};

template <typename X>
auto create() {
  return &Container<X>::Container<int>; // Mutation: missing 'template' keyword
}
```

This mutation intentionally introduces a situation that may cause the compiler to crash by violating dependency resolution rules in template instantiation, targeting parts of the code that involve templates and nested templates within template classes.
