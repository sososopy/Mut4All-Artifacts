Mutation Operator: Template Specialization with Invalid Condition

Target Code Construct: Template Function

Mutation Rule:
1. Identify a template function within a struct or class that uses a type trait or condition to enable or disable its instantiation (e.g., using `enable_if`).
2. Modify the condition within the `enable_if` or similar construct to reference a non-existent or invalid member of a type, such as a member that does not exist in the type's definition.
3. Ensure that the modified condition is syntactically correct but semantically incorrect, leading to a potential compiler crash.

Example:
Original Code:
```
struct Example {
  template <bool B, typename T = void> struct enable_if;
  template <typename T> struct enable_if<true, T> { typedef T Type; };

  template <typename T>
  static typename enable_if<SomeTrait<T>::value, void>::Type process() {
    // Function implementation
  }
};
```

Mutated Code:
```
struct Example {
  template <bool B, typename T = void> struct enable_if;
  template <typename T> struct enable_if<true, T> { typedef T Type; };

  template <typename T>
  static typename enable_if<SomeTrait<T>::non_existent_member, void>::Type process() {
    // Function implementation
  }
};
```

Explanation:
- The mutation targets the condition within the `enable_if` construct.
- The original condition `SomeTrait<T>::value` is replaced with `SomeTrait<T>::non_existent_member`, which does not exist.
- This mutation is designed to test the compiler's handling of invalid template conditions, potentially leading to a crash if not properly managed.
