Mutation Operator: Misuse of Macros in Constant Expressions

Target Code Construct: Macros and Constant Expressions

Mutation Rule:
1. Identify a macro definition in the seed program that performs an operation, such as a comparison or arithmetic operation.
2. Locate a constant expression in the program where a macro is used, particularly within a `constexpr` context.
3. Modify the macro usage in the constant expression to include a non-constant or runtime-dependent expression, such as accessing a member of a struct or a pointer dereference.
4. Ensure that the modified expression still compiles but introduces a logical inconsistency that the compiler might not handle gracefully.

Example:
Original Code:
```
#define max(a, b) ((a) > (b) ? (a) : (b))

struct data {
    int value;
};

void example(struct data *d) {
    constexpr int result = max(5, d->value);
}
```

Mutated Code:
```
#define max(a, b) ((a) > (b) ? (a) : (b))

struct data {
    int value;
};

void example(struct data *d) {
    constexpr int result = max(5, d->value); // Use of non-constant expression in constexpr
}
```

Explanation:
The mutation involves using a macro within a `constexpr` that includes a non-constant expression (`d->value`). This misuse can lead to undefined behavior or compiler crashes, especially if the compiler does not handle such cases robustly. The mutation targets the interaction between macros and constant expressions, which is a common source of bugs in C++ compilers.
