Mutation Operator: Undefined Class Method Invocation

Target: Class methods that are declared but not defined.

Mutation Rule:
1. Identify a class that has a declared method but lacks a definition within the class. This can be a method that is declared in the class interface but not implemented in the class body or any associated implementation file.
2. Directly invoke this undefined method within a member function or outside the class where the method should be utilized.
3. Ensure that the invocation of the undefined method is performed with arguments that correspond to its declaration.
4. If the class already has an instance in the code, use this instance to call the method; otherwise, declare a new instance of the class and use it for the invocation.

Example:
Consider a class `Example` with a declared method `void unimplementedMethod();` but without a definition.

Original Code:
```
class Example {
public:
    void definedMethod() {
        // Some implementation
    }
    void unimplementedMethod(); // Declared but not defined
};

// Some other function
void testFunction() {
    Example ex;
    ex.definedMethod();
}
```

Mutated Code:
```
class Example {
public:
    void definedMethod() {
        // Some implementation
    }
    void unimplementedMethod(); // Declared but not defined
};

// Some other function
void testFunction() {
    Example ex;
    ex.definedMethod();
    ex.unimplementedMethod(); // Invoke the undefined method
}
```

Rationale:
By invoking a method that is declared but lacks a definition, the compiler is forced to handle a situation where there's an expectation for a symbol that doesn't exist. This can lead to a crash during the compilation process, particularly in the handling of linking or symbol resolution. The mutation specifically targets the gap between declaration and definition, which is a common source of inconsistency and errors in C++ programs.
