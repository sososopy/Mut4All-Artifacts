Mutation Operator: Modify Function Call Argument Types

Target Construct: Function Calls

Mutation Rule:
1. Identify a function call within the code, particularly those using built-in functions or library functions.
2. Select one of the arguments of the function call that is expected to be of a specific type (e.g., integer, float, etc.).
3. Change the type of the selected argument to a different type that is incompatible with the expected type. For example, if the argument is expected to be an integer, change it to a floating-point literal or a string.
4. Ensure that the modified argument is syntactically valid but semantically incorrect.

Example:
Original Code:
```
int result = __builtin_fpclassify(0, 1, 4, 3, 2, 1.0);
```

Mutated Code:
```
int result = __builtin_fpclassify(0, 1, 4, 3, 2, "invalid_type");
```

Explanation:
In this mutation, the last argument of the `__builtin_fpclassify` function, which is expected to be a floating-point value, is changed to a string literal. This type mismatch is likely to trigger a compiler error or crash, especially in functions that perform type-specific operations. This mutation operator can be applied to various function calls across different seed programs, providing broad coverage and a high likelihood of exposing type-related issues in the compiler.
