Mutation Operator: Modify Concept Definition with Nested Requires Clauses

Target: Concept Definitions

Mutation Rule:
1. Identify a concept definition that uses a `requires` clause. Ensure the concept is defined using the `concept` keyword.
2. Introduce a nested `requires` clause within the existing `requires` clause. This involves adding a second `requires` keyword inside the braces of the first `requires` clause.
3. Ensure that the nested `requires` clause contains expressions that involve existing types or variables in the program, or introduce simple new types or variables if necessary.
4. Ensure the syntax is incorrect by omitting necessary components such as the body of the `requires` clause, leading to a malformed concept definition.

Example:
Original Concept Definition:
```
template <typename T>
concept Addable = requires(T a, T b) { a + b; };
```

Mutated Concept Definition:
```
template <typename T>
concept Addable = requires requires(T a, T b) { a + b; };
```

In this mutation, the nested `requires` clause is introduced without a proper body, creating a scenario that is likely to trigger a compiler error or crash due to the malformed structure.
