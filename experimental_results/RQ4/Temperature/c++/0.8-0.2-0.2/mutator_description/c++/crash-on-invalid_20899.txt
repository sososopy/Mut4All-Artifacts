
Mutation Operator: Template Instantiation with Invalid Condition

Target Code Construct: Template function definitions

Description: This mutation operates on template functions where a type trait or condition is used in an `enable_if` or similar construct. The mutation involves modifying the condition in such a way that it refers to non-existent or inaccessible members, which can lead to compiler crashes during template instantiation.

Mutation Rule: 
1. Identify a template function where a condition is used to enable or disable the function, typically using a construct like `enable_if`.
2. Modify the condition within the `enable_if` to reference a non-existent member or invalid type condition.

Step-by-Step Instructions:
- Locate a template function that uses `enable_if`, such as `typename enable_if<Foo<T>::bar, void>::Type`.
- Change the condition in the `enable_if` to one that is invalid or refers to a non-existent member. For instance, if the original condition is `Foo<T>::bar`, mutate it to `Foo<T>::non_existent_member`.
- Ensure that `Foo<T>` is a valid instantiation, but that `non_existent_member` does not exist, which can lead to a crash when the compiler attempts to instantiate the template.

Example:
Original:
```cpp
template <typename T>
static typename enable_if<Foo<T>::bar, void>::Type method() {
}
```
Mutated:
```cpp
template <typename T>
static typename enable_if<Foo<T>::non_existent_member, void>::Type method() {
}
```

Note: The mutation should be applied carefully to maintain the validity of the overall program structure, ensuring that `Foo<T>` itself is a valid type but has no member named `non_existent_member`. This mutation can trigger errors during template instantiation, particularly in compilers not robust against certain invalid template conditions.
