Mutation Operator: Nested Template Instantiation in Class Templates

Target Code Construct:
This mutation operator targets class templates with nested template instantiation within a member function or constructor.

Mutation Rule:
1. Identify a class template that contains a member function or a constructor where a nested template instantiation is used.
2. Modify the nested template instantiation to use a new template parameter. If a template parameter does not exist, add a new template parameter to the class template.
3. Within the function or constructor, modify the nested template instantiation by adding a template that depends on this new parameter, intentionally omitting the `template` keyword when required by the language rules to cause ambiguity in dependent contexts.
4. This mutation should be mainly applied to template specialization or nested templates within the class template.

Example:
Original Code:
```cpp
template <typename X>
struct Wrapper {
  template <typename Y>
  void process(Y value) {
    // Original nested template instantiation
    Nested<X>::apply(value);
  }
};
```

Mutated Code:
```cpp
template <typename X, typename Z>
struct Wrapper {
  template <typename Y>
  void process(Y value) {
    // Modified nested template instantiation, omitting 'template' keyword
    Nested<Z>::apply<int>(value);
  }
};
```

Explanation of Mutated Content:
- A new template parameter `Z` is introduced to the class template `Wrapper`.
- Within the `process` member function, the nested template instantiation is modified to use `Z` instead of `X`, and the `template` keyword is omitted before `apply<int>`, creating a potentially ambiguous reference to a dependent template name. This mutation specifically aims to challenge the compiler's template instantiation and name lookup mechanisms, potentially triggering bugs related to template handling.
