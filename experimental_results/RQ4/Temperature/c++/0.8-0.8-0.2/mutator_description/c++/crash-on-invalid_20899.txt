Mutation Operator: Template Instantiation in Static Member Functions

Target: This mutation operator targets static member functions within a struct that use template metaprogramming, specifically where the code instantiates a template with conditions that may not be met.

Mutation Rule:
1. Identify a static member function within a struct that uses a template metaprogramming construct (e.g., `enable_if`) to conditionally define a type or behavior.
2. Locate the condition typically associated with a template argument that dictates whether a particular type or function is enabled.
3. Modify the condition expression in the template instantiation such that it refers to a non-existent or invalid member, ensuring the condition cannot be met. For example, change `Foo<T>::bar` to `Foo<T>::nonExistentMember`.
4. Ensure that the modification does not involve changing the name or creating new template structures but instead focuses on altering existing logic conditions.

Example:
Original Code:
```
struct Container {
  template <bool B, typename T = void> struct enable_if;
  template <typename T> struct enable_if<true, T> { typedef T Type; };

  template <typename T>
  static typename enable_if<Feature<T>::available, void>::Type execute() {
    // Functionality when condition is met
  }
};
```

Mutated Code:
```
struct Container {
  template <bool B, typename T = void> struct enable_if;
  template <typename T> struct enable_if<true, T> { typedef T Type; };

  template <typename T>
  static typename enable_if<Feature<T>::nonExistentMember, void>::Type execute() {
    // Functionality when condition is met
  }
};
```

By altering the condition to one that refers to a non-existent member (`nonExistentMember`), it increases the likelihood of triggering a compiler crash due to invalid template instantiation logic. This mutation is applicable to any struct with similar static member functions employing template metaprogramming techniques.
