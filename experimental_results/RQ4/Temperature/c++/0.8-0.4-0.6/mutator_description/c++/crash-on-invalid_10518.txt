Mutation Operator: Altering Template Specialization Context

Target Code Construct: Template Specialization in Function Definitions

Mutation Rule:
1. Identify a function template definition, ensuring there is at least one template parameter.
2. Introduce a template specialization directly within the function body that uses a type different from the declared template parameter type.
3. Within the specialized template, introduce a member access operation (`.` or `->`) on a type that does not support it, causing a semantic mismatch.
4. Ensure the template specialization is invoked within the function.

Example of Mutation:
Given a seed program with a function template:
```
template <typename T>
void exampleFunction(T t) {
    // Original content
}
```

Apply the mutation:
```
template <typename T>
void exampleFunction(T t) {
    // Introduce incorrect specialization
    if constexpr (std::is_same_v<T, int>) {
        struct InvalidType { int value; };  // Create a new struct
        InvalidType instance;
        instance.nonExistentMember = 5;  // Access a non-existent member
    }
}
```

Explanation:
- The mutation introduces a conditional template specialization for `T` when it is of type `int`.
- Inside this specialization, a new struct `InvalidType` is declared, introducing a member `value`.
- A member `nonExistentMember` is accessed on an instance of `InvalidType`, which does not exist, creating a semantic inconsistency likely to confuse the compiler's template instantiation and semantic analysis process, potentially triggering a crash.
