Mutation Operator - Invalid Structured Binding in Lambda Capture

Target Construct: Lambda Expressions with Captured Variables

Mutation Rule:
1. Identify lambda expressions within the code that capture variables.
2. Select a structured binding declaration that is part of the capture list or introduce a new structured binding using existing types in the code. Ensure the binding is invalid by referencing non-existing fields or elements.
3. Apply the invalid structured binding within the capture list of the lambda.

Example:
Original Code:
```
auto& [a, b] = existing_function();

auto lambda = [a, b]() {
    return a + b;
};
```

Mutated Code:
```
auto& [a, b] = existing_function();

auto lambda = [a, b, c]() { // Introduce invalid structured binding by using 'c' which is not declared
    return a + b;
};
```

Explanation:
This operator targets lambda expressions by altering the capture list to include invalid structured bindings, specifically using undeclared or non-existing elements. This leverages the compiler's need to resolve captures and structured bindings, potentially triggering crashes or unexpected behavior in the presence of invalid code constructs. This mutation exploits the compiler's semantic analysis phase, which is where such bugs typically manifest.
