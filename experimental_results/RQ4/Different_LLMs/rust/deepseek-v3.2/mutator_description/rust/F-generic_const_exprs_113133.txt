Mutation operator: Insert a const function call inside a const generic parameter default value in a `for<...>` binder in a where clause.

This mutation operator applies to Rust programs that use the `generic_const_exprs` and `non_lifetime_binders` features. It targets the specific code construct where a `for<...>` binder with const generic parameters is used in a where clause. The operator modifies the default value expression of a const generic parameter within such a binder by inserting a call to a const function. The const function must be defined in the same scope. The mutation changes the default value from a simple constant expression to a block that defines a const function and then calls it, returning a constant value.

Specifically, for a seed program containing a const function `const_fn` and a where clause with a `for<const N: usize = DEFAULT>` binder, the operator transforms the default value `DEFAULT` into `{ const fn helper() { const_fn(); } helper(); DEFAULT }`. This introduces a new const function `helper` that calls the existing const function `const_fn`, then calls `helper`, and finally evaluates to the original `DEFAULT`. The operator should use an existing const function from the seed program for the call inside `helper`. If no const function exists, one must be created: a simple const function returning a unit type `()` should be added to the crate root, e.g., `const fn new_const_fn() {}`. The mutation must ensure that all identifiers used are in scope; the new helper function is defined locally within the block.

Example transformation: Given a seed with `const fn bar() {}` and a where clause `for<const N: usize = 1> () :`, mutate to `for<const N: usize = { const fn helper() { bar(); } helper(); 1 }> () :`. The constant `1` is preserved as the final expression. The operator should adapt to any existing const function name and any default value expression. The inserted block must be a valid constant expression. This mutation stresses the compiler's handling of const evaluation within generic parameter defaults, particularly in the context of late-bound generic parameters introduced by `for<...>` binders.
