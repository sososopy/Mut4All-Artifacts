Mutation Operator:
Target: Replace a const generic argument in a trait bound with a const expression that references a generic type parameter.

This mutation applies when a seed program contains a trait bound of the form `T: Trait<ConstParam = {value}>` where `Trait` has an associated constant that is generic over a type. The operator changes the const argument `{value}` to a const expression that uses a generic type parameter `T` from the surrounding context, such as `{std::mem::size_of::<T>()}`. The new const expression must be valid in a const context and use only existing generic parameters and standard library const functions. The operator should only apply if the trait's associated constant expects a value of a type that is compatible with the const expression's result type, inferred from the context. For example, if the original is `fn f<T, U: Trait<T, A = { 1 }>>() {}`, mutate to `fn f<T, U: Trait<T, A = { std::mem::size_of::<T>() }>>() {}`. Ensure the const expression does not introduce new variables or types; use only existing generic parameters and inherent constant functions. This change stresses the compiler's ability to handle const generics that depend on generic types, which is the core issue in the bug.
