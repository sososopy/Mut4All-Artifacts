mutation operator: Insert a thread_local macro invocation inside a generic const argument of an impl block.

This operator applies when there is an impl block that includes generic parameters, specifically when at least one of those generic parameters is a const parameter with a block expression or complex initializer. The mutation modifies the const generic argument by inserting a thread_local macro invocation inside its initialization block. The inserted thread_local macro must be placed such that it creates a static item within the const block. If the const generic argument is already a block expression, the thread_local macro is added as a new statement at the beginning of that block. If the const generic argument is not a block expression, it is wrapped in a block expression that starts with the thread_local macro invocation, followed by the original expression. The macro invocation should use a static variable name derived from existing names in the seed program (e.g., by appending _TL to an existing identifier) and a type that is already in scope, preferably one that appears in the surrounding context. For example, if the impl block is for a type named Foo, use Foo as the type in the thread_local static declaration. The mutation must ensure that the thread_local macro is expanded in a context where it will be parsed as an item, typically at the beginning of a block.

Example application: Given an impl block like 'impl<T, const N: usize> Trait for Type<T, N> {}', this operator does not apply because there is no const parameter with a block expression. However, given 'impl<T, const C: SomeType> Trait for Type<T, { some_expr }> {}', the operator transforms it to 'impl<T, const C: SomeType> Trait for Type<T, { thread_local! { static VAR_TL: SomeType = some_expr; } some_expr }> {}'. In the bug report example, the original code has a const generic argument that is a block containing a thread_local macro. The mutation would create a similar nested structure, potentially triggering the same HIR ownership mismatch ICE. The operator should only apply when the const generic argument is syntactically a block or can be wrapped in a block, and the impl block's type includes a path that can be used as the static's type. The goal is to replicate scenarios where HIR nodes from macro expansions inside const generic arguments end up with incorrect owner contexts.
