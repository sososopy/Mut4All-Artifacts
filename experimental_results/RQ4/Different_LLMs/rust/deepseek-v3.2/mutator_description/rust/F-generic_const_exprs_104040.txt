mutation operator: substitute generic const parameter with its evaluated value in trait impl headers

this mutation applies when a trait implementation header uses a generic const parameter from the trait definition. it targets the specific code construct where an impl block specifies a constant argument for a trait's const generic parameter. the operator replaces the constant identifier or expression used in the impl header with its concrete evaluated constant value.

the mutation is performed by analyzing the trait definition to identify const generic parameters. then, for each impl block that provides an argument for such a parameter, the compiler is used to evaluate that argument to a concrete constant value (e.g., an integer literal). the original argument in the impl header is then replaced with this evaluated value.

for example, given a seed program with:
trait Trait<const N: usize> { fn method(&self) -> usize; }
const K: usize = 5;
impl Trait<K> for SomeType { ... }
the constant argument `K` is evaluated to `5`. the mutation changes the impl header to:
impl Trait<5> for SomeType { ... }

this operator focuses on the interaction between const generics and trait resolution, particularly under the generic_const_exprs feature where constant evaluation and identity are critical. it directly triggers the compiler's internal assertions about trait binding equality, as seen in the bug report where the compiler panicked comparing `Print<L>` and `Print<4>`. the mutation substitutes one form for the other, testing whether the compiler handles both forms uniformly during code generation.

the operator uses only elements present in the seed program: the trait, the const parameter, the impl block, and the concrete type. no new declarations are introduced. the change is a direct textual substitution within the impl header after compile-time evaluation of the constant expression.
