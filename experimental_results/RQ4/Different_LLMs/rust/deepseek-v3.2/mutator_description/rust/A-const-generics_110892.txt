mutation operator: Replace a generic constant expression in a trait bound with a constant expression referencing a function call that returns the same type, but where the function is defined with mismatched const generic parameter arity. This operator applies when a trait bound uses a const generic parameter in a const expression context, typically within a where clause. The mutation modifies the trait bound by replacing the const generic parameter with a call to a const function that expects a different number of const generic parameters than are provided. Specifically, if the seed program has a const generic parameter used in a bound like `const N: usize`, and there exists a const function `fn f<const M: usize>() -> usize` in scope, change the bound to use `{ f::<N, N>() }` (introducing an extra const generic argument) or `{ f::<>() }` (providing too few arguments). If such a function does not exist, introduce a new const function with mismatched arity: for example, declare `const fn mismatch<const A: bool, const B: bool>() -> bool { A }` if the original constant is a bool, and then use `{ mismatch::<CONST>() }` where only one const argument is supplied but two are expected. The change should be made directly in the trait bound expression, ensuring all types and names are taken from the seed program or introduced as described. For example, if the original code has `where T: Trait<{ N }>`, mutate to `where T: Trait<{ mismatch::<N>() }>` with `mismatch` defined as `const fn mismatch<const A: bool, const B: bool>() -> bool { A }` (assuming N is bool). This creates a mismatch between expected and supplied const generic parameters, potentially triggering ICEs related to const evaluation and trait resolution.
