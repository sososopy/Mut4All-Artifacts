mutation operator: Replace a trait bound containing a higher-ranked trait bound (`for<...>`) with a simple trait bound that removes the higher-ranked quantifier but retains the base trait, focusing on cases within const contexts or generic const expression scopes.

This mutation applies when a function signature, type alias, or trait declaration contains a `for<'a>` (or similar lifetime quantifier) clause within a trait bound, particularly in a `const fn` or a context using the `~const` trait qualifier. The operator targets the specific syntactic pattern `for<...> Fn(...)` or similar higher-ranked trait bounds and replaces it with just `Fn(...)` (or the corresponding trait), thereby removing the universal quantification over lifetimes.

The change must be made directly to the bound in the source code. For example, if the seed program contains `F: ~const for<'a> Fn(&'a Alias<'a>) + ~const Destruct`, the mutated version becomes `F: ~const Fn(&Alias<'_>) + ~const Destruct`. Here, the `for<'a>` quantifier is stripped, and the lifetime parameters in the function type are replaced with an anonymous lifetime `'_` to maintain syntactic validity, assuming such a replacement is possible without introducing new undeclared lifetimes. If the seed program does not have an appropriate anonymous lifetime pattern, the innermost lifetime may be used if it is declared in an outer scope; otherwise, a new named lifetime may need to be introduced in the outer scope (e.g., adding `<'b>` to the enclosing function) to avoid ambiguity, but this is a secondary step only if necessary.

The operator should be applied only when the higher-ranked trait bound is present and the surrounding context involves const generics, generic const expressions, or `~const` traits, as these features are more prone to compiler bugs like the one reported. The mutation aims to alter the resolution of bound variables, which can trigger internal compiler errors related to unexpected bound var resolution.

Example seed code snippet: `const fn with_positive<F: ~const for<'a> Fn(&'a Alias<'a>) + ~const Destruct>(fun: F) { ... }`
Mutated code snippet: `const fn with_positive<F: ~const Fn(&Alias<'_>) + ~const Destruct>(fun: F) { ... }`
In this example, `Alias` is an existing type alias from the seed program, and `'_` is used as an anonymous lifetime that is valid in the context. No new variables, types, or functions are introduced beyond this syntactic change. The change is limited to the trait bound itself, preserving the rest of the function signature and body.
