mutation operator: This mutation operator targets the initialization of uninhabited or partially initialized types using MaybeUninit::assume_init. It applies when a struct or enum contains a field of the never type (`!`) or is otherwise uninhabited, and there is a call to `MaybeUninit::<T>::uninit().assume_init()` where `T` is such a type. The mutation changes the call to `MaybeUninit::<T>::zeroed().assume_init()` to alter the initialization pattern that may expose bugs in GVN (Global Value Numbering) related to unreachable code or invalid dominator tree nodes.

Specifically, for any expression of the form `MaybeUninit::<T>::uninit().assume_init()` where `T` is a struct or enum that includes a field of type `!` (never type) or is uninhabited (e.g., an enum with no variants), replace `uninit()` with `zeroed()`. This mutation should only be applied if the type `T` is defined in the current scope and is uninhabited or contains a never type field.

For example, given a seed program with a struct `S` defined as `struct S { x: u8, y: ! }`, and a usage like `let val = unsafe { MaybeUninit::<S>::uninit().assume_init() };`, mutate it to `let val = unsafe { MaybeUninit::<S>::zeroed().assume_init() };`. This changes the MIR representation of the initialization, potentially triggering different compiler paths in GVN that could reveal reachability or domination calculation bugs.

Ensure the mutation is applied only in unsafe contexts where `assume_init` is called, and avoid introducing new types or variables. Use the existing type `T` from the seed program. If `T` is not uninhabited or does not contain a never type, do not apply this mutation. This operator aims to test edge cases in MIR optimizations involving uninhabited types and zero-initialization.
