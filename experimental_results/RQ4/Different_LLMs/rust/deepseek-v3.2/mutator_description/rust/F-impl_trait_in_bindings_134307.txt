Mutation operator: Replace a reference to a concrete type with a reference to an `impl Trait` binding in a local variable declaration.

This operator applies to any `let` binding where the type annotation is a reference to a concrete type (e.g., `&TypeName`). It mutates the type annotation to `&impl Trait`, where `Trait` is a trait that the referenced type implements, and adjusts the initialization expression to match if necessary.

To apply, for each `let` binding in the seed program with a type annotation of the form `&ConcreteType` (or `&mut ConcreteType`), perform the following steps:
1. Identify the concrete type `ConcreteType` being referenced.
2. Find a trait `Trait` that `ConcreteType` implements. Prefer traits already used elsewhere in the program (e.g., `Debug`, `Clone`, `PartialEq`) to minimize new declarations. If no suitable trait exists in scope, introduce a trait bound by adding `use` statements for common traits from the standard library (e.g., `use std::fmt::Debug;`).
3. Change the type annotation to `&impl Trait` (or `&mut impl Trait` for mutable references).
4. Ensure the initialization expression is a reference to a value of `ConcreteType`. If it is not already a reference, wrap it with `&` (or `&mut`). If it is already a reference, it remains unchanged.

Example mutation:
Original code: `let x: &i32 = &some_integer;`
Mutated code: `let x: &impl PartialEq = &some_integer;`

Original code: `let y: &mut String = &mut some_string;`
Mutated code: `let y: &mut impl Debug = &mut some_string;`

If the concrete type does not implement any trait used in the mutation, the operator should skip that binding to avoid compilation errors. The operator must only apply when the trait implementation can be verified from the context.
