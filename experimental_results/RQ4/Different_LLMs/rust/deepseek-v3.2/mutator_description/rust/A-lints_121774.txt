mutation operator: Modify a function call to discard its result in a context where the function is marked with the #[must_use] attribute, specifically by wrapping the call in a let binding with an underscore pattern or by prefixing it with an underscore assignment, ensuring the function is defined in the current scope or accessible via imports.

This operator targets function call expressions where the called function has a #[must_use] attribute. It applies when the seed program contains a function definition with #[must_use] and a call to that function where the result is currently used or explicitly ignored in a manner that might not trigger the lint. The mutation changes the call site to explicitly discard the result using a let _ = ...; statement or an underscore assignment _ = ...;, which can alter the diagnostic emission flow.

The operator first identifies a function item in the current module or imported scope that is annotated with #[must_use]. It then locates a call expression invoking that function. If the call is already part of an expression statement (e.g., f();), it may already discard the result, but the mutation can still apply to ensure explicit discarding. If the call is used in a value context (e.g., let x = f();), the mutation modifies it to discard instead. Preference is given to using existing function names from the seed program; no new elements are introduced beyond the underscore pattern, which is a built-in Rust construct.

Example: In a seed program with a function defined as #[must_use] fn compute() -> i32 { 0 }, and a call let x = compute();, mutate to let _ = compute();. Alternatively, if the call is compute(); alone, it can be mutated to _ = compute(); to create an assignment expression that discards the result. This change may expose bugs in the compiler's diagnostic tracking for must_use lints, particularly around trimmed_def_paths and ICE conditions.
