mutation operator: Invalid generic parameter ordering in struct definitions with const generic parameters. This mutation operator targets struct definitions that have at least one const generic parameter and at least one type or lifetime generic parameter. It applies when a struct definition has generic parameters in the order: const parameters first, followed by type or lifetime parameters. The mutation changes the order of generic parameters to place const generic parameters after type or lifetime parameters, while preserving the default value assignments if any. Specifically, if the struct definition is struct Name<const C: Type = default, T, ...> {...}, mutate it to struct Name<T, const C: Type = default, ...> {...}. The mutation must ensure the total number of generic parameters remains the same and their identities are preserved, only their order is altered. Use existing parameter names and types from the seed program. Do not introduce new types or names. Example: if seed has struct Foo<const N: usize, T>, mutate to struct Foo<T, const N: usize>. If seed has struct Bar<const LEN: usize = 1, U, V>, mutate to struct Bar<U, const LEN: usize = 1, V>. This reordering can trigger internal compiler errors in substitution logic, especially when default values are involved or during well-formedness checking, as seen in the bug report where parameter indices become out of range.
