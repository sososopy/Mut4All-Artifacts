mutation operator
target generic constant expressions and overlapping impls in coherence checking, specifically focusing on the interaction between generic const parameters and constant values in impl blocks. this mutation applies to programs using the generic_const_exprs feature and involving structs with const generic parameters, where multiple impl blocks exist for the same struct with potentially overlapping const arguments. the mutation modifies the constant arguments in impl blocks to create ambiguous or overlapping situations that may trigger internal compiler errors during coherence checking. the changes involve replacing a concrete constant argument in an impl block with a generic const parameter that is already defined in the struct's generic parameters, or vice versa, to create a scenario where the solver may encounter unexpected infer types or unresolved obligations. the mutation should be applied to a struct definition with at least two const generic parameters and at least two impl blocks for that struct. if the seed program contains a struct with const generic parameters and multiple impl blocks, select one impl block that uses concrete constant arguments. change one of the concrete constant arguments to a generic const parameter name that is already declared in the struct's generic parameters but not used in that impl block's header. ensure the generic const parameter has the same type as the concrete argument being replaced. if no such generic parameter exists, introduce a new const generic parameter to the struct with an appropriate type and then use it in the impl block. the introduced parameter should be given a unique name not conflicting with existing identifiers in the scope, following rust naming conventions. for example, if the seed program has struct s<const n: usize, const m: usize> and impl s<5, 10>, change it to impl s<n, 10> where n is an existing const generic parameter of type usize. if n does not exist, modify the struct to struct s<const n: usize, const m: usize, const p: usize> and then change the impl to impl s<p, 10>. this mutation aims to create a scenario where the coherence checker must handle a generic const parameter in a position previously occupied by a concrete value, potentially leading to assertion failures about empty obligations or unexpected infer types in query input. the mutation should preserve the overall structure of the program and avoid introducing undefined names; all names used must be either existing in the seed program or newly declared as described.
