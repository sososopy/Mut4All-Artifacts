mutation operator: Replace async trait method with non-async trait method and adjust call sites accordingly. This operator targets async trait methods (methods declared with async fn in a trait) and replaces them with synchronous versions, while also modifying any await expressions at call sites to direct calls. It applies within trait definitions for methods marked async and at every location where such a method is invoked with an .await suffix. For the trait method, remove the async keyword from the method signature. If the trait method has a return type implied by async fn, change it to return impl Future<Output = original_return_type> (or a compatible concrete future type if one can be inferred from the surrounding context) to maintain compatibility, but if the surrounding context does not provide a suitable future type, introduce a new function that returns a future that immediately yields the original value. At each call site where the method is invoked and .await is used, remove the .await suffix. If the method call is part of a larger expression where the future is needed, ensure the expression still type-checks by potentially wrapping the call in an async block that yields the result. Use only types, variables, and functions present in the seed program. If introducing new elements, specify they should be a simple function returning a ready future from std::future::ready. Example: For an async trait method async fn execute(self, shared_state: &SharedState); change it to fn execute(self, shared_state: &SharedState) -> impl std::future::Future<Output = ()>; and at a call site like self.previous.execute(shared_state).await; change it to self.previous.execute(shared_state);. If the return type adjustment is needed, add a helper function fn immediate_future<T>(value: T) -> impl std::future::Future<Output = T> { std::future::ready(value) } and use it in the method body to return a future.
