mutation operator: Insert an async closure inside a non-async function or method, where the closure captures variables from the outer function but does not use all of its parameters.

This operator applies when a seed program contains a function or method with at least one parameter and at least one local variable or additional parameter that can be captured. The operator will modify the function body by adding an async closure expression. The closure will have a parameter list that includes at least one new parameter name not used within the closure body. The closure body will capture and use at least one variable from the outer function scope, but will not reference all of the closure's own parameters. This creates a mismatch between the closure's formal parameters and its captured upvars, which may stress the compiler's capture analysis.

Specifically, for a given function in the seed program, choose a point inside its body where a statement can be inserted. If the function has at least one parameter, select one of these parameters to be captured. If there are no parameters but there is a local variable in scope, capture that instead. Then, construct an async closure. The closure signature should include a list of parameters; for example, use two parameters named `param1` and `param2`. Inside the closure body, write an expression that uses the captured outer variable but does not use `param1` or `param2`. Finally, place this closure as an expression statement ending with a semicolon.

For example, if the seed function is `fn example(x: i32) { let y = 5; }`, the mutation could produce `fn example(x: i32) { let y = 5; async |param1, param2| { x.wrapping_add(1); }; }`. Here, the async closure captures `x` from the outer function, but its parameters `param1` and `param2` are unused. The closure body uses `x` via a method call to ensure it is captured.

The operator must use identifiers that are likely to be unused in the current scope to avoid name conflicts. Generate simple names like `p1`, `p2` for closure parameters. If these names conflict with existing names in the scope, append a number until a unique name is found. The captured variable should be an existing parameter or local variable from the outer function. Do not introduce new variables outside the closure. The closure body should contain a single expression that uses the captured variable, such as a method call or arithmetic operation, to ensure the capture is non-trivial.
