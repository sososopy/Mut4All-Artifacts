mutation operator: Replace Trait Bound with an Incorrect Sized Constraint in Where Clauses
Applies to: any where clause in generic definitions (structs, enums, functions, impls) that contains a trait bound.
Change: In a where clause, replace a trait bound (e.g., T: SomeTrait) with a Sized bound on a type that does not already have one, specifically targeting types that are likely to be unsized (like slices, trait objects, or associated types). The goal is to introduce a potentially conflicting or overly restrictive Sized requirement. For each trait bound 'P: Q' found, mutate it to 'P: Sized' if 'P' is a type parameter or an associated type, and if 'P' does not already have an explicit Sized bound in the same where clause. If the seed program already uses Sized bounds extensively, instead add an extra redundant Sized bound for a different type parameter.
Example: Original code: fn process<T: DeserializeOwned>(item: T) { ... } Mutated code: fn process<T: Sized>(item: T) { ... } Note that this changes the trait requirement entirely. Another example: Original: where T: Deserialize<'de>, U: Serialize Mutated: where T: Sized, U: Serialize This can cause compilation errors if T needs to be unsized for the function's logic, but more importantly, it may expose internal compiler assumptions about trait satisfaction and sizedness during monomorphization or trait selection, potentially triggering out-of-bounds errors in the compiler's internal data structures when it encounters an unexpected combination of bounds. Use existing type parameters from the seed; do not introduce new ones.
