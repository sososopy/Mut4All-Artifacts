mutation operator
Target generic constant expressions in function calls with mismatched const generic argument types. This applies to calls to functions with generic const parameters where the provided const argument is of a type that differs from the expected const generic parameter type, potentially leading to internal compiler errors during monomorphization. Specifically, replace a const generic argument in a function call with a const expression of a different integer type (e.g., change a usize argument to an i32 expression) while keeping the value semantically similar (e.g., same numeric value). The mutation must only use types and constants already present in the seed program or introduce new primitive literal constants (like 4i32). If the seed program contains a function call with generic const parameters, identify a const generic argument that is a numeric literal or a simple constant expression. Change its type by adding a suffix to the literal (e.g., change 4 to 4i32) or by casting an existing constant expression to a different integer type using as. Ensure the mutated const expression is valid Rust syntax and does not introduce undeclared identifiers.

For example, if the seed contains:
fn foo<const N: usize>() {}
foo::<4>();
Mutate to:
foo::<{ 4i32 as usize }>();
Or, if the seed contains:
const K: usize = 5;
foo::<K>();
Mutate to:
foo::<{ K as i32 as usize }>();
This mutation operator focuses on the boundary of const generic type checking and evaluation, which is implicated in the bug report's ICE during monomorphization collector visitation of polymorphic constants.
