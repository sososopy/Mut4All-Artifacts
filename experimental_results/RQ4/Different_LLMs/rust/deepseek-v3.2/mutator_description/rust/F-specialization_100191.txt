mutation operator: Introduce a specialized impl that uses an associated type projection in its trait bound, targeting the interaction between negative coherence checking and specialization. This operator applies when a seed program contains at least one trait definition and at least one generic impl for that trait. The mutation adds a new impl that specializes an existing generic impl, where the specializing impl uses an associated type from the implementing type in its trait bound. Specifically, for a trait Trait<T> and an existing impl<U, V> Trait<U> for V, add a new impl<W> Trait<W::Assoc> for W where W: OtherTrait, using an associated type from an existing trait in the seed. If no such trait exists, introduce a new trait with an associated type: declare `trait Dummy { type DummyAssoc; }` and implement it for a concrete type already present. The new impl should be marked `default` if the seed uses specialization. The mutation changes the specialization graph and can trigger normalization failures during negative coherence checks. Example: seed contains `trait Trait<T> {}` and `impl<T, U> Trait<T> for U {}`. Mutation adds `trait Dummy { type Assoc; }` and `impl<T> Trait<T::Assoc> for T where T: Dummy {}`. This mirrors the bug's structure where the bound `<T as Iterator>::Item` is used.
