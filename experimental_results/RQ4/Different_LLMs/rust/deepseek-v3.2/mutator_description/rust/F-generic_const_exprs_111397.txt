Specifically, the error "expected const for .. but found Type(..) when substituting" points to a type-checking or substitution logic flaw within the generic_const_exprs feature. The bug likely triggers when the compiler processes inherent associated types (IATs) that depend on const generic parameters and involve const expressions, especially when those expressions are used in where-clauses or type paths. The ICE manifests during the MIR borrow-checking phase, suggesting the bug is in the substitution logic during monomorphization or type normalization.

The inherent associated type must have its own const generic parameters and a where-clause that uses a const expression involving both the impl's const parameter and the associated type's const parameter.
