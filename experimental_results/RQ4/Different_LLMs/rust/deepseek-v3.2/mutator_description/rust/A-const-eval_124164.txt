mutation operator: In static item declarations, mutate the type annotation by removing it entirely if it is present, or by inserting a spurious `=` token if it is absent, to produce an ill-typed static definition that may trigger validation errors during const-eval. Specifically, locate any static item in the seed program. If the static declaration includes a colon and a type (e.g., `static NAME: Type = ...;`), delete the colon and the type, leaving only `static NAME = ...;`. If the static declaration already lacks a type annotation (i.e., it is written as `static NAME = ...;`), insert an equals sign immediately after the identifier, resulting in `static NAME = = ...;` (a duplicated `=`). This mutation should be applied to the first static item encountered in the seed program. Use only existing static item names from the seed; do not introduce new identifiers. Example transformation for a static with type: `static COUNTER: AtomicUsize = AtomicUsize::new(0);` becomes `static COUNTER = AtomicUsize::new(0);`. Example transformation for a static without type: `static FLAG = true;` becomes `static FLAG = = true;`.
