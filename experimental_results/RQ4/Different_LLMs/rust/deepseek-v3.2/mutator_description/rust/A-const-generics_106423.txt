mutation operator
Target specific code construct: This operator targets generic const arguments in function calls where the const argument is an integer literal. It applies to function calls where at least one generic parameter is a const parameter of integer type and the corresponding argument is a numeric literal.

Operator description: Replace a numeric literal used as a const generic argument with a complex constant expression that evaluates to the same value but involves a generic parameter from the surrounding context. Specifically, for a function call like function_name::<T, N, ...>(...) where N is a const generic parameter of integer type and the argument for N is a literal L, mutate it to function_name::<T, { M + (L - M) }, ...>(...) where M is another const generic parameter from the same function's generic parameter list, if such a parameter exists and is also of integer type. If no such M exists, introduce a new const generic parameter M with a default value equal to L, and adjust the function signature accordingly in the seed program. The mutation ensures the expression still evaluates to L but introduces a polymorphic constant that depends on another generic parameter.

Example application: Given a seed program containing a function call like butter_st::<f64, 4, 2>(...), where 4 and 2 are const generic arguments, and assuming the function butter_st has generic parameters like butter_st<T, const ORDER: usize, const SECTIONS: usize>(...). If ORDER is 4 and SECTIONS is 2, and there is another const generic parameter available (or we introduce one), mutate to butter_st::<f64, { OTHER_CONST + (4 - OTHER_CONST) }, 2>(...) where OTHER_CONST is another const generic parameter of integer type already present in the generic parameter list of butter_st. If no such parameter exists, first modify the function signature in the seed program to include an additional const generic parameter with a default, e.g., change fn butter_st<T, const ORDER: usize, const SECTIONS: usize>(...) to fn butter_st<T, const ORDER: usize, const SECTIONS: usize, const OTHER_CONST: usize = 4>(...) in the relevant module, then apply the mutation to the call site as butter_st::<f64, { OTHER_CONST + (4 - OTHER_CONST) }, 2, 4>(...). The mutation ensures the expression { OTHER_CONST + (4 - OTHER_CONST) } simplifies to 4 but presents as a polymorphic constant during compilation.

Rationale: This mutation directly triggers the bug pattern where the compiler encounters a polymorphic constant (UnevaluatedConst) during monomorphization, as seen in the bug report. It increases coverage by generating complex const expressions that depend on generic parameters, stressing const evaluation and generic instantiation phases.
