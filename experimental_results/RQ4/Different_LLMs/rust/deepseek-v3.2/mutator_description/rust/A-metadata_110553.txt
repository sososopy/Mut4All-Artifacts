mutation operator: Introduce a generic parameter omission in a function call where the function has multiple generic parameters, specifically omitting a later generic parameter while providing an earlier one via turbofish syntax. This applies to function calls where the function has at least two generic parameters (e.g., type and const generics) and the call uses turbofish syntax to specify at least the first generic argument but not all required arguments.

The mutation modifies a function call expression of the form `function_name::<ExplicitArg1, ExplicitArg2, ...>(args)` to `function_name::<ExplicitArg1>(args)`, removing one or more subsequent generic arguments from the turbofish. If the original call uses no turbofish and relies on inference, this operator does not apply. The operator selects a function call where the function definition has multiple generic parameters (like `<T, const N: usize>`). It then removes the turbofish arguments after the first one, leaving only the first explicit generic argument specified. The expectation is that type inference might fail or the compiler may encounter an internal error when processing the omitted parameters.

Example: Original code has a function `fn f<T, const N: usize>(x: T) -> [T; N]` and a call `let a = f::<u8, 10>(5);`. After mutation, it becomes `let a = f::<u8>(5);`, omitting the const generic parameter `10`. The compiler must then handle the missing const parameter, potentially leading to an inference error or ICE.

The mutation should only use functions and types already present in the seed program. No new declarations are introduced. The change is purely syntactic removal within the function call expression.
