mutation operator
Target code construct: trait implementations with const methods, specifically when a trait method is declared as a const fn in the trait definition and then implemented in an impl block that also uses the const keyword on the method. The operator applies to any impl block for a trait where at least one method signature includes the const keyword. It mutates by removing the const keyword from the method signature inside the impl block while keeping the trait's method declaration as const. This creates a mismatch where the trait requires a const method but the implementation does not provide one, potentially triggering compiler errors or ICEs related to const trait implementations and effect checking.

The mutation is applied as follows: For each method within an impl block that implements a trait, if the method signature includes the const keyword, remove that const keyword from the signature. Ensure that the rest of the method signature (e.g., parameter types, return type) remains unchanged. Use only existing elements from the seed program; do not introduce new variables, types, or functions. This operator focuses on the const qualifier in method implementations, exploiting the compiler's handling of const trait methods and effects.

Example in pseudo-code: Original seed code snippet includes `const fn add(self, b: Vec3) -> Self::Output`. After mutation, it becomes `fn add(self, b: Vec3) -> Self::Output`. The trait std::ops::Add still declares add as a const fn in its definition, but the implementation no longer matches this, which may expose bugs in const context validation or effect parameter handling. This operator is widely adaptable because it targets a specific keyword removal in trait implementations, applicable to any seed program with const trait methods.
