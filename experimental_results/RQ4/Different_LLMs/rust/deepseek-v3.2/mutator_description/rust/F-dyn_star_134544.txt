mutation operator
target code construct: explicit type casts (as expressions) where the source expression is a reference to a dyn Trait (e.g., &dyn Trait) and the target type is dyn* Trait. applies to any explicit cast using the as keyword in a context where the dyn* Trait feature is enabled (via #![feature(dyn_star)]). the mutation replaces the source expression with a dereference of that reference (using the * operator) before the cast. specifically, if the seed program contains an expression of the form &dyn Trait as dyn* Trait, mutate it to *(&dyn Trait) as dyn* Trait. more generally, if the source expression is a reference to a dyn Trait (any reference type: &, &mut, or even a Box<dyn Trait> if it is being dereferenced), and it is being cast to dyn* Trait, insert an explicit dereference so the cast operates on the dereferenced value. note that the mutation should only apply when the target type is explicitly dyn* Trait (or a similar dyn* type). use existing variable names and types from the seed program. do not introduce new declarations. the change is purely syntactic: add a * operator before the source expression if it is a reference, ensuring parentheses are added if needed for precedence. example: given seed code snippet: let r: &dyn SomeTrait = ...; let _ = r as dyn* SomeTrait; mutated code: let r: &dyn SomeTrait = ...; let _ = *r as dyn* SomeTrait; another example: given seed code: fn f(x: &mut dyn Trait) { x as dyn* Trait; } mutated code: fn f(x: &mut dyn Trait) { *x as dyn* Trait; } if the source expression is already a dereference (e.g., *x), do not apply the mutation (to avoid double dereference). the mutation aims to trigger edge cases in coercion and cast handling between dyn and dyn* types, particularly around dereferencing and ownership semantics that may expose internal compiler errors like the one reported.
