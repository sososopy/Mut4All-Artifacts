mutation operator: Replace a struct instantiation with a reference to a const expression that initializes a similar struct with mismatched generic trait bounds. This operator targets struct definitions with generic type parameters that have trait bounds, particularly Copy. It applies when a struct definition includes a generic parameter with a trait bound, and there exists a const item that attempts to initialize an instance of this struct. The mutation changes a direct struct instantiation expression to instead reference a constant that uses a type argument which does not satisfy the trait bound due to a nested unsized type, like a slice. For example, if the seed program contains a struct definition like struct S<T: Copy>(T); and a const item like const C: &S<[i32]> = &S([]);, then within a function or another const context where S is instantiated, replace an expression like S(value) with C. This replacement introduces a scenario where the constant's type argument ([i32]) fails to meet the Copy bound, potentially triggering const evaluation issues similar to the bug report. The mutation must use existing struct names and constant names from the seed program. It does not introduce new names; it repurposes existing constants that have incompatible type arguments relative to the struct's trait bounds. The goal is to create a mismatch between expected and actual layouts during const evaluation, focusing on references to unsized types within generic structs.
