mutation operator: Change const parameter type from a reference to a slice of the same base type

This mutation operator targets const generic parameters with reference types, specifically &'static str or &'static [T], in function, struct, or impl definitions. It changes the const parameter type from a reference to a slice of the same base type, e.g., from &'static str to [&'static str; 1] or from &'static [u8] to [&'static [u8]; 1]. The operator applies when a const generic parameter is declared as a reference type. The mutation modifies the parameter type declaration and updates all uses of that const parameter within the relevant scope to match the new type, which involves adjusting associated function calls or trait bounds that depend on the original type. If the const parameter is used in a where clause that depends on its type, such as requiring [(); A.len()] for a string slice, the mutation may need to adjust those bounds or remove them if they become invalid, but preference is given to keeping the program compilable by using existing elements. For example, if the seed program has a const parameter const A: &'static str, change it to const A: [&'static str; 1]. Then, wherever A is used, such as in A.len() or A.as_ptr(), replace with A[0].len() or A[0].as_ptr(), using the first element of the slice to preserve the original value. Ensure that any new array literals introduced, like [FOO; 1] for a const argument, are constructed from existing constants or values in the seed program. If the seed program does not have a suitable constant for the slice element, introduce a new const item with the same value as the original argument, but this should be avoided by reusing existing names. The goal is to stress the compiler's handling of const generic parameters with complex or nested types, potentially exposing bugs in type checking, monomorphization, or MIR generation for ADT const params.

Example: In a seed program with a function like const fn concat_strs<const A: &'static str, const B: &'static str>() -> &'static str, mutate it to const fn concat_strs<const A: [&'static str; 1], const B: [&'static str; 1]>() -> &'static str. Then, inside the function body, change A to A[0] and B to B[0] in all expressions, such as A.len() becoming A[0].len(). For the call site concat_strs::<FOO, BAR>(), change it to concat_strs::<[FOO; 1], [BAR; 1]>(). This mutation may trigger issues in the compiler's const generic evaluation, especially with adt_const_params features, as it alters the type structure while preserving semantics.
