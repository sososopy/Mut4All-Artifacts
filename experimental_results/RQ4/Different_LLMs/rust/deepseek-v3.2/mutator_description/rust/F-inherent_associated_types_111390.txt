mutation operator
target: inherent associated type references within higher-ranked trait bounds (HRTBs) and function pointer types. applies when a type alias or function signature uses a for<'a> fn(...) -> ... pattern referencing an inherent associated type (IAT) from a generic struct with lifetime parameters, where the IAT itself depends on that lifetime. the mutation changes the way the IAT is referenced by altering the binding structure of the lifetime parameter in the HRTB relative to the IAT projection. specifically, modify the type alias or function signature that uses the HRTB to either (a) swap the order of lifetime parameters between the HRTB and the struct, if possible, or (b) introduce an explicit projection that binds the lifetime differently. for a seed program containing something like type Alias = for<'a> fn(&'a T) -> Struct<'a>::Assoc; mutate it to type Alias = for<'a> fn(&'a T) -> <Struct<'a> as Trait>::Assoc; where Trait is a new trait introduced if not present. to introduce Trait, declare a trait with an associated type of the same name and implement it for Struct, mirroring the inherent associated type. if the seed program already has a suitable trait, use that. if no trait exists, add a trait definition with an associated type Assoc, and implement it for Struct, making the associated type equal to the existing IAT. this changes the projection from an inherent associated type to a trait-associated type, which may trigger different substitution paths in the compiler. ensure the trait is declared before its use, and the implementation matches the generic parameters of Struct. example: if the seed has struct S<'a>(&'a ()); impl<'a> S<'a> { type P = &'a i32; } type Function = for<'a> fn(&'a i32) -> S<'a>::P; mutate by adding trait Tr { type P; } impl<'a> Tr for S<'a> { type P = &'a i32; } and changing the type alias to type Function = for<'a> fn(&'a i32) -> <S<'a> as Tr>::P;. this mutation targets the specific interaction between HRTB lifetime substitution and IAT projection that caused the ICE.
