mutation operator
target trait method signatures with cross-trait type dependencies.
this operator applies to trait method signatures where a parameter or return type is another trait. it modifies these signatures to create a cyclic dependency between traits via their method signatures. specifically, if trait T1 has a method that uses trait T2 as a parameter or return type, and trait T2 already exists in the seed program, then modify a method in T2 to use T1 as a parameter or return type, thereby creating a mutual dependency. the change must use the existing trait names T1 and T2. do not introduce new types. the operator only applies when two distinct traits are present. for a seed program with traits T1 and T2, if T1 has a method `fn method1(param: T2) -> T2` or similar, then modify a method in T2 to be `fn method2(param: T1) -> T1` or `fn method2() -> T1`. if T2 has no methods, add such a method. if T2 already has a method, change one of its parameter or return types to T1. the change must be syntactically valid; use `T1` and `T2` directly as trait object types without the `dyn` keyword, mirroring the bug report. example: seed contains `trait Alpha { fn get(&self); } trait Beta { fn put(&self); }`. mutate by changing Beta's signature to `fn put(param: Alpha) -> Alpha;` or adding a new method `fn process(a: Alpha) -> Alpha;` to trait Beta. this creates a potential cycle for object safety computation.
