mutation operator: replace zero-sized array type with unit type in union field declarations

applies to: any union declaration containing a field with an array type of zero length (e.g., `[T; 0]`)

changes: locate all union definitions in the seed program. for each field within those unions, if the field's type is an array type with a constant length expression that evaluates to zero, mutate that field's type to the unit type `()`. this mutation must preserve the field identifier name. if the union contains multiple zero-sized array fields, apply the mutation to each such field individually, generating separate mutant programs for each single mutation.

example: given a seed union declaration `union U { a: [u8; 0], b: i32 }`, the mutated version becomes `union U { a: (), b: i32 }`. the field name `a` is kept, only its type is changed from `[u8; 0]` to `()`.

rationale: this mutation directly targets the layout computation for unions containing zero-sized arrays, a structure implicated in the bug report. by replacing the zero-sized array with a unit type (another zero-sized type but with different layout rules), it may expose incorrect assumptions or inconsistencies in the compiler's layout algorithm, particularly when interacting with features like transmutability or repr(C) structs.
