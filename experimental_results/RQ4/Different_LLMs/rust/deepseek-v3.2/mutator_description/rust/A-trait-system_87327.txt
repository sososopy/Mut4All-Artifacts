mutation operator
Target code construct: Associated type projections within nested type contexts, specifically projections appearing inside non-parameterized anonymous types such as unions, structs, or enums defined within trait implementations.
Where it applies: Inside the body of a trait implementation (inherent impl, trait impl, etc.), locate any anonymous type definition (union, struct, enum) that contains a field or variant whose type uses an associated type projection (e.g., `<Self as Trait>::AssocType`). Mutate by wrapping the projected type in a generic struct that is defined locally, introducing a generic parameter that is constrained by a trivial trait bound derived from existing traits in scope.
Changes: First, identify an existing associated type projection within a field/variant of a locally defined anonymous type. Create a new generic struct (or enum) within the same scope, with a single type parameter and a trivial trait bound (e.g., `Sized`). Replace the original projection with an instantiation of this new generic struct, using the projection as the type argument. Ensure the new struct is defined immediately before its use, using a name not conflicting with existing identifiers (e.g., add a suffix like `_Wrapper`). Use only traits already imported or defined in the current module for the bound.
Example: Original code snippet contains `union U { a: <Self as Iterator>::Item, }`. After mutation, insert `struct Wrapper<T: Sized>(T);` before the union, and change the union field to `a: Wrapper<<Self as Iterator>::Item>,`. The bound `Sized` is chosen because it is a default bound and often present. This constructs a deeper nesting of projections.
Rationale: This mutation increases the complexity of type normalization paths by adding intermediate generic structs, stressing the compiler's ability to handle nested projections during region erasure and trait solving, which is a known source of ICEs in the trait system.
