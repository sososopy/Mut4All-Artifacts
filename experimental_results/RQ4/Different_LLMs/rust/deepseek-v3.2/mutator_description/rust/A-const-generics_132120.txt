mutation operator: Insert a const block with an undeclared constant item (type omitted) as an argument to a const generic parameter.

This mutation operator targets function calls, method calls, or type instantiations that accept const generic parameters. It applies when a seed program contains a call or instantiation site where a const generic argument is expected.

The operator modifies the seed program by taking an existing const generic argument expression at such a site and replacing it with a const block. Inside this const block, a new constant item is declared without an explicit type annotation, and it is initialized using the original const generic argument expression. The constant's name must be a fresh, unused identifier within the current scope. The original argument expression is moved inside the const block's initializer.

For example, if a seed program contains a call `f::<N>()`, where `N` is a const expression, the operator could mutate it to `f::<const { const NEW_CONST = N; NEW_CONST }>()`. The identifier `NEW_CONST` must not collide with any existing names. The constant `NEW_CONST` is declared without a type (`const NEW_CONST = N;`).

If the original const generic argument is a simple literal or identifier, it is used directly as the initializer. If it is a more complex expression, the entire expression is placed as the initializer. The const block must be placed precisely where the const generic argument is expected.

The operator should prioritize call sites for functions known to use const generics, especially those in standard library intrinsics or arch-specific functions, as these often have complex const generic handling. The goal is to create a const block whose inner constant lacks type information, which may trigger type inference or checking failures in the compiler's const generic processing.
