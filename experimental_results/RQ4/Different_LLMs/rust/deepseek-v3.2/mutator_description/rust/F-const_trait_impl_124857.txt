mutation operator: Introduce a recursive const trait bound in a generic impl that references the trait being implemented. This operator applies to any trait impl block that is generic over a type parameter. For a given generic impl of a trait TraitName for a type parameter T, add a where clause T: ~const TraitName. If the trait already has a const_trait attribute, ensure the impl is also const. If the crate does not already have the const_trait_impl feature enabled, add #![feature(const_trait_impl)] at the crate root. Also, ensure there exists at least one concrete impl (non-generic) for the same trait, such as for a built-in type like i32. The mutation should add the const qualifier to the generic impl and the concrete impl if not already present, and add the recursive where clause to the generic impl. For example, if the seed program contains trait Tr {} and impl Tr for i32 {}, mutate to: #[const_trait] trait Tr {} impl const Tr for i32 {} impl<T> const Tr for T where T: ~const Tr {}. If the trait already has a const_trait attribute, keep it. Ensure all impls for the trait are made const. This creates a scenario similar to the bug report where coherence checking must handle recursive const bounds with inference variables.
