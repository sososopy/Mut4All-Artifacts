mutation operator
This operator targets function signatures (specifically return type annotations) that involve trait bounds with for<> binders and impl Trait. It applies when a function has a return type that is a trait object or impl Trait, and the program already uses the non_lifetime_binders feature. The mutation modifies the return type by introducing a for<> binder that incorrectly binds a type parameter within an impl Trait inside a trait bound, creating a nested scoping issue. The operator changes the return type from `-> impl Trait` or `-> dyn Trait` to `-> (dyn for<T> Trait<Assoc = impl Trait<T>> + '_)` where T is a new type parameter introduced in the for binder, and the impl Trait inside the associated type binding uses that bound variable. If the seed program does not have a suitable trait, the operator uses an existing trait from the seed (e.g., a trait defined without generic parameters) and adds generic arguments incorrectly. Specifically, it replaces the return type of a function with: `(dyn for<PARAM> TRAIT<Assoc = impl TRAIT<PARAM> + '_>)` where PARAM is a new identifier (e.g., `T`), and TRAIT is an existing trait name from the seed. If no trait exists, declare a simple trait `trait Trait {}` at the module level. Ensure the function signature is syntactically valid but semantically problematic, e.g., by omitting necessary parentheses or using `:` instead of `->` to induce parsing oddities. For example, if the seed has `fn foo() -> impl Iterator`, mutate to `fn foo :(dyn for<T> Iterator<Item = impl Iterator<T> + '_)`. This introduces escaping bound vars in well-formedness checks.
