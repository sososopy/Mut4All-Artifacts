mutation operator: replace a const trait implementation with a non-const trait implementation while preserving specialization ordering, targeting scenarios where a const impl specializes a non-const impl or vice-versa within a trait hierarchy featuring min_specialization.

This operator applies to Rust code containing at least one trait marked with `#[const_trait]` and at least two impl blocks for that trait where one is more specific than the other (i.e., one impl has a generic parameter and the other a concrete type, indicating a potential specialization relationship). The operator will modify the constness of one of these impl blocks.

Specifically, the operator selects a pair of impl blocks for the same `#[const_trait]` trait T. Let impl A be the more generic impl (e.g., `impl<T> const T for U<T>`) and impl B be the more specific impl (e.g., `impl const T for i32`). The operator will change impl B from const to non-const, resulting in `impl T for i32`, while keeping impl A const. This creates a situation where a non-const impl attempts to specialize a const impl, which is a known edge case for the compiler's const trait and specialization interaction.

The change must be made directly to the `impl` keyword: remove the `const` keyword from the selected more-specific impl block. All other parts of the impl block, including trait bounds, where clauses, and method bodies, remain unchanged. If the impl block contains any default method implementations inside, they are left unmodified. This mutation should be applied only if the seed program already contains the necessary feature attributes (`#![feature(const_trait_impl, effects, min_specialization)]`) and the trait is marked with `#[const_trait]`. No new types, variables, or functions are introduced.

Example transformation: Original code has `trait Foo {} impl const Foo for i32 {} impl<T> const Foo for T {}`. The operator modifies the first impl to `impl Foo for i32 {}`, resulting in a non-const impl for i32 and a const generic impl for T. This directly mimics the structure that triggered the bug report, where the ordering and constness mismatch lead to an internal compiler error about a parent item not being marked as default.
