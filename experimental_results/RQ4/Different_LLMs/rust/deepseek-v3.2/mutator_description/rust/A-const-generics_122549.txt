mutation operator
This operator targets const generic parameters in trait and impl signatures where the const parameter is used in a const expression block (i.e., braces {}) as a type argument. It modifies the const expression block by either removing the braces entirely, leaving only the const parameter name, or by changing the braces to parentheses, which is syntactically invalid for a const argument but may parse differently. The operator applies wherever a const generic parameter N is used as { N } within angle brackets for a type argument in a trait method signature, an impl header, or a struct type. For example, if a seed program contains a trait method like fn example<const N: usize>(&self) -> SomeType<T, { N }>;, the mutation would change { N } to N or (N). If the seed program uses a similar pattern in an impl for a struct like impl<const N: usize> Trait for Type<T, { N }>, the same change applies. The operator must ensure that any lifetime or type parameters referenced are those already present in the scope; no new identifiers are introduced. If the const expression block contains more complex expressions, such as { N + 1 }, the operator does not apply, as it only targets simple { N } blocks. The goal is to create a mismatch or ambiguity in const argument resolution that may lead to internal compiler errors like unexpected inference variables.
