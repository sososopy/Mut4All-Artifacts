mutation operator: Insert a local lifetime bound inside a generic const argument block expression. This mutation targets const generic arguments that are block expressions, specifically when the generic_const_exprs feature is enabled. It applies to any function call or type instantiation where a const generic parameter is supplied via a block expression. The mutation inserts a local variable binding with an explicit lifetime annotation inside that block, before the final expression. For example, if the seed program contains a call like `foo::<{ ... }>()` where the block currently contains only a final expression, the mutation modifies it to `foo::<{ let _: &'a (); ... }>()`. The lifetime `'a` must be an existing named lifetime parameter in scope, chosen from the surrounding function's generic parameters. If no such named lifetime exists, the mutation does not apply. The inserted statement is `let _: &'a ();` placed as a preceding statement in the block, ensuring the block still evaluates to the same const value but now includes a lifetime annotation that may affect region checking. This change mimics the exact pattern that triggered the ICE in the bug report, stressing the interaction between region inference and const evaluation within generic const arguments.
