mutation operator: Replace a const generic argument in a where-clause bound with a function item identifier from the current scope.

This operator targets where-clauses that impose bounds on const generic parameters, specifically array repeat expressions like `[T; N]` or similar const-argument positions within bounds. It applies when a seed program contains both a generic function or struct with a const generic parameter and at least one free function (non-method) item in scope. The mutation replaces a valid const argument (like a literal or a const parameter name) with the identifier of an existing free function. The function identifier must be visible and must not be a method call. The goal is to create a scenario where a function item is incorrectly used as a const argument, which may expose incomplete handling in the compiler's const generics lowering or well-formedness checking.

The change is made directly in the abstract syntax tree (AST) at the point of the const argument. For a seed program containing `fn foo() {}` and a generic item like `fn bar<const N: usize>() where [(); N]: {}`, the mutation could produce `fn bar<const N: usize>() where [(); foo]: {}`. The operator only uses identifiers of functions that are already declared in the seed program; it does not introduce new items. If multiple const argument positions exist in where-clause bounds, one is selected non-deterministically. If multiple free function identifiers are available, one is selected non-deterministically to replace the original argument.

This operator is designed to trigger bugs related to the validation and lowering of const generic arguments, particularly under incomplete features like `min_generic_const_args`, where the compiler may not properly reject or handle non-const items in const argument positions, potentially leading to internal compiler errors.
