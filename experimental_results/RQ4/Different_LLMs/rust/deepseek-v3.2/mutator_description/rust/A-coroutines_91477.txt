mutation operator: replace `yield` expression in a generator with a `return` statement that yields the same value via a `FromIterator` trait implementation on a generator-compatible type.

applies to: any function body containing a `yield` expression where the function's return type is an `impl Trait` that could be satisfied by an iterator (commonly `impl Iterator`).

change: locate a `yield expr;` statement. replace it with `return SomeType::from_iter(vec![expr]);` where `SomeType` is a type that implements `FromIterator<Y>` (where `Y` is the type of `expr`) and also implements the expected return trait (e.g., `Iterator`). if the seed program already contains a suitable type that implements `FromIterator` and the target trait (like `std::vec::Vec` or `std::collections::LinkedList`), use that type. if no such type exists, introduce `std::vec::Vec` as it is always available in the prelude. ensure the return type of the function remains compatible; if the return type is `impl Iterator`, `Vec::into_iter()` can be called on the returned value, but since `Vec` itself implements `IntoIterator`, returning a `Vec` also satisfies `impl Iterator`. therefore, change the statement to `return vec![expr];`.

example: original code snippet: `fn get_contents() -> impl Iterator { yield "hello"; }`. mutated code: `fn get_contents() -> impl Iterator { return vec!["hello"]; }`. this removes the generator state machine construction and replaces it with a direct return of a collection that is also an iterator, testing the compiler's handling of trait resolution and return type inference in contexts where generators are expected.
