mutation operator
Target construct: binary operations (arithmetic, bitwise, comparison) involving operands of different integer types, particularly when one or both operands are obtained via unsafe field accesses from a union. This applies to any binary expression where the types of the left and right operands are not identical integer types and at least one operand originates from an unsafe union field read.

Description: Replace a binary operation's operator with another binary operator that has different type coercion or overflow behavior, or change the order of operands to trigger different type interactions. Specifically, for a binary expression `a op b`, where `a` and `b` are expressions of potentially different integer types (e.g., i32 and u32), mutate by swapping the operator to a different one from the set {Add, Sub, Mul, Div, Rem, BitAnd, BitOr, BitXor, Shl, Shr, Eq, Ne, Lt, Le, Gt, Ge}. Alternatively, swap the operands to `b op a` if the operator is non-commutative (e.g., Sub, Div, Rem, Shl, Shr, Lt, Le, Gt, Ge). The mutation should preserve the original types of the operands.

Example: Given an expression `x - y` where `x` is of type u32 and `y` is of type i32, mutate to `x + y` (changing operator) or to `y - x` (swapping operands). Another example: `a < b` where `a` is u64 and `b` is i64 could be mutated to `a > b` or `b < a`. The mutation must only use variables and types already present in the seed program. No new declarations are introduced; only the operator or operand order in the expression is altered. This mutation targets the potential for the compiler to incorrectly handle type mismatches or asymmetric operations during const-evaluation or mir transformation.
