mutation operator: replace array length expression in array type with a large constant value that exceeds typical architectural address space limits, targeting the const evaluator's handling of oversized arrays in constant contexts.

this operator applies when the seed program contains an array type definition where the length is expressed as a compile-time constant expression, such as a numeric literal, a constant expression involving built-in functions, or a simple arithmetic operation. the operator specifically targets the length expression within array type syntax, e.g., `[T; LENGTH]`. the goal is to mutate the length to a value that is extremely large, likely to cause overflow or allocation failures during const evaluation.

the mutation changes the length expression to `usize::MAX >> SHIFT`, where `SHIFT` is a small integer (like 0, 1, or 2) to ensure the value remains within the range of `usize` but is excessively large for memory representation. if `usize::MAX` is not already in scope, the operator uses the fully qualified path `std::usize::MAX` or ensures the `std` prelude is considered. the operator selects this mutation because the bug report involves an array length of `usize::MAX >> 2`, which triggered an internal compiler error during const evaluation.

for example, given a seed program snippet: `struct S([u8; 10]);`, the operator would mutate it to: `struct S([u8; usize::MAX >> 2]);`. if the original length is an expression like `N * 2`, the operator replaces the entire expression with `usize::MAX >> 2`. the operator only applies to array types that appear in any context (struct definitions, type aliases, function signatures, etc.) and where the length is determinable as a constant expression. it avoids ambiguous cases by requiring the array type to be explicitly written in the source.

the operator ensures that the mutated length uses `usize::MAX` which is a defined constant in the standard library, thus not introducing undeclared identifiers. if the seed program does not have `usize` imported, the operator still uses `usize::MAX` as it is always available in the core prelude. no new items are introduced beyond this expression change.

the change is made directly to the abstract syntax tree node representing the array length, preserving the rest of the program structure. this mutation aims to stress the const evaluator with large array sizes, potentially exposing similar bugs to the reported ICE.
