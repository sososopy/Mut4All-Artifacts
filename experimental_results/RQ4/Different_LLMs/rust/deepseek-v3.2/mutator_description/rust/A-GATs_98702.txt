mutation operator GATs - Associated Type with Const Parameter in Trait Impl with Macro Expansion
This operator targets trait implementations involving Generic Associated Types (GATs) where the associated type definition uses const generic parameters in a complex expression, especially when generated via macro expansion. It applies to trait impl blocks that define an associated type Node<T> where the concrete type involves const parameters in its generic arguments, specifically when those const arguments are computed expressions referencing the const parameters. The mutation modifies the expression used for the const generic argument within the associated type definition in the trait impl. Specifically, it changes the const expression that uses multiplication or other arithmetic operations to a different operation or constant, while preserving the same const parameter names from the trait definition. For seed programs containing a trait like 'trait NodeT<const N: usize> { type Node<T>; }' and an impl such as 'impl NodeT<C> for SomeType { type Node<T> = SomeStruct<T, C, {C * C}>; }', the operator changes the const expression {C * C} to a different form, for example {C + C} or {C * C + 1} or {C} alone. The new expression must be a valid constant expression using existing const parameters. If the original uses a binary operation like multiplication, replace it with addition, subtraction, or a different constant literal that still results in a usize. Ensure the mutated const expression does not introduce undeclared identifiers; use only the const parameters already in scope (like N from the trait) and integer literals. For example, if the seed has 'type Node<T> = Node<T, $n, {$n*$n}>;' inside a macro, mutate to 'type Node<T> = Node<T, $n, {$n+$n}>;' or 'type Node<T> = Node<T, $n, {$n*$n+1}>;'. The goal is to alter the const value computation while keeping the structure of GAT with const generics, which may expose ICEs in the compiler's handling of late-bound regions and normalization.
