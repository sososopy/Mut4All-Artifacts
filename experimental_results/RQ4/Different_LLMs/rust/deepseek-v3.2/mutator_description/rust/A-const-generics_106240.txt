Mutation operator: Const generic parameter substitution in trait bounds. This operator targets trait bounds within impl blocks where a const generic parameter is used as a type argument within the bound. Specifically, it applies when a trait bound of the form `T: Trait<ConstParam>` or `T: Trait<{expr}>` is found in a where clause on an associated function or method inside an impl block that also defines that const generic parameter. The mutation changes the const generic parameter used in the bound to a different const expression that is valid in the current context. The change must use elements already present in the seed program. If no other suitable const expression exists, the operator may substitute the const parameter with a simple literal (like 0 or 1) of the correct type, but only if such a literal is type-compatible (e.g., usize). The goal is to alter the const argument in the trait bound while keeping the rest of the function signature and impl block intact, potentially creating a scenario where the trait bound's const argument differs from the one implied by the struct or impl context. For example, given a seed where an impl defines `const N: usize` and a method has a bound `T: Bar<N>`, the mutation could change the bound to `T: Bar<0>` or `T: Bar<M>` if another const `M` is in scope. This aims to expose bugs in the compiler's handling of mismatched or unsatisfied const generic arguments in trait bounds during type checking or const evaluation. Example: In the provided code, the bound `T: Bar<N>` in `unsatisfied` would be mutated to `T: Bar<0>`. No new declarations are introduced unless a literal is used; the literal `0` is implicitly of type usize. The change is made only in the where clause of the function.
