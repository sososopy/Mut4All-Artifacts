mutation operator: Replace a constant expression in a const generic argument or where-clause bound with a more complex expression that introduces redundant arithmetic operations and nested blocks, targeting generic const expressions with feature gates.

This operator applies when the seed program contains a const generic parameter used in an expression within a const context, such as an array length, a where-clause bound, or a const argument. The operator selects a const expression E that involves a const generic parameter N. It mutates E into ( { { N } } ) or ( ( N - 1 ) + 1 + N ) or similar, wrapping the original expression in extra blocks and adding arithmetic operations that simplify to the original value but introduce additional syntactic nesting. The new expression must be well-typed and evaluate to the same constant value as E. The operator should only apply if the seed already uses the generic_const_exprs feature or if the operator adds the feature gate #![feature(generic_const_exprs)] to the crate root when introducing such expressions. The mutation aims to stress the const evaluator with nested blocks and redundant operations that may expose ICEs in const evaluation during trait selection.

Example transformation: In a function signature like fn foo<const N: usize>(_: [u8; N]) {}, mutate the array length expression N into { { N } }. In a where-clause like where [(); L]:, mutate the expression L into (L - 1) + 1 + L. Use existing const parameter names from the seed. Avoid introducing new variables or types.
