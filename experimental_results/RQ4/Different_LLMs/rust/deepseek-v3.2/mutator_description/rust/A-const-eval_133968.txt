mutation operator for static items with nested struct initializers involving unsized types and references: change the static item's initializer expression by adding an extra layer of struct construction or reference indirection using existing types and variables. This operator applies when a static item's type involves generic structs with 'static lifetime bounds and unsized type parameters, and its initializer already contains struct construction. The mutation adds an extra wrapper struct instantiation or an additional reference dereference/address-of operation within the initializer, using only types, variables, and functions present in the seed program. Specifically, if the static initializer is a struct constructor call (or a block containing one), locate a subexpression that is a reference to a struct value. Then, wrap that subexpression in another instantiation of the same struct type (if possible) or add an explicit dereference followed by an immediate reborrow (i.e., &*expr). If the struct type has a field that is a reference, replicate the field initialization with the wrapped or reborrowed value. For example, given a static item like static C: Outer<Inner<[u8]>> = Outer(&Inner { x: &data });, where Outer and Inner are struct types defined in the seed, mutate to static C: Outer<Inner<[u8]>> = Outer(&Inner { x: &Inner { x: &data } }); if Inner can be nested, or to static C: Outer<Inner<[u8]>> = Outer(&Inner { x: &*&data }); adding a dereference-reborrow chain. This increases complexity of const-evaluated nested initializers and may trigger missing const-eval handling for unevaluated consts.
