Mutation Operator: Const Generic Parameter Type Substitution with Inferred Conflict

This mutation operator targets const generic parameters in struct definitions, impl blocks, and function signatures where the const parameter has a type that is a user-defined type (non-primitive). It substitutes the const parameter's type with a different existing type in the seed program that is incompatible or leads to ambiguous inference, particularly in contexts involving trait implementations or expressions that use the const parameter. The goal is to create a situation where the compiler must reconcile const values of mismatched types during inference, potentially triggering an ICE similar to the reported bug.

Applicability: This mutation applies when a const generic parameter in a struct, enum, trait impl, or function has a type that is not a primitive (i.e., not integer, bool, char). It requires the seed program to have at least two distinct user-defined types or one user-defined type and a primitive type available.

Procedure: For each const generic parameter declaration of the form `const PARAM: TYPE`, where `TYPE` is a user-defined type (e.g., a struct or enum defined in the seed program), replace `TYPE` with another existing type from the seed program. Prefer substituting with a primitive type (like `bool` or `i32`) if available, as the bug involves mixing `bool` and `Dimension`. If no primitive type is present, use a different user-defined type. Ensure the substitution is applied consistently in all relevant contexts where the const parameter is used (e.g., in struct fields, impl headers, function signatures) to maintain syntactic correctness while creating type conflicts.

Example: Suppose the seed program defines two structs, `Dimension` and `Weight`, and uses `Dimension` as a const parameter type. Original code: `struct Quantity<S, const D: Dimension>(S);`. After mutation, change to: `struct Quantity<S, const D: bool>(S);` if `bool` exists in scope, or to `struct Quantity<S, const D: Weight>(S);` if `Weight` is another user-defined type. Additionally, update any related impl or function using `const D: Dimension` to `const D: bool` (or `Weight`) accordingly. This creates a mismatch where the const parameter's expected type differs from its usage, potentially causing inference conflicts during trait resolution.
