Based on the bug report labeled F-adt_const_params, Rust compiler bugs are more likely to trigger when using advanced type system features like ADT (Algebraic Data Type) const parameters, especially involving complex constant expressions, arrays, and type aliases. The bug occurs during debuginfo generation when comparing types that are structurally identical but may have different representations due to const parameter evaluation.

Mutation operator: Replace a const parameter in a generic struct instantiation with an equivalent constant expression that uses a different syntactic form but represents the same value. This targets the scenario where the compiler may incorrectly treat syntactically different but semantically equal constant expressions as distinct types during debuginfo type mapping.

Specifically, this mutation applies to struct instantiations that use const parameters of array or composite types. For a struct definition like `struct S<const C: T>`, and an instantiation `S<CONST>`, where CONST is a constant expression of type T, mutate the instantiation to use a different constant expression that evaluates to the same value as CONST. If the seed program contains a type alias for the constant type, use the alias; otherwise, construct an equivalent expression using existing constants or literals.

The mutation would change the impl to use the direct constant value instead of the alias or function call. For instance, replace `Walk<0, BRIDGE_MATRIX>` with `Walk<0, [[0; N_ISLANDS]; N_ISLANDS]>`. This changes the syntactic form of the const parameter while preserving its value, potentially exposing bugs in type identity checking during debuginfo generation.

Steps: Identify all generic struct instantiations that use const parameters of array or composite types. For each instantiation, if the const parameter is a named constant (like BRIDGE_MATRIX), replace it with its literal definition or an equivalent expression using existing constants (like EMPTY_MATRIX). This mutation should be applied only when such equivalent expressions exist in the seed program to avoid introducing undefined names.
