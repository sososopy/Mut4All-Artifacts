mutation operator: Introduce a lifetime shadowing conflict in RPITIT implementations.

This operator targets trait implementations that use Return Position Impl Trait In Trait (RPITIT). Specifically, it applies when an impl block for a trait with associated types that have lifetime parameters also defines a method returning impl Trait referencing those associated types. The mutation introduces a new lifetime parameter in the impl block that shadows an existing lifetime parameter from the trait's associated type, then uses that shadowed lifetime incorrectly in the RPITIT return type.

Apply this mutation to any impl block implementing a trait with an associated type that has a lifetime parameter, where the impl contains a method using RPITIT that references the associated type. First, identify the trait's associated type declaration with a lifetime parameter, e.g., `type Item<'a>;`. Then, in the impl block, if there is already a generic lifetime parameter (e.g., `impl<'a, T> Trait for Type<'a, T>`), add a new lifetime parameter with the same name as the associated type's lifetime parameter, placed before the existing ones to shadow it. For example, change `impl<'a, T> Trait for Type<'a, T>` to `impl<'a, 'a, T> Trait for Type<'a, T>`. This creates a duplicate lifetime parameter declaration. Next, within the impl block's method that uses RPITIT and references the associated type, replace the lifetime argument used for the associated type with the shadowed lifetime name. For instance, if the method return type is `-> impl Iterator<Item = Self::Item<'some_lifetime>>`, change `'some_lifetime` to the shadowed lifetime name `'a`. If the method does not already reference the associated type with a lifetime, add such a reference using the shadowed lifetime.

The mutation should use lifetimes and type names already present in the seed program. Do not introduce new data names, types, or variable names beyond the duplicate lifetime parameter. The duplicate lifetime parameter must be declared in the impl block's generic parameters. The goal is to create a scenario where lifetime shadowing interacts with RPITIT refinement checking, potentially triggering internal compiler errors related to region checking.
