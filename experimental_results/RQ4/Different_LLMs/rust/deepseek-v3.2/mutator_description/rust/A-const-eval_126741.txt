mutation operator: Replace a constant item with a zero-sized closure that is used via a reference from multiple functions. This operator targets constant items with function pointer types, specifically those that are zero-sized closures, and ensures they are referenced via a shared reference from multiple distinct functions. The operator applies when a seed program contains a constant item of a function pointer type or a closure type with no captures. The mutation changes the constant's initializer to a closure expression that has no captures and returns the unit type. Then, it ensures the constant is referenced via a shared reference in at least two separate functions. If the seed program already contains multiple functions that use the constant, no new functions are introduced. If only one function uses the constant, a new function is added that also references the constant via a shared reference. The new function is declared with a unique name that does not conflict with existing items, for example by appending a numeric suffix to the constant's name. The new function must be defined in the same module scope as the constant and should be public if the constant is public to maintain visibility consistency. The constant's type should remain unchanged. For example, given a seed program with a constant item of type fn() -> (), the mutation changes its initializer to a closure like || {} and ensures it is referenced via &CONST_NAME in at least two functions. The operator does not introduce new types or variables beyond the possible new function. The goal is to create a scenario where the compiler's incremental compilation and optimization passes may incorrectly handle the constant's allocation identity across different compilation sessions.
