mutation operator: Add an async modifier to a const function declaration in an impl block that does not already have an async modifier. Apply this mutation when the impl block is for a trait, and the function signature does not already contain the async keyword. The function must be declared with the const keyword. The mutation changes the function declaration by inserting the async keyword before the const keyword. If the function already has a pub, default, or unsafe keyword, maintain the existing order but place async directly before const. If the function body contains an expression that uses .await, ensure that expression remains unchanged. If the function body does not contain an await expression, no change to the body is required. If the trait definition does not declare the mutated function, the mutation should still be applied, as this may trigger type checking cycles or ICEs related to const and async interaction. This mutation targets the specific combination of const and async in trait impl contexts, which is known to cause internal compiler errors in the mir_const_qualif query as observed in the bug report. Example: In a seed program with a trait impl containing a const fn method(), mutate it to async const fn method().
