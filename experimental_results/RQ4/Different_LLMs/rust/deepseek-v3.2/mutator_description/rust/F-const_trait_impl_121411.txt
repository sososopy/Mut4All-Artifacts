mutation operator: change the number of arguments in a trait method implementation that is marked with const to mismatch the trait signature, specifically targeting const trait impls with mismatched argument counts.

This mutation operator applies to any impl block annotated with const that implements a trait method. It modifies the number of parameters in the method signature within the impl block to differ from the number defined in the trait. If the trait method has N parameters, the mutation changes the impl method signature to have M parameters, where M is chosen as either N+1 or N-1, ensuring M is non-negative. The new parameters must be given types. To derive these types, examine the existing parameter types in the trait method signature. If adding a parameter, use the type of an existing parameter from the trait method, preferring the first parameter's type if available. If removing a parameter, delete the last parameter in the impl method signature. The mutation must not alter the trait method signature itself, only the impl method signature. Additionally, the mutation should ensure that the impl method body, if present, is adjusted to either ignore the extra parameter (if added) or remove usage of the removed parameter (if removed), but only if the body is simple and directly references parameters; if the body is complex or references the parameter in a non-trivial way, the mutation may leave the body unchanged, potentially causing type errors that are acceptable. This operator targets the scenario where the compiler's const evaluation logic may incorrectly handle the ABI mismatch between the trait signature and the impl signature in const contexts.

Example: Suppose the seed program contains a const trait impl like: const trait Trait { fn method(x: i32, y: i32) -> i32; } impl const Trait for Type { fn method(x: i32, y: i32) -> i32 { x + y } }. After mutation, the impl could become: impl const Trait for Type { fn method(x: i32, y: i32, z: i32) -> i32 { x + y } } where an extra parameter z of type i32 (same as first parameter type) is added, or: impl const Trait for Type { fn method(x: i32) -> i32 { x + y } } where the last parameter y is removed, causing a potential reference to undefined y in the body. The mutation prioritizes using existing types from the trait signature to avoid introducing new types. If the trait method has no parameters, adding a parameter requires introducing a type; in that case, use a primitive type like i32 that is likely present in the program context.
