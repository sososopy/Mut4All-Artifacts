Mutation operator: Replace opaque type alias with inferred concrete type in pattern matching context.

Applies when: A pattern match (match expression or let binding pattern) is performed on a binding declared with an opaque type alias (using `impl Trait` in type alias position, e.g., `type T = impl Copy;`). The mutation specifically targets cases where the opaque type alias is used to declare the type of a variable that is later matched or destructured.

Change: For a given variable `v` declared with an opaque type alias `type Alias = impl Trait; let v: Alias = expr;`, locate all pattern matches (including `let` bindings with patterns) that use `v` as the scrutinee. Replace the type annotation `: Alias` on the declaration of `v` with the concrete type inferred from the initializer expression `expr`. This concrete type must be deducible from `expr` without requiring additional type annotations. If `expr` is a function call or otherwise has a generic or opaque type itself, this mutation does not apply.

Example: Original code contains `type T = impl Copy; let foo: T = Some((1u32, 2u32));` followed by `match foo { ... }`. The initializer `Some((1u32, 2u32))` has concrete type `Option<(u32, u32)>`. The mutation changes the declaration to `let foo: Option<(u32, u32)> = Some((1u32, 2u32));` while keeping the `type T = impl Copy;` alias definition unchanged (though it may become unused). The subsequent pattern match on `foo` now operates on a concrete type instead of an opaque alias.

Rationale: This mutation directly triggers the compiler's handling of pattern matching with opaque types, which involves special logic for exhaustiveness checking and constructor categorization. The bug report shows an ICE occurring when matching on an opaque type alias in a closure upvar context. By substituting the opaque alias with a concrete type, we test whether the compiler's pattern matching logic behaves consistently between opaque and concrete types, potentially exposing mismatches in type representation or constructor handling that lead to internal compiler errors. This mutation has high coverage because it targets a specific feature interaction (opaque types + pattern matching) present in the bug report and can be applied to many pattern forms (enum, struct, tuple). The change uses only existing elements from the seed program, replacing the opaque alias annotation with a concrete type derived from the existing initializer expression.
