Mutation operator: Introduce a dyn ~const trait object with a non-auto trait in a context where trait objects are allowed but const trait bounds are not fully validated.

This mutation operator targets code constructs where trait objects are formed, specifically involving the `~const` syntax for const trait bounds, which is an experimental feature. The operator applies to any place where a dyn trait object type is specified, such as in variable type annotations, function signatures, or type arguments. The mutation modifies a dyn trait object by inserting `~const` before a trait name within the object, when the trait is not an auto trait (like Send or Sync). For example, if the seed program contains `let x: &dyn ExistingTrait;`, the mutation changes it to `let x: &dyn ~const ExistingTrait;`. If the seed program does not have a dyn trait object, the operator first introduces one by creating a variable with a type annotation referencing an existing trait from the seed program. For instance, if there is a trait `Trait` defined, the mutation adds a statement like `let _: &dyn ~const Trait;` to the function body. The operator ensures that the trait used is not an auto trait, as auto traits are allowed in trait objects and may not trigger the bug. This mutation is designed to expose bugs in the compiler's handling of const trait bounds in trait objects, particularly in the type lowering or object safety checking phases, as seen in the bug report where an assertion failure occurs due to mismatch between alias and fresh types. The mutation should be applied only when the `const_trait_impl` feature is not enabled in the crate attributes, to avoid early feature gate errors and potentially reach deeper compiler passes. Additionally, the mutation can be applied to existing dyn trait objects that already have multiple trait bounds by inserting `~const` before one of the non-auto traits, e.g., changing `&dyn Trait1 + Trait2` to `&dyn Trait1 + ~const Trait2`. This increases the chance of triggering internal compiler errors related to projection and alias type mismatches during trait object analysis.
