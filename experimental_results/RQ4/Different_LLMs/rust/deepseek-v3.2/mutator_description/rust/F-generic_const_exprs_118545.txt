mutation operator: Change the type of a const generic parameter from a supported type (like integer, bool, char) to a function pointer type in a struct, enum, or function definition that uses generic_const_exprs feature.

This mutation applies when the seed program uses the generic_const_exprs feature and contains a struct, enum, or function definition with a const generic parameter of a currently supported type (e.g., usize, i32, bool, char). The mutation modifies the const generic parameter's type to be a function pointer type. The function pointer type should be constructed using a function that already exists in the seed program. If no suitable function exists, introduce a trivial function that matches a simple signature (e.g., fn() -> ()) and declare it in the same scope. The change is made directly in the definition of the generic parameter.

Example: Suppose the seed program contains: struct S<const N: usize>; and a function fn f() -> bool { true } exists. Mutate to: struct S<const N: fn() -> bool>;.

If no function with a matching signature exists, add a new function declaration such as fn dummy() -> () {} and then change the const generic parameter type to fn() -> ().

The mutation should be applied only once per seed program, targeting the first eligible const generic parameter definition. This aims to trigger internal compiler errors related to unsupported const generic types and constant evaluation, similar to the reported bug.
