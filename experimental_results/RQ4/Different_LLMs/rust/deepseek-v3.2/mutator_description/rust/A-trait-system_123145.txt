mutation operator: replace a function return type that is an impl Trait with a unit tuple of that same function's name, thereby creating a self-referential impl Trait return type.

applies to: any function signature with a return type of `impl Trait` where the function name is in scope and can be referenced.

changes: locate a function definition with a return type of `impl Trait`. change the return type to `(function_name,)` where `function_name` is the identifier of the function being mutated, resulting in a return type like `(func,)`. this constructs a unit tuple containing the function item itself, which often has a type that is a function pointer or similar, and wraps it in a tuple. this can create complex cycles when combined with blanket trait implementations for tuples and functions, similar to the bug report.

example: given a seed function `fn example() -> impl Display { 5 }`, mutate to `fn example() -> (example,)`. this uses the existing function name `example`. no new elements are introduced beyond the tuple syntax; the function name must already exist.

constraints: this mutation only applies if the function's identifier is valid and in scope within its own return type annotation. it does not apply to methods with `self` parameters in a way that would create immediate syntax errors. prefer using the exact function name as it appears in the definition.
