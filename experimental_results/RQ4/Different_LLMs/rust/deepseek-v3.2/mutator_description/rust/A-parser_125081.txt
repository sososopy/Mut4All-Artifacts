mutation operator
Target: Incorrectly terminated character literals in generic argument contexts.
Applicability: When a char literal appears as a value within angle brackets (e.g., as a generic argument or const argument), and the char literal is not properly closed with a single quote. Specifically, the mutation applies to char literal tokens that are missing the closing quote and are followed immediately by a comma, greater-than sign, or other token that would normally end a generic argument list.
Mutation: Insert a closing single quote (') immediately after the char literal's opening quote and content, but before the next token. If the char literal content is a single character (like 'a'), it becomes 'a'. If the content is a Unicode escape sequence (like '\u{03B2}'), it becomes '\u{03B2}'. If the content is an invalid multi-character sequence, it becomes that sequence followed by a quote. The mutation does not add any new variable or type; it only fixes the syntax of the existing char literal token.
Example: In seed code with a pattern like `let _: Type<&str, 'a> = ...;` where 'a is a lifetime, mutate it to `let _: Type<&str, 'a'> = ...;` (note this changes lifetime to char). However, the bug is triggered when the parser misinterprets an unclosed char literal. So for a seed like `let _: Cell<&str, "a"> = Cell::new('β);`, the char literal 'β is unclosed. The mutation would produce `let _: Cell<&str, "a"> = Cell::new('β');`. This mutation should be applied whenever a single quote is followed by any characters (including Unicode) and then immediately by a comma, >, or other delimiter without an intervening closing quote.
Preference: Use existing char literals in the seed. If none exist, the mutation is not applied. The change is purely syntactic: add a single quote character.
