mutation operator
target code construct: trait implementations that include a method not defined in the trait, specifically within const contexts and involving associated type bounds or effect syntax.
description: replace an existing trait method implementation with a new method that is not declared in the trait. the new method should have a return type that is an impl trait with const bounds, and its body should return a value that matches the return type. this mutation applies to any trait impl block that already implements at least one trait method. if the trait impl block is within a const context (i.e., marked with const keyword), the mutation should also add const to the new method signature. the new method name should be derived by appending a numeric suffix to an existing method name in the same impl block, ensuring the name is not already present in the trait definition. if no existing method name exists, use a generic name like "extra_method". the return type should be an impl trait with the same const bounds as those used elsewhere in the seed program, such as ~const PartialEq + ~const Destruct, and should return a simple value like a literal integer that satisfies those bounds. do not introduce new traits or types; use existing traits and types from the seed program. for example, if the seed program contains impl const Foo for SomeType, and Foo has a method bar defined, mutate by adding a method bar2 with signature fn bar2() -> impl ~const PartialEq + ~const Destruct { 123 } inside the same impl block. this mutation is designed to trigger query cycles and deadlocks in the compiler's const checking and trait solving logic, particularly when combined with associated type bounds and effect syntax.
