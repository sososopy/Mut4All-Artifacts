mutation operator: Mutate const generic parameter in struct or function definitions from a concrete constant expression to a complex nested ADT constant expression involving references and generic types, when the feature adt_const_params is enabled. This applies when the seed program contains a struct or function with a const generic parameter that is currently a simple literal or a trivial struct, and the program has the #![feature(adt_const_params)] attribute. The mutation changes the const parameter to a more complex constant expression that uses struct initialization with fields that may include references to other ADTs with generic parameters. Specifically, if there exists a const generic parameter like const N: usize, change it to const N: SomeStruct where SomeStruct is a type already defined in the program that derives ConstParamTy, and the constant expression becomes an instance of SomeStruct that contains a reference to another ADT with a generic type parameter. Ensure that the types used in the mutation are already present in the seed program; if not, this mutation does not apply. For example, if the seed has struct Foo { value: i32, nested: &'static Bar<T> } and struct Bar<T>(T) both deriving ConstParamTy, and a struct Test<const F: Foo>, mutate any usage of a simple const generic parameter in a similar struct or function to use a Foo constant with nested Bar reference. The mutation should introduce a new constant expression that mirrors existing constant patterns in the program but varies field values or generic arguments slightly to create a distinct constant. This aims to trigger layout computation bugs in the compiler when handling complex ADT constant parameters.
