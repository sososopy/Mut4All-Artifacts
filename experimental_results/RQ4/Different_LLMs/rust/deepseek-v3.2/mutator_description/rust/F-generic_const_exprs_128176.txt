mutation operator: modify associated type binding in trait object with generic const expression
applies to: any trait object type that uses associated type bindings where the associated type has generic const parameters, specifically within dyn Trait<Assoc<const_expr> = Type> patterns. target seed programs must already define a trait with an associated type that has a generic const parameter (e.g., trait Trait { type Assoc<const N: T>; }) and must already contain a dyn Trait usage.
changes: locate a dyn Trait<Assoc<const_expr> = Type> pattern in the seed program. modify the const_expr within the angle brackets of the associated type binding to another const expression of the same type. preference is to use existing const items or literals that match the const parameter's type from the seed program. if no suitable const exists, introduce a new const item in the same scope as the usage. for example, if the seed has `const C: i32 = 5;`, change `dyn Trait<Assoc<1> = Ty>` to `dyn Trait<Assoc<C> = Ty>`. if the const parameter's type is integer, vary the expression: change a literal `1` to `0`, `2`, or `1+1`. ensure the new const expression type-checks (e.g., same type as the const parameter). do not change the associated type name or the binding type.
example: seed contains `trait X { type Y<const N: i16>; }` and usage `fn f(arg: Box<dyn X<Y<1> = ()>>) {}`. mutate to `fn f(arg: Box<dyn X<Y<0> = ()>>) {}` or if there is `const K: i16 = 2;` in scope, mutate to `fn f(arg: Box<dyn X<Y<K> = ()>>) {}`. if no const exists, add `const MUTATED_CONST: i16 = 3;` right before the function and change usage to `Y<MUTATED_CONST>`.
