Mutation operator: Replace a struct field initialization with a duplicate field name that shadows an earlier field in the same struct definition, applied when initializing a struct constant or static item. This operator targets struct initialization expressions within const contexts or static initializers. It requires that the struct definition in scope has at least two fields. The operator duplicates the name of one field from the struct definition, using it to initialize a second field in the same initializer, thereby creating a duplicate field name in the initializer which shadows the first. Specifically, for a struct `S { field1: T1, field2: T2, ... }` and an initializer `S { field1: expr1, ... }`, change it to `S { field1: expr1, field1: expr2, ... }` where `expr2` is an existing expression of the appropriate type from the surrounding context, such as another field initializer expression or a suitable constant. If no such expression exists, introduce a default value like `Default::default()` or a zero literal if the type permits (e.g., `0` for integer, `false` for bool). This mutation mimics the bug where duplicate field names in struct initializers, especially in static/const contexts, can trigger internal compiler errors during const-eval or type checking. Example: For seed code `struct Point { x: i32, y: i32 } const P: Point = Point { x: 1, y: 2 };`, mutate to `struct Point { x: i32, y: i32 } const P: Point = Point { x: 1, x: 2 };`. Ensure the duplicated field name matches an existing field in the struct definition and the expression for the duplicate has a type compatible with the field’s type, using existing values or defaults as specified.
