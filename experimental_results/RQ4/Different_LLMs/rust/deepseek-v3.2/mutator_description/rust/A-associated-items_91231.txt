mutation operator: Introduce an associated type projection from a reference to an extern type within a where-clause on an inline function.

This mutation applies when a seed program contains both an extern type declaration (using `extern { type Name; }`) and a trait with an associated type. It targets function definitions, specifically those with the `#[inline]` attribute. The operator adds a where-clause to such an inline function. The where-clause imposes a trait bound that references the extern type and projects its associated type. The bound is formulated as `&'a ExternType: Trait`, where `'a` is a lifetime parameter already in scope for the function (or introduced if none exists), `ExternType` is the name of an existing extern type in the program, and `Trait` is the name of an existing trait that has an associated type named `Type`. The function's parameter list is then extended with a new parameter whose type is the associated type projection `<&'a ExternType as Trait>::Type`. If the function previously had no parameters, a parameter is added; if it had parameters, the new parameter is appended. The function body remains unchanged; if the body references parameters, the new parameter is not used, which is acceptable for the purpose of triggering normalization code paths.

Specifically, for a seed program containing `extern { type Ext; }` and `trait Tr { type Ty; }`, locate any function with `#[inline]`. If the function has a lifetime parameter `'a`, use it; otherwise, introduce a new lifetime parameter `'a` into its generic parameter list. Add the where-clause `where &'a Ext: Tr`. Change the function signature to include a new parameter `_p: <&'a Ext as Tr>::Ty`. For example, a seed function `#[inline] fn g() {}` is mutated to `#[inline] fn g<'a>(_p: <&'a Ext as Tr>::Ty) where &'a Ext: Tr {}`. If the function already has a where-clause, the new bound is appended to it. The extern type name and trait name are taken directly from existing declarations in the program; no new types or traits are invented. This mutation is designed to replicate the conditions that trigger the compiler bug: an associated type projection from a reference to an extern type within the constraints of an inline function, which may cause normalization failures during compilation.
