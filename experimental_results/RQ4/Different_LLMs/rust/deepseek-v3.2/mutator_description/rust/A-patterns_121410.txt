mutation operator: Convert tuple pattern binding to a simple binding when the right-hand side expression is a field access or method call that returns a non-tuple type. This operator targets destructuring patterns in let statements and similar binding contexts where the pattern is a tuple pattern (e.g., let (a, b) = expr;). It applies when the expression on the right-hand side is a field access (like foo.x) or a method call that is known (from the seed program's context) to return a non-tuple type. The mutation changes the tuple pattern to a single identifier binding, using a fresh variable name if needed, but preferring to reuse an existing unused variable name from the surrounding scope if possible. The new binding's type will be inferred. For example, let (_, t2) = foo.x; becomes let t2 = foo.x;. If the tuple pattern has more than one binding, the mutation selects the first named binding (ignoring placeholders like _) to become the simple binding; if there are no named bindings, it introduces a new variable like bound_val. This mutation is designed to trigger pattern matching and type system inconsistencies, particularly around moves, borrows, and packed structs, as seen in the bug report where destructuring a non-tuple leads to an internal compiler error. The change must respect existing variable scopes to avoid name conflicts.
