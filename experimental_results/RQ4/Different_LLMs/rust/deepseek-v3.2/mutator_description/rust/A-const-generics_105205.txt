Mutation Operator:

Target Code Construct: This operator applies to const generic arguments and const expressions used in array lengths or where-clause bounds within functions or struct definitions that use the `generic_const_exprs` feature. Specifically, it mutates const expressions that are already present in the seed program by replacing them with a const parameter from an outer scope that has a mismatched type or is out of scope, potentially leading to unresolved const expressions during wfness checking.

Procedure: Identify a const expression that is used as a generic const argument, array length, or bound in a where-clause. Replace this const expression with a reference to a const parameter from an outer generic context that is not directly accessible in the current scope or whose type is incompatible. If no such const parameter exists in the seed program, introduce a new const parameter in an outer function or struct with a different type (e.g., `usize` vs `u32`) and use it in the mutated expression. Ensure the mutation creates a const expression that the compiler must evaluate during wfness checking but may fail to resolve due to scope or type mismatches.

Example: Suppose the seed program contains a function with a const generic parameter `N: usize` and uses a const expression like `N + 1` in an array length. The mutation would change `N + 1` to `M + 1`, where `M` is a const parameter from an outer function (e.g., `fn outer<const M: u32>()`) that is not in scope or has a different type. This forces the compiler to handle a `ConstKind::Expr` that references an invalid or type-mismatched const parameter during wfness computation.

Changes: Locate a const expression `expr` in a const generic argument, array length, or where-clause bound. Replace `expr` with `outer_const + adjustment`, where `outer_const` is a const parameter from an outer context (if absent, add `const OUTER: usize = 1;` at the crate root and use `OUTER`). This creates a new const expression that may trigger unsupported wfness checks.
