mutation operator: Replace a const trait impl with a non-const trait impl for a trait that also has a const impl elsewhere in the program. This operator targets trait implementations that are marked with the `const` keyword. It applies when the seed program contains at least one `const impl` block for a trait that is also implemented (const or non-const) elsewhere, potentially on a different type. The mutation changes the `const impl` to a regular `impl` by removing the `const` keyword. If the trait itself is not a `const trait` (i.e., declared with `#[const_trait]` or part of the nightly `const_trait_impl` feature), this change is valid Rust code but may alter trait resolution in complex contexts involving generics and pinning, particularly where the compiler internally generates trait bounds involving `~const`. The operator should prioritize modifying a `const impl` that is used within a generic context or a function that uses pin projections. For example, if the seed has `impl<T> const Deref for Wrap<T> { ... }`, mutate it to `impl<T> Deref for Wrap<T> { ... }`. Ensure the mutated code compiles by keeping all other parts of the impl identical, including generic parameters, associated types, and method signatures. Do not introduce new items; only modify the existing impl header.
