Mutation Operator: Constant Expression Mutation in Generic Const Expression Context

This mutation operator targets expressions within const generic arguments that are used in struct definitions, function signatures, or method return types, particularly when those expressions involve const generic parameters. The operator applies when a const generic argument is a simple arithmetic expression (like addition, subtraction, multiplication) involving a const generic parameter. The mutation changes the arithmetic operator to another one, potentially altering the expression's value or making it ill-formed, which can expose bugs in const evaluation or inference.

For a seed program containing a const generic expression like `{ N + 1 }` or `{ N - 1 }`, where `N` is a const generic parameter, the mutation operator will replace the arithmetic operator with a different one. Specifically, it will cycle through the operators `+`, `-`, `*`, `/`, `%`. The operator will only apply if all operands are either const generic parameters or integer literals, ensuring the mutation produces a syntactically valid expression. If the original operator is `+`, it might be mutated to `-`; if it is `-`, it might be mutated to `*`, and so on, in a deterministic sequence.

Example: In a seed program with a struct definition like `struct S<const N: usize>;` and an associated function `fn f() -> S<{ M + 1 }>` where `M` is a const generic parameter, the mutation could change `{ M + 1 }` to `{ M - 1 }`. This alteration could affect type compatibility or const evaluation, potentially triggering an ICE similar to the reported bug if the compiler mishandles the mutated expression during trait selection or const evaluation.

The mutation should be applied to every occurrence of such const generic expressions in the seed program, but only if the expression is used in a context where const generics are allowed (e.g., as a generic argument to a struct or function). New elements are not introduced; only existing operators are swapped. The goal is to test edge cases in const expression evaluation and inference, which are prone to ICEs in the Rust compiler, especially with the generic_const_exprs feature enabled.
