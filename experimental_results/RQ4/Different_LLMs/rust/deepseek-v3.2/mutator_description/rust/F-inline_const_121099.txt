Mutation operator: Insert an invalid constant expression within a global_asm! macro invocation using the const keyword. This mutation applies to any Rust program that uses the global_asm! macro with the asm_const feature enabled. The operator targets the arguments of the global_asm! macro where a const expression is expected. Specifically, it modifies a const argument by replacing it with a constant expression that provokes a compile-time evaluation error, such as a division by zero, an out-of-bounds array access, or a panic in a const context. The operator should locate a global_asm! macro call. If the call already contains a const argument, mutate that argument's expression to an erroneous one. If the call does not contain a const argument, insert a new const argument with an erroneous expression. The erroneous expression must be a valid Rust constant expression syntactically but must fail to evaluate at compile time. For example, change a const argument from a simple literal like const 5 to const 1 / 0. If the macro uses format arguments, ensure the number of placeholders matches the number of arguments after mutation. Use existing constant values from the program to construct the erroneous expression where possible, such as using a previously defined const item in a division by zero. For instance, if a const X: i32 = 1; exists, the mutation could produce const X / 0. If no suitable const exists, use a literal like 1 and an operation guaranteed to fail, such as division by zero. The goal is to trigger constant evaluation errors during the resolution of asm constants, potentially exposing internal compiler errors like the one in the bug report.
