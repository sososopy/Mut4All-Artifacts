mutation operator
Target code construct: const trait implementations with missing required trait items.
This mutation operator applies to impl blocks for traits, specifically when the impl block is marked with the const qualifier. The operator modifies the impl block by removing a required trait item (method, associated type, or constant) that is declared in the trait definition but not implemented in the impl block. The operator selects a trait item from the trait definition that is not already present in the impl block. If the trait definition contains multiple required items, one is chosen arbitrarily. If all required items are already implemented, this operator does not apply. The change is to delete the entire item from the impl block. For example, given a trait definition trait Trait { fn method(); } and an impl const Trait for Type { fn method() {} }, the operator would not apply because the required item is implemented. However, if the impl block were missing fn method, the operator would ensure it remains missing (no change needed). But to trigger bugs like the deadlock, we introduce an impl block that incorrectly implements a trait by adding an extra method not declared in the trait. The operator adds a method to the impl block that is not declared in the trait, mimicking the bug where fn huh was added. Specifically, the operator adds a new method to the const impl block. The new method's signature should be simple: it takes no parameters and returns a unit type (). The method name should be a fresh identifier not conflicting with existing names in scope; generate a name like missing_method_N where N is a unique number. The method body should be empty braces {}. This introduces a mismatch between trait definition and impl, similar to the bug's extra method huh. This can lead to query cycles or deadlocks during const checking. For instance, if seed has trait Foo { fn foo(); } and impl const Foo for S { fn foo() {} }, the operator changes it to impl const Foo for S { fn foo() {} fn missing_method_1() {} }. This extra method is not in the trait, causing an error, but may also trigger internal compiler state issues.
