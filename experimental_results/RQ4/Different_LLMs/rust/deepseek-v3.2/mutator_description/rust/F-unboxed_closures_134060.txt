mutation operator: replace a trait method default body parameter type with an unsized type that triggers improper ctype checking

target code construct: trait definitions with default method implementations where the method has an extern "C" or similar ABI and takes parameters. specifically applicable when the trait method is defined with a default body and one of its parameters is of a type that could be unsized. the mutation focuses on the parameter types within the signature of such trait methods.

operator description: identify any trait method with an explicit ABI (like extern "C") that provides a default implementation. for each parameter in that method's signature, if the parameter's type is a sized type, replace it with a type that is known to be unsized, such as dyn Trait, [T], or str, prioritizing types that already exist in the seed program's scope. if no such unsized type exists in scope, introduce a new trait (e.g., trait DummyTrait {}) and use dyn DummyTrait as the parameter type, ensuring the new trait is declared at an appropriate visible location (like the same module). the mutation changes only the parameter type in the method signature, not the method body, which may then cause a type mismatch that should be handled by the compiler's linting passes.

example: given a seed program snippet: trait Foo { extern "C" fn bar(&self, x: i32) -> i32 { x } }, the operator could mutate it to: trait Foo { extern "C" fn bar(&self, x: dyn SomeExistingTrait) -> i32 { x } } if SomeExistingTrait is in scope, or if not, declare trait Dummy {} and then change to: trait Foo { extern "C" fn bar(&self, x: dyn Dummy) -> i32 { x } }. note that the body still uses x, leading to a type error, but the focus is on triggering the improper ctype analysis on the unsized parameter.
