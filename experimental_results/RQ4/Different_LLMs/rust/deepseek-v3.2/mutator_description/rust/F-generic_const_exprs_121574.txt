mutation operator
target code construct: generic impl blocks with const generic parameters and associated functions returning nested impl Trait types. specifically applies to impl blocks for a generic type (or a type that does not exist, as in the bug report) that use a const generic parameter, where a method returns `impl Trait` containing another `impl Trait` in its associated type (like `impl Iterator<Item = impl Iterator<...>>`). the mutation operator modifies the lifetime bindings on the nested impl Trait.

changes: locate any function inside an `impl<const N: ...> ...` block that returns `impl Trait<Item = impl Trait<...>>`. within the return type, if the nested impl Trait has an explicit lifetime bound (e.g., `+ 'a` or `+ '_`), mutate that bound. if it has an explicit bound, remove it or change it to a different lifetime parameter already in scope (but not necessarily matching the outer lifetime). if no explicit bound is present, add a bound using a lifetime parameter that is already declared in the function's generic parameters (preferring the one used in the function signature, like `'a`). if no lifetime parameters exist in the function, introduce a new lifetime parameter to the function signature and use it as a bound.

example: given seed code like `impl<const Z: usize> X<Z> { fn y<'a>(&'a self) -> impl Iterator<Item = impl Iterator<Item = [u8; Z]> + '_> {} }`, the nested impl Trait has `+ '_`. mutate it to `+ 'a` (since `'a` is in scope). alternatively, if the seed code lacks a bound, add one: `impl<const Z: usize> X<Z> { fn y(&self) -> impl Iterator<Item = impl Iterator<Item = [u8; Z]>> {} }` becomes `impl<const Z: usize> X<Z> { fn y<'b>(&self) -> impl Iterator<Item = impl Iterator<Item = [u8; Z]> + 'b> {} }` where `'b` is newly introduced.

requirements: only apply when the generic_const_exprs feature is enabled (or could be added). prefer using existing lifetime names from the function's generic parameters. do not introduce undeclared lifetimes; if adding a bound requires a new lifetime, add it to the function's generic parameters first. avoid changing the const generic parameter or the outer type. focus solely on the lifetime bound attached to the inner impl Trait within the return type's associated type.
