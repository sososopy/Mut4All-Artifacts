mutation operator: nested generator mutation by inserting yield statements after mutable borrows of outer generator parameters within inner generators. This mutation applies to generator definitions (closures using yield) that capture mutable references from an outer scope, specifically when an inner generator is defined inside an outer generator. The mutation inserts a yield statement immediately after a mutable borrow of a variable that is captured from the outer generator's parameters within the inner generator's body. The yield statement must be placed in the inner generator after the mutable borrow expression but before any subsequent use of the borrowed reference. This targets the drop-tracking and borrow-checking interactions between nested generators. For example, if the seed program contains an outer generator with a parameter x of type &mut T, and an inner generator that mutably borrows x via let a = &mut *x;, then insert yield; right after that borrow statement inside the inner generator. If there is already a yield statement immediately after, no change is made. This mutation uses only existing variables and control flow constructs; it does not introduce new names or types. The inserted yield statement is simply yield;. This can create complex suspension points that may trigger unreachable code in conflict error reporting as seen in the bug.
