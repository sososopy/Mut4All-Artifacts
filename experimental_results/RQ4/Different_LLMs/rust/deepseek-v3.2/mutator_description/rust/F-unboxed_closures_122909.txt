mutation operator: modify function signatures that use the rust-call ABI to have a single non-self tuple argument

This operator applies to functions declared with the extern "rust-call" ABI. The operator changes the function's parameter list to consist of a single tuple parameter that contains all the original parameters (excluding self). If the function originally had no parameters besides self, the operator will introduce a single unit tuple parameter. If the function had multiple parameters besides self, the operator will combine them into a tuple type. Specifically, locate any function definition with the extern "rust-call" attribute. Replace its parameter list (excluding the self parameter) with a single tuple parameter that groups all those parameters. For example, if the original function is defined as extern "rust-call" fn f(self, a: TypeA, b: TypeB) -> ReturnType, mutate it to extern "rust-call" fn f(self, args: (TypeA, TypeB)) -> ReturnType. If the function is a method with only a self parameter, mutate it to extern "rust-call" fn f(self, args: ()) -> ReturnType. Ensure the function body is updated to destructure the tuple if necessary, by replacing direct uses of the original parameters with tuple field accesses (like args.0, args.1). If the function body is empty (like the example in the bug report), simply change the signature without altering the body. This mutation targets the specific condition that triggers the ICE: rust-call ABI functions must take a single non-self tuple argument. By creating seed programs that use extern "rust-call" functions with various parameter counts (including zero parameters besides self), and applying this mutation, we can expose compiler bugs in the handling of rust-call ABI during MIR transformations like inlining.
