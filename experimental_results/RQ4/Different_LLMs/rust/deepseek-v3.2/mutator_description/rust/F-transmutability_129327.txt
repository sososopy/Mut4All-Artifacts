mutation operator: Introduce an undeclared lifetime into a reference type within a struct definition that is used in a transmutability check.

This mutation applies to struct definitions that are referenced as the source or destination type in a call to a transmutability-checking function like `BikeshedIntrinsicFrom` or `is_transmutable`. The mutation modifies a field within the struct definition that is of a reference type (e.g., `&T`). It changes the lifetime specifier of that reference to a lifetime name that is not declared in the current scope. Specifically, for a field with type `&'existing T`, replace `'existing` with a new lifetime identifier `'undeclared` that is not introduced in the struct's generic parameters or the enclosing function. If the field already uses an explicit lifetime, that lifetime is replaced. If the field uses an anonymous lifetime (`'_`), it is replaced with the undeclared named lifetime. The struct must be defined locally within the function or module where the transmutability check is performed.

The changes are: locate a struct definition used in the transmutability check. Identify a field that is a reference type. Replace its lifetime with a new lifetime identifier not present in the current scope. No other declarations or parameters are added. The goal is to create a use of an undeclared lifetime within the struct.

Example: In the seed program, there is a struct `Src` with a field `a: &str`. The mutation would change it to `a: &'undeclared str`. No lifetime `'undeclared` is declared anywhere. This mimics the original bug's condition where the struct `Src` had a field `a: &'a str` but the lifetime `'a` was not declared on the struct. The mutation should not add the lifetime declaration to the struct; it should leave it undeclared.
