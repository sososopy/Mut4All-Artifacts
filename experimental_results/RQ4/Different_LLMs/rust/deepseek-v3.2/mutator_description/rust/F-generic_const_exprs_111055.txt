mutation operator: Substitute a const generic parameter default expression with a different const expression of the same type, specifically using a const item that references another const generic parameter from the same generic parameter list or from an outer scope, creating a potential dependency cycle or out-of-range substitution scenario. This applies to struct, enum, union, trait, function, or impl definitions where a const generic parameter has a default value that is a const expression.

The mutation changes the default expression of a const generic parameter. For a generic parameter list containing a const parameter with a default, locate the const parameter declaration. Identify its default expression, which is the `= <expression>` part. Replace this entire default expression with `= <const_item_name>`, where `<const_item_name>` is the name of an existing const item in scope. Prefer const items whose type matches the const parameter's type. If multiple const items exist, choose one that is not trivially equal to the original default, such as a const that itself is generic or depends on generic parameters. If no suitable const item exists in the current scope, introduce a new const item in the appropriate scope (e.g., at the module level if mutating a struct definition). The new const item should be declared as `const NEW_CONST: <type> = <value>;` where `<type>` matches the const parameter's type and `<value>` is a simple literal or expression that does not cause immediate compilation errors. The goal is to create a situation where the default value is a const that may lead to complex substitution logic, potentially triggering an out-of-range error during monomorphization.

Example: In a seed program containing `const DEFAULT_SIZE: usize = 1024;` and a struct definition `struct Buffer<T, const N: usize = DEFAULT_SIZE> { data: [T; N] }`, mutate the default expression. The mutated struct becomes `struct Buffer<T, const N: usize = DEFAULT_SIZE> { data: [T; N] }` (no change if only one const exists). To achieve mutation, if another const `const CHUNK: usize = 65536;` exists, change to `struct Buffer<T, const N: usize = CHUNK> { data: [T; N] }`. If no other const exists, introduce a new const at the module level: `const ALTERNATE_SIZE: usize = 2048;` and then mutate the struct to `struct Buffer<T, const N: usize = ALTERNATE_SIZE> { data: [T; N] }`. This can lead to scenarios where the default const value interacts with other generic parameters during instantiation, potentially exposing bugs in const parameter substitution.
