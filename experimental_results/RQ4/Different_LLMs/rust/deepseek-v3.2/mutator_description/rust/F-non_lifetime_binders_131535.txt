mutation operator: Replace an existing trait bound with a for<...> binder where the bound variable appears in a nested position without appropriate lifetime or type parameter support, targeting return types, argument types, or where clauses in functions or trait declarations.

This mutation applies to any trait bound in a function signature, trait definition, or where clause that uses a trait with generic parameters. The operator modifies the bound to introduce a higher-ranked trait bound (HRTB) using the for<...> syntax, but places the bound variable in a context where it may escape, such as inside an associated type projection, another trait bound, or a type that does not properly bind the variable.

Specifically, locate a trait bound like `T: Trait<U>` or `impl Trait<U>` in the seed program. Change it to `T: for<V> Trait<...>` where the bound variable V is used in a nested component that may not correctly handle the binder, for example, as an associated type like `T: for<V> Trait<Assoc = impl OtherTrait<V>>` or within another bound like `T: for<V> Trait<U = dyn OtherTrait<V>>`. Ensure the mutation uses existing trait names, type parameters, and lifetimes from the seed program. If the seed program lacks a suitable trait, introduce a simple trait definition without any generic parameters, like `trait Simple {}`, and then use it in the mutation. The introduced trait should be defined at the module level.

Example transformation for a function signature: if the seed contains `fn foo(x: impl Iterator<Item = u32>) {}`, mutate to `fn foo(x: impl for<T> Iterator<Item = impl Into<T>>) {}` where T is a new type parameter introduced in the for binder. Since T is not bound elsewhere, this may cause escaping bound variables. To use existing elements, if the seed has a trait `Tr` and a type `U`, change `fn bar() -> impl Tr<U>` to `fn bar() -> impl for<V> Tr<Assoc = impl Tr<V>>`.

Another example for a where clause: change `where T: MyTrait<Param = u8>` to `where T: for<P> MyTrait<Param = impl AnotherTrait<P>>`. Ensure the nested impl trait uses the bound variable P in a way that might not be properly handled by the compiler's binder infrastructure.
