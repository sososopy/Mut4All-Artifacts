Mutation operator: Mutate const generic arguments in associated type bounds within trait definitions.

This mutation operator targets trait definitions where an associated type has a bound involving another trait with a const generic parameter. Specifically, it applies when a trait has an associated type with a bound of the form `SomeTrait<U<CONST_EXPR> = SomeType>`. The operator replaces the const expression in the associated type bound with another const expression of the same type.

The mutation changes the const generic argument used in the bound of the associated type. For example, if the seed program contains `type T: B<U<1i32> = ()>;`, the operator might mutate it to `type T: B<U<2i32> = ()>;` by replacing the integer literal. The new const expression must be a valid constant of the same type as the original; it should be derived from existing constants in the seed program if possible, or a simple literal like 0, 1, or -1. No new variables, types, or functions should be introduced unless they are already present. The change is made directly in the trait definition where the associated type is declared.

This mutation is designed to expose bugs in the compiler's handling of const generics within associated type bounds, particularly in type checking and trait solving, which are likely to trigger internal compiler errors as seen in the bug report. It achieves coverage across programs that use const-generic associated types in trait bounds.
