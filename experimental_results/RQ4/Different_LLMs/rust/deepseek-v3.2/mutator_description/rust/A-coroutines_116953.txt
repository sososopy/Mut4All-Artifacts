mutation operator: The mutation operator targets functions annotated with #[no_mangle] that contain async blocks or other constructs that involve monomorphization (like generics) within their body. It replaces the #[no_mangle] attribute with #[inline(never)] and introduces a new dummy #[no_mangle] function that calls the original function. This mutation applies to any function in a seed program that has the #[no_mangle] attribute. The goal is to change the code generation and linkage context around monomorphization points while preserving the observable behavior of calling the original function. Specifically, for each function item with the #[no_mangle] attribute, the operator performs the following changes: first, remove the #[no_mangle] attribute from the original function and add #[inline(never)] to it; second, declare a new function with the same signature as the original but with a name derived by appending a suffix like _wrapper to the original function's identifier, and annotate this new function with #[no_mangle]; third, inside the body of this new wrapper function, make a call to the now #[inline(never)] original function, passing through all parameters and returning its result. If the original function has a return type other than (), the wrapper must return that same type. The wrapper function should be placed in the same module scope as the original function, directly after it. This mutation is designed to expose bugs related to monomorphization and code generation in functions that require unique symbol names, especially when combined with features like async blocks, generics, or panic=abort settings. For example, if the seed contains a function like #[no_mangle] fn foo() { let x = Some(AsyncBlock); }, it would be mutated to #[inline(never)] fn foo() { let x = Some(AsyncBlock); } #[no_mangle] fn foo_wrapper() { foo() } . This changes the compilation artifact layout and may trigger internal compiler errors similar to the reported issue.
