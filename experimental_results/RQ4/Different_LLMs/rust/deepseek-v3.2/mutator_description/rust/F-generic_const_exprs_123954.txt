Mutation Operator: Reorder Generic Parameters with Defaults

This mutation operator targets struct, enum, or trait definitions that have multiple generic parameters, where at least one const generic parameter has a default expression. It applies when a seed program contains a generic item with both const and type parameters. The operator reorders the generic parameters such that a const generic parameter with a default expression is placed before a type parameter that does not have a default (or vice versa, if the original order is different). This aims to expose mismatches in the compiler's internal indexing or substitution logic for generic arguments.

Apply to any generic item (struct, enum, trait, impl, function) with at least two generic parameters, where at least one is a const generic with a default expression. The mutation swaps the positions of two consecutive generic parameters in the definition. For example, if a struct has parameters [const N: usize = 3, T], mutate to [T, const N: usize = 3]. Ensure that the reordering does not introduce syntax errors (e.g., const parameters must still use valid const expressions). Use only the existing generic parameters from the seed; do not introduce new ones. The change is made directly in the source code at the definition site.

Example: For a seed with struct S<const N: usize = 5, T> { field: T }, mutate to struct S<T, const N: usize = 5> { field: T }. If the seed has struct S<T, const N: usize = 5>, mutate to struct S<const N: usize = 5, T>. This reordering may trigger the ICE by altering the expected order of generic arguments during compilation.
