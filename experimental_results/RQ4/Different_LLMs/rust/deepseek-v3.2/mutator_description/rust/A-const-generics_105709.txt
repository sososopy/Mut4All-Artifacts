mutation operator: Substitute const generic default expression with a const block that contains a const generic parameter reference from the same generic parameter list, but with an index that is out of bounds relative to the substitution context.

This mutation operator applies to struct definitions, enum definitions, and function definitions that have const generic parameters with default values. Specifically, it targets the default expression assigned to a const generic parameter. The operator replaces the default expression with a const block that references a const generic parameter from the same list using its index, but where the index is invalid (e.g., referencing a parameter that does not exist in the current substitution list). In the bug report, the default is `{ const {3} }`. The mutation would change it to something like `{ const { N } }` where `N` is the name of a const generic parameter from the same definition, but if there is only one parameter (the one being defaulted), referencing it creates a self-reference that may cause substitution issues. To generalize, the operator should introduce a reference to a const generic parameter at an index that is out of range for the substitution list being used during compilation.

Implementation steps: In the seed program, locate a const generic parameter with a default value. Let the const generic parameters be listed as `<const P0: T0, const P1: T1, ..., const Pk: Tk = DefaultExpr, ...>`. The operator modifies `DefaultExpr` to become `{ const { Pj } }` where `j` is chosen to be an index that is not present in the current substitution context. For example, if there are `k+1` parameters total, but the substitution list only has `m` elements (where `m <= k+1`), choose `j` such that `j >= m`. If the default is for parameter `Pk`, then referencing `Pk` itself creates a self-reference cycle. Alternatively, if there are multiple parameters, reference a different parameter `P0` but ensure that during substitution, the index for `P0` might be out of range due to the way defaults are processed. The new expression must be a const block containing only the identifier of the chosen const generic parameter.

Example: Original code: `struct S<const N: usize = 5>;`. Mutated code: `struct S<const N: usize = { const { N } }>;`. This introduces a self-reference. If the struct has multiple parameters: `struct S<const M: usize, const N: usize = M>;` is valid, but to trigger bugs, mutate to `struct S<const M: usize, const N: usize = { const { M } }>;` which is similar but uses a const block. The const block may cause different compiler behavior during evaluation.

Note: The mutation uses identifiers that already exist in the seed program. No new declarations are introduced. The operator is designed to exploit the compiler's handling of const generic default expressions, particularly during substitution where indices may be miscalculated, leading to "type parameter out of range" errors.
