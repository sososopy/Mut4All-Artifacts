mutation operator
Target code construct: trait definitions with associated types and trait bounds, particularly when those bounds involve other traits that may be missing or mismatched, leading to projection type mismatches during coherence checking.
Apply to any trait definition that includes an associated type with a trait bound. In the seed program, locate a trait definition with the form: trait TraitName { type AssocName: BoundTrait; }. The mutation operator modifies the bound trait within the associated type declaration. Specifically, it replaces the bound trait name with another trait name that exists in the current scope but is not the originally bound trait. If multiple traits are present, select one arbitrarily. If only one trait is present (the original bound), introduce a new trait with a simple declaration (e.g., trait NewTrait {} ) and use that as the new bound. The change is: within the trait definition, change the bound trait in the associated type declaration from its original name to a different trait name. For example, if the original code has trait Z { type Assoc: Y; } and trait X exists, mutate to trait Z { type Assoc: X; }. If trait Y does not exist and trait X is the only other trait, this mutation may already be present. To ensure applicability, if no other trait exists, declare a new trait with a trivial definition (e.g., trait Other {} ) before the trait definition being mutated, and then change the bound to Other. This creates a scenario where the associated type's bound differs from the actual type used in impls, potentially causing projection mismatch during specialization graph construction.
Example mutation: Original trait Z { type Assoc: Y; }. After mutation, if trait X is present, it becomes trait Z { type Assoc: X; }. If only trait Z and Y are defined, add trait Other {} at the top and then mutate to trait Z { type Assoc: Other; }. This change should be applied only to trait definitions that have associated types with trait bounds. The goal is to create incoherence between the bound and the actual associated type assignment in impl blocks, which can trigger internal compiler errors during trait solving, especially with the next-solver coherence mode.
