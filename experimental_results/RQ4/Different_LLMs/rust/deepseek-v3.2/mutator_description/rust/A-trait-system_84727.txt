mutation operator
Target: Trait implementations with transitive where clause dependencies.
Apply to: Any trait implementation block where the where clause references a trait bound that itself depends on the same trait being implemented, forming a potential cycle or recursive obligation.
Description: Identify a trait implementation block where the where clause contains a bound of the form Self: Trait<Other, Output>. In the seed program, locate such an implementation. Then, modify the where clause by swapping the order of type parameters in the referenced trait bound, or by replacing one of the type parameters with a different type parameter from the surrounding context that maintains the same arity but changes the implied obligations. Specifically, if the where clause is Self: Trait<A, B>, change it to Self: Trait<B, A> if A and B are distinct type parameters; if they are the same, introduce a new type parameter from the trait definition (if available) or duplicate an existing one to create a mismatch. Ensure that the new where clause is syntactically valid but alters the trait resolution path.
Example: Suppose a seed program contains impl<T, U> Trait<U> for Struct<T> where Struct<T>: Trait<T>. The mutation would change the where clause to Struct<T>: Trait<U>. This uses existing types T and U from the context. No new types are introduced; only the positions of existing type parameters are swapped.
Changes: Parse the implementation block, extract the where clause predicates. For each predicate that is a trait bound referencing Self and the same trait being implemented, identify the type arguments. If there are at least two distinct type arguments, swap the first two. If all arguments are identical, select another type parameter from the implementation's generic parameters (excluding Self) and replace one occurrence of the repeated argument with this different parameter, ensuring the number of type arguments remains the same. Update the where clause in the source code accordingly.
Rationale: This mutation directly targets complex trait selection logic where cyclic dependencies or changing obligation applicability can lead to internal compiler errors, as seen in the bug report where a where clause becomes inapplicable during confirmation.
