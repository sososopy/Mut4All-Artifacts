Mutation operator: InjectInlineAssembly
This operator targets functions and injects inline assembly code to create potentially problematic codegen scenarios, particularly focusing on the interaction between Rust code and inline assembly. 
It applies to functions that do not currently contain inline assembly.
The injected assembly code will be a simple addition operation using two registers, chosen to potentially clash with or alter the expected behavior of the surrounding Rust code.
For example, given a function like 
function example(a, b) { return a + b; }, 
the mutation might result in 
function example(a, b) { 
  asm("add rax, rdx" : : "a"(a), "d"(b) : "rax"); 
  return a + b; 
} 
This introduces a change that could trigger bugs related to inline assembly and its interaction with the Rust compiler's code generation, particularly under options like -Zmir-opt-level=0. 
When introducing new elements like the assembly code, they should be declared in a way that avoids ambiguity, such as using existing types and variables in the seed program to define the assembly operation's inputs and outputs.
