Mutation operator: ReplaceConstantEvaluationWithNonConstEvaluation

This mutation operator targets constant expressions and replaces them with non-const expressions. The goal is to test the compiler's ability to handle constant evaluation and non-const evaluation correctly.

Here's how it works:

1. Identify constant expressions in the code, such as constant functions, constant variables, or constant literals.
2. Replace the constant expression with a non-const expression that has the same type and semantics. For example, replace a constant function call with a non-const function call, or replace a constant variable with a non-const variable.
3. Ensure that the replacement expression is not constant-foldable, meaning that it cannot be evaluated at compile-time.

This mutation operator applies to any code that uses constant evaluation, including but not limited to:

* Constant functions and variables
* Constant literals and expressions
* Generic functions and types with constant parameters
* Const generics and trait bounds

The replacement expression should be declared in the same scope as the original constant expression, and should have the same type and semantics. The mutation operator should avoid introducing new types, variables, or functions that are not already present in the code.

For example, given the following code:
```rust
const FOO: i32 = 5;

fn main() {
    let x = FOO;
    println!("{}", x);
}
```
The mutation operator could replace the constant `FOO` with a non-const expression, such as:
```rust
let foo = 5;

fn main() {
    let x = foo;
    println!("{}", x);
}
```
This mutation operator is likely to expose bugs related to constant evaluation, such as incorrect handling of constant folding, incorrect optimization of constant expressions, or incorrect error reporting for non-const expressions used in constant contexts.
