Mutation Operator: Replace Const Functions with Non-Const Counterparts

This mutation operator targets constant functions and replaces them with non-constant counterparts to test the compiler's handling of constant evaluation and layout. 

It applies to code constructs that involve constant functions, such as const fn in Rust, which are used to define functions that can be evaluated at compile-time.

The operator works by replacing the const keyword in function definitions with an empty string, effectively making the function non-constant. 

For example, given a const function like const fn new() -> Self { ... }, the mutation operator would replace it with fn new() -> Self { ... } to test how the compiler handles the change from constant to non-constant evaluation.

This operator can help expose bugs related to constant evaluation, layout, and other areas where the compiler's behavior changes between constant and non-constant contexts, as indicated by the bug labels A-const-eval and A-layout in the provided bug report. 

By applying this mutation, the test can check if the compiler correctly handles the transition from constant to non-constant functions and if it properly evaluates and lays out the data in such cases. 

This approach prefers using existing functions and types within the seed program, minimizing the introduction of new elements and ensuring the mutation is widely adaptable across different program structures and features.
