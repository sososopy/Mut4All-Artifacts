Mutation Operator: Replace Const Generic Function With Non-Const Function

This mutation operator targets Rust code that uses const generic functions, specifically focusing on replacing a const function with a non-const function in a const context. The goal is to test the compiler's handling of const evaluation and valtree compatibility.

Given a struct or type that uses a const generic function, such as `struct X<const FN: fn() = { || {} }>`, this operator would replace the const function `FN` with a non-const function. For example, if a function `foo` is already defined in the scope, the mutation could replace `FN` with `foo`, assuming `foo` does not have the `const` keyword.

This change can help expose bugs related to const evaluation and valtree compatibility, as the compiler will attempt to evaluate a non-const function in a const context, which may trigger errors similar to the one described in the bug report, such as `'ty::Const::eval' called on a non-valtree-compatible type`.

To apply this mutation, first identify all const generic functions used in the struct or type definitions. Then, replace each const function with a non-const function that is defined in the same scope. If no suitable non-const function exists, a simple non-const function can be declared, for example, `fn bar() { }`, and used for the replacement.

The expected outcome is to trigger compiler errors or internal compiler errors (ICE) related to const evaluation, helping to test the compiler's robustness in handling const generics and valtree compatibility.
