Mutation Operator: Conditional Statement Negation
This mutation operator targets conditional statements in the code and negates their conditions. 
It applies to if statements and match statements with guard clauses. 
The goal is to test how the compiler handles different branching logic, especially in optimized MIR. 
To achieve this, the operator would identify conditional statements in the code, 
then negate the condition by adding a not keyword or negating the comparison operator. 
For example, if (a > b) would become if (!(a > b)) or if (a <= b). 
The operator should prefer using existing variables and functions in the seed program, 
and if new elements need to be introduced, they should be declared explicitly without ambiguity. 
By applying this mutation, we can test the compiler's ability to handle different code paths and optimize them correctly. 
The example given in the bug report with the question mark operator and Result type could be a good starting point to test this operator. 
The mutation could involve changing the condition in the if let or match statement to test different branches and ensure the compiler optimizes the MIR correctly in all cases.
