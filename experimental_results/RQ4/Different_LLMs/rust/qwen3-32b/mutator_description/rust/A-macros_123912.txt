Mutation operator: Macro argument type mismatch in path-based macros  
Applies to macros that expect a `path` argument but are invoked with non-path expressions. Targets macro_rules patterns where the first token is a `path` type but the actual argument contains a block `{...}` or inline expression.  

Example mutation:  
Original: `m!(SomeValidPath)`  
Mutated to: `m!({ ... })` (replace the path argument with an inline block containing arbitrary expressions, e.g., `{ let x = 1; x }`).  

This forces the compiler to resolve a non-path argument during macro expansion, exposing errors in path validation logic. The mutation uses existing expressions in the seed program for the inline block content, avoiding new declarations.
