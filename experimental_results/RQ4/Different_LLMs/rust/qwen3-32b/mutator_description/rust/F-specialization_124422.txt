Mutation Operator: Incomplete Default Impl Specialization  
Target code construct: A trait with an associated type and an impl block marked `default`  
Applies to: Trait implementations where the default impl is incomplete (missing associated type) and a specialization impl exists  

Mutation action:  
1. In a trait with an associated type `type Output;`, locate an impl block with the `default` keyword  
2. Remove the associated type implementation from the default impl block  
3. Add a second impl block for a specific type that specializes the associated type without `default` marker  

Example (pseudo-code):  
Original seed fragment:  
trait Assoc { type Output; }  
impl<T> Assoc for T { default type Output = (); }  
impl Assoc for u16 { type Output = u16; }  

Mutated version:  
trait Assoc { type Output; }  
impl<T> Assoc for T { default  // Missing associated type implementation  
}  
impl Assoc for u16 { type Output = u16; }  // No `default` marker on specialization  

This creates:  
- An incomplete default impl (missing `type Output` declaration)  
- A specialization that violates the requirement to specialize a `default` item  
- Potential type coherence errors when trait implementations reference each other  

The mutation leverages existing trait structures in the seed program and focuses on the interaction between incomplete default impls and specializations, which is the core issue in the reported ICE.
