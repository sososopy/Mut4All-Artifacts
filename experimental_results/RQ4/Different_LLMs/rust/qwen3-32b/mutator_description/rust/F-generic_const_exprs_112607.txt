Mutation Operator: ArrayDimensionMismatchInMatchPatterns
Applies to: Function parameters of type nested array (e.g., [[T; N]; M], [T; N], etc.) with generic const parameters
Transformation: Replace array dimensionality in parameter type with different nesting depth (e.g., [[T; N]; M] → [T; N], [T; N] → [[T; M]; K]) while preserving pattern dimensions in match arms. This creates mismatch between actual array structure and pattern syntax in match expressions.

Example:
Original:
pub fn f(arr: [[u8; N]; M]) { 
    match arr {
        [[]] => (), // 2D pattern
        _ => ()
    }
}

Mutated:
pub fn f(arr: [u8; N]) { 
    match arr {
        [[]] => (), // 2D pattern but arr is 1D type
        _ => ()
    }
}

Or:
pub fn f(arr: [u8; N]) { 
    match arr {
        [[_, _]] => (), // 2D pattern but arr is 1D type
        _ => ()
    }
}

Mutation ensures pattern syntax in match arms references array dimensionality that differs from the parameter's actual type. This exploits compiler's handling of generic const expressions in nested array types during pattern matching, often leading to ICE when type inference encounters mismatched type/const structures.
