Mutation operator: Replace a const parameter in a struct or trait impl with a user-defined type (e.g., a struct) where only primitive const types (u8, i32, bool, char) are valid. Apply this to existing structs and trait implementations that originally use primitive const types, ensuring the struct/impl already exists in the seed program.

Example mutation on code using generic const expressions:
Before:
pub struct Vector<T, const N: usize> {
    data: [T; N],
}

After:
pub struct Dimension;
pub struct Vector<T, const D: Dimension> {
    data: [T; D as usize],
}

Mutation operator: Add a trait implementation with multiple generic parameters, including a const parameter of the user-defined type, where the trait expects only one generic parameter. Use existing types/traits from the seed program.

Example mutation on code using Add trait:
Before:
impl<const N: usize, T> Add<Vector<T, N>> for Vector<T, N> {
    // implementation
}

After:
impl<const D: Dimension, LHS, RHS> Add<LHS, D> for Vector<LHS, D> {
    // implementation
}

Mutation operator: Introduce a const parameter with a user-defined type in a function signature where only primitive types are allowed, using existing function names and types from the seed program.

Example mutation on code with a generic function:
Before:
pub fn new<const N: usize>() -> Vector<T, N> { ... }

After:
pub fn new<const D: Dimension>() -> Vector<T, D> { ... }

These operators target the core issue in the bug report: the compiler's inability to handle non-primitive types in const parameters. They enforce type mismatches between const parameters (like using structs instead of usize/bool) and create situations where the compiler must relate incompatible const kinds during trait resolution, which triggers the ICE.
