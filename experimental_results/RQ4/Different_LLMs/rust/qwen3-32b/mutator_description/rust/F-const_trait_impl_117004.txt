Mutation Operator 1: ConstTraitBoundToNonConst  
Target construct: Trait implementations with `#[const_trait]` and their usage in generic bounds.  
Description: Modify an existing `const` trait bound in an `impl` block to use `~const` instead, ensuring the trait was originally implemented with `#[const_trait]`. This forces the compiler to process a non-const method or associated type in a context where it expects const correctness, potentially exposing ICEs during AST lowering.  

Example:  
Original code:  
```rust  
#[const_trait]  
pub trait Example {  
    fn method(&self);  
}  

impl<T: const Example> Struct<T> {  
    fn call_method(&self, value: T) {  
        value.method();  
    }  
}  
```  
Mutated code:  
```rust  
#[const_trait]  
pub trait Example {  
    fn method(&self);  
}  

impl<T: ~const Example> Struct<T> {  
    fn call_method(&self, value: T) {  
        value.method();  
    }  
}  
```  

This mutation operator applies to seed programs where a const trait is used in a generic parameter bound, and its methods or associated types are called in non-const contexts. It leverages existing types and traits in the seed program to maintain validity in other scenarios while stressing the compiler’s const trait handling.
