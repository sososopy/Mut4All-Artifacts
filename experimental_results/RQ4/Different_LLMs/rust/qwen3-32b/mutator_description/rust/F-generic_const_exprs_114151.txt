Mutation Operator: Introduce nested arithmetic const expressions in generic bounds with overlapping parameters  
Applies to generic functions with const parameters that are already used in array types or trait bounds. When a function accepts a generic const parameter and is used in a context where the const value appears in both a trait bound (e.g., [(); ...]:) and a direct array allocation, replace the existing const usage with a compound expression combining addition and subtraction of the same parameter.  

Example:  
Original code:  
fn bar<const M: usize>(_: [u8; M]) {}  

Mutated code:  
fn bar<const M: usize>(_: [u8; { M + 1 - M }]) {}  
impl<const M: usize> SomeTrait for SomeType where [(); (M - 1) + 1 + M]: { ... }  

This creates a scenario where the same const parameter appears in both the function argument's array size and a trait bound's size constraint, requiring overlapping const evaluations that may not be correctly handled by the compiler's evaluation machinery. The mutation ensures the arithmetic expressions are structurally similar to the ICE's failing pattern while reusing existing parameters from the seed program.
