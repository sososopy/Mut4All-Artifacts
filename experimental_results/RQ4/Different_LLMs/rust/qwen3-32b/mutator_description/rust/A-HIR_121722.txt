Mutation Operator: Nested Anonymous ADT with Duplicate Field
Applies to: Struct or union fields that already contain at least one named field
Action: Replace an existing field with an anonymous struct/union containing a field with the same name as another field in the parent type

Example mutation:
Original:
struct Example {
    a: u8,
    b: i32,
}

Mutated:
struct Example {
    a: u8,
    b: <anonymous struct> {
        a: u8,  // Duplicate field name
    },
}

Additional variations:
1. Add nested anonymous struct/union inside existing union field
2. Create multiple levels of nesting with identical field names
3. Use reference to parent field inside nested anonymous ADT
4. Combine with #[repr(C)] attribute for strict layout checking

The mutation creates ambiguity in field name resolution by:
- Creating shadowing between parent and nested anonymous ADTs
- Forcing compiler to traverse nested ADTs for uniqueness checks
- Using explicit field names that match parent scopes
- Mixing different ADT types (struct/union) in nested layers

This targets the compiler's handling of nested anonymous ADTs and field name resolution during type checking, which may expose bugs in the field uniqueness validation logic.
