Mutation Operator: ReplaceGenericParamWithAssociatedType
Applies to trait implementations with a generic type parameter where the trait has at least two implementations (one default). For any implementation of the form `impl<T> Trait<T> for U`, replace `T` with an associated type from a trait implemented by `T` in the seed program. The new implementation becomes `impl<T> Trait<<T as ExistingTrait>::Assoc> for U`, where `ExistingTrait` is a trait known to be implemented by `T` in the source code. This creates nested type normalization during coherence checks that may expose specialization handling bugs. Example: transform `impl<T> Format<T> for Printer` to `impl<T> Format<<T as Stream>::Element> for Printer` if `Stream` is a trait implemented by all `T` types in scope.

Mutation Operator: AddNegativeCoherenceConstraint
Applies to existing trait implementations with specialization. Introduce a negative coherence constraint by adding a `where` clause requiring a type to not implement a trait. For any implementation `impl<T> Trait<T> for U`, add `where T: !OtherTrait` to create overlapping impl conflicts. This stresses the compiler's coherence checking logic. Example: change `impl<T> Display<T> for Renderer` to `impl<T> Display<T> for Renderer where T: !Serializable`. The constraint must reference an existing trait `Serializable` already used in the seed program to avoid introducing new types.

Mutation Operator: NestedSpecializationImpl
Applies to programs with multiple trait specializations. Create a new implementation that combines two type parameters, one of which uses an associated type from an existing trait. For example, transform a simple `impl<T> Trait<T> for U` into `impl<T> Trait<<T as FirstTrait>::Assoc> for V<T>` where `FirstTrait` is a trait implemented by `T` in the program and `V<T>` is an existing generic type. This creates complex type relationships that may crash the specialization normalization. Requires that `FirstTrait` and `V<T>` already exist in the seed program.
