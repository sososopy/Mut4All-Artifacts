mutation operator: Recursive Template Instantiation Depth Increase

This mutation operator targets template instantiations that could lead to deep recursion during compilation. It applies to template class or function definitions that have at least one integer non-type template parameter. The operator increases the value of one integer non-type template parameter in a template instantiation to a larger constant, potentially triggering deeper recursive instantiation patterns that may expose recursion depth bugs in template handling, particularly in C++14 and later standards where constexpr and template rules are more complex.

The operator first identifies all template instantiations within the seed program. For each instantiation, it examines the template arguments. If an argument is an integer literal or a constant expression that can be evaluated at compile time (like a plain integer), the operator will replace it with a larger value. The new value is calculated by multiplying the original value by a fixed factor (e.g., 10) or adding a fixed increment (e.g., 100), ensuring it remains a valid integer constant expression. If the original value is zero, it is set to a small positive integer like 1 or 10 to initiate recursion. The change is made directly in the source code at the point of instantiation.

For example, if the seed program contains a template instantiation like `SomeTemplate<5>`, the operator might mutate it to `SomeTemplate<50>`. If the program uses a template with multiple parameters, such as `AnotherTemplate<3, void*>`, and the first parameter is an integer, it could become `AnotherTemplate<30, void*>`.

The operator must only use values that are syntactically valid and preserve the overall structure of the template arguments. It does not introduce new types or variables; it only modifies existing integer constants in template arguments. This mutation can lead to increased recursive template expansion, potentially exposing compiler crashes or infinite recursion bugs similar to the reported issue where deep template instantiation caused a parser failure.

Preference is given to modifying parameters in templates that are likely involved in recursive patterns, such as those found in template metaprogramming constructs (e.g., factorial calculations, type lists). The operator avoids ambiguous changes by strictly altering integer literals or compile-time constant expressions within template argument lists, ensuring the mutated code remains compilable in a correct compiler but may stress incorrect ones.
