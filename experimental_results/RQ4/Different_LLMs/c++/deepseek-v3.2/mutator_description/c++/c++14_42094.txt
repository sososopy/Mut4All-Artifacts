mutation operator: Variadic Template Lambda Capture in Return Type
Target: This mutation applies to lambda expressions defined inside function templates that have a return type specified via decltype referencing a captured variable. Specifically, it targets cases where the lambda is used within a variadic template expansion, such as in fold expressions or pack expansions.
Change: When a lambda inside a function template uses decltype of a captured variable (including parameters) as its return type, replace the captured variable reference in the decltype with a direct type expression that is equivalent. For example, if the lambda captures a function template parameter 'value' and uses decltype(value), replace decltype(value) with the type of 'value' as deduced from the function template parameter. If the type is a simple type like 'T', use T directly. If the type is more complex, attempt to reconstruct it using existing type aliases or template parameters from the enclosing context. The goal is to remove the dependency on the captured variable's declaration within the decltype while preserving semantics.
Example: In the bug report code, the lambda inside 'indirect' has return type decltype(value). After mutation, it becomes: return [](auto) -> T { return 1; }; where T is the template parameter of the enclosing function template 'indirect'. This changes the capture dependency but should be equivalent in type. Apply this mutation only when the lambda is defined within a function template and the decltype refers to a captured variable that is a parameter or local variable of that function template. Ensure the mutated lambda still compiles correctly in non-buggy compilers, but may trigger different instantiation paths in buggy compilers.
