mutation operator
This mutation operator targets binary comparison expressions where one operand is a call to a standard library function that returns a pointer or a size, and the other operand is an integer constant. The operator mutates the integer constant to zero, which can trigger division-by-zero assertions during constant expression evaluation when the compiler attempts to compute pointer differences or other arithmetic involving the result of the library function call. It applies to any binary operator (such as >, <, ==, !=, >=, <=) where the left or right operand is a call to a function like memcpy, memmove, memset, strlen, or similar, and the other operand is an integer literal. The mutation changes the integer literal to 0. If the integer literal is already 0, no mutation is applied. The operator prefers to use existing integer literals from the seed program; it does not introduce new variables or types.

For example, if the seed code contains:
memcpy(dest, src, n) > 5
The mutated code becomes:
memcpy(dest, src, n) > 0
Another example: if the seed code contains:
strlen(s) == 10
The mutated code becomes:
strlen(s) == 0
The mutation is applied only to integer literals that are directly used in the comparison with the library function call result; it does not affect other operands or expressions. This mutation can expose bugs in the compiler's constant evaluation logic when handling library functions in comparisons with zero.
