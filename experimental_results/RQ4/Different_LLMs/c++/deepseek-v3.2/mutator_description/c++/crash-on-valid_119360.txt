mutation operator: The mutation operator targets casts that involve variable-length array (VLA) types, particularly when those VLA types are used in contexts where the compiler must generate code for array-to-pointer decay or aggregate copying, such as within va_arg expressions. This applies to any cast expression where the destination type is a pointer type and the source expression is a va_arg call that retrieves a VLA type. The operator modifies the cast to explicitly decay the array to a pointer before the cast, or changes the cast to a reinterpret_cast when the source is a VLA retrieved via va_arg, to stress the compiler's handling of VLA representations in unusual contexts.

The operator applies when the seed program contains a va_arg call that retrieves an array type, and that result is used in a cast to a pointer type. The operator will alter the cast to use a compound expression that first decays the array to a pointer via the unary & operator applied to the first element, or changes the C-style cast to a reinterpret_cast, depending on which mutation is selected for a given instance. This aims to expose bugs in code generation for VLAs and va_arg where the compiler may incorrectly handle the size or type information.

To apply, for each occurrence of a cast where the source is a va_arg call with an array type (including VLA) and the destination is a pointer type, replace the cast with one of two mutations:
1. Replace (DestType)va_arg(args, ElementType[size]) with (DestType)&(va_arg(args, ElementType[size]))[0]
2. Replace (DestType)va_arg(args, ElementType[size]) with reinterpret_cast<DestType>(va_arg(args, ElementType[size]))

If the seed program does not have the necessary headers for reinterpret_cast, the first mutation is preferred. The operator uses existing variable names and types from the seed program; no new declarations are introduced. The mutation should only be applied if the array type in va_arg is a variable length array (size is not a constant expression) or if the size is a runtime value, to match the bug scenario.

Example: In the bug report code, the line (uint8_t*)va_arg(args, uint8_t[size]); would be mutated to (uint8_t*)&(va_arg(args, uint8_t[size]))[0] or reinterpret_cast<uint8_t*>(va_arg(args, uint8_t[size])). This change stresses the compiler's ability to handle the address-of operator on a VLA result from va_arg and the cast of that address.
