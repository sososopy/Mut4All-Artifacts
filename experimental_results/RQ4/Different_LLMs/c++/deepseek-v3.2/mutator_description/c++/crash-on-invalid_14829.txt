Mutation operator: Replace a comma operator call with a varargs operator call in a context that expects a non-varargs comma operator.

This mutation applies when a program uses the comma operator (operator,) in an expression, where the comma operator is defined as a non-varargs function (with specific parameter types). The mutation changes the comma operator declaration to use a varargs parameter (ellipsis ...) for one of its parameters, while keeping the operator as a friend or member function within a class. The mutation targets the definition of the operator, not its calls, but is only applied if the operator is actually used in the code.

Specifically, locate any class that declares a friend or member function operator, with a non-varargs parameter list. Change one of the parameters to a varargs parameter (...), ensuring the operator remains a friend if originally a friend, and remains private if originally private. The mutation should be applied to one parameter of the operator, typically the second parameter, while the first parameter remains a concrete type. The operator's return type remains unchanged. This mutation is only applied if the operator, is invoked somewhere in the program (e.g., in an expression like (obj, arg)).

For example, if the seed program contains:
class A {
  friend void operator,(A, int);
};
And there is a usage like (A(), 5);
Then mutate to:
class A {
  friend void operator,(A, ...);
};
The mutation introduces a varargs parameter where a specific type was previously expected. The varargs parameter must be valid C++ syntax; it does not introduce new types or variables beyond the ellipsis. The change is made directly in the class definition. Ensure the operator remains accessible (friend or public) as per original, and the mutation does not create ambiguous declarations (e.g., avoid duplicate operators). If the operator is overloaded, prefer mutating the version that is actually used.
