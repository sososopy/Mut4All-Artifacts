Based on the bug report, the compiler crashes while instantiating a function definition, specifically within a template context involving a namespace and a function named 'tail' with multiple integer template arguments. This indicates that bugs are more likely triggered during the instantiation of complex template functions, especially those within namespaces and involving multiple template parameters. The crash occurs during the parsing phase, suggesting issues with template argument deduction, substitution, or capture of variables within lambda or nested contexts during instantiation.

Mutation operator: Introduce a lambda expression within a template function body that captures a variable by reference, where the captured variable's type depends on a template parameter, and the lambda is invoked inside the function. This targets the instantiation of template functions, as seen in the bug where 'tuple::tail<2, int, int, int>' is being instantiated. The mutation applies to template function definitions within any namespace or class template.

To apply this mutation, locate a template function definition in the seed program. Within its body, before any return statement or at a point where statements are allowed, introduce a lambda expression. The lambda should capture a variable by reference. The variable to capture must be of a type that exists in the current scope; if no such variable exists, declare a new variable of a simple type like 'int' with a name such as 'captured_var' initialized to zero. The lambda should have an empty parameter list and return void, and it should be invoked immediately. The changes are: add a variable declaration if needed, then add the lambda definition and its invocation.

Example in pseudo-code: If the original template function is: template<typename T> void func(T param) { /* existing body */ }. After mutation: template<typename T> void func(T param) { int captured_var = 0; auto lambda = [&captured_var]() { }; lambda(); /* existing body */ }. This ensures the lambda captures a variable by reference, which may trigger issues during template instantiation similar to the crash in the bug report.
