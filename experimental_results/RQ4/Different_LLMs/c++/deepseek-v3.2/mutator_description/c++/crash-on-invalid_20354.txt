Mutation Operator: Duplicate Extern Declaration with Parameter Shadowing

Target: Function parameter declarations where the parameter name is reused in an extern declaration within the same function scope.

Description: In a function definition, identify any parameter. Inside the function body, insert an extern declaration using the same name as that parameter. This creates a redeclaration of the parameter as an external variable at block scope, which is invalid C++ because the extern declaration attempts to introduce a name that is already declared as a parameter in the same scope. The mutation should be applied only when the parameter name is a simple identifier (not a parameter pack or a function parameter with a default argument that itself contains a declaration). The inserted extern statement should use the same type as the parameter if the parameter type is a fundamental type or pointer; for more complex parameter types (like class types), the extern declaration should use a placeholder fundamental type (e.g., int) to avoid introducing undeclared types, but the name must match the parameter name exactly. No new types or variables beyond the extern declaration are introduced; the mutation reuses existing names.

Example: Given a seed function `void process(double value) { ... }`, the mutation would produce:
`void process(double value) { extern double value; ... }`
If the parameter type is a class `MyClass` not previously defined, the mutation would use a basic type to avoid adding undefined types: `void process(MyClass obj) { extern int obj; ... }`. The extern declaration is placed at the start of the function body. This mutation targets the specific code construct of a parameter name reused in an extern declaration, which can trigger compiler crashes during linkage computation as seen in the bug report.
