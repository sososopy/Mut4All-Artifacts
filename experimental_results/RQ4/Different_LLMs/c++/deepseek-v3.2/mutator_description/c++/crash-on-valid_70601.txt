mutation operator: Replace decltype expressions containing lambda invocations in template aliases with a direct call to the lambda's operator() in an unevaluated context, while preserving template arguments and concept constraints.

Target: This applies to template alias declarations (using alias = ...) where the initializer is a decltype expression that contains a lambda expression with a concept-constrained template parameter, and the lambda's operator() is invoked with explicit template arguments in an unevaluated context.

Procedure: For each template alias declaration of the form 'template <...> using Alias = decltype([]<Concept T> {}.template operator()<Args>());', where Concept is a concept name, T is a template parameter, and Args are template arguments, mutate it to 'template <...> using Alias = decltype([]<Concept T> requires Concept<T> {}.template operator()<Args>());'. If the lambda already has a requires-clause, append the constraint using '&&'. If the concept constraint is already expressed via a requires-clause, ensure the constraint is duplicated in both the template parameter and the requires-clause. This mutation specifically triggers additional constraint checking in unevaluated contexts.

Example: Given a seed with 'template <class> concept C = true; template <class> using U = decltype([]<C T> {}.template operator()<int>());', mutate to 'template <class> concept C = true; template <class> using U = decltype([]<C T> requires C<T> {}.template operator()<int>());'. This introduces a redundant requires-clause that may expose compiler crashes during constraint satisfaction evaluation in decltype.
