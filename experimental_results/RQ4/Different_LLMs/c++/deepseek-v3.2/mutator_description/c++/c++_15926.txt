mutation operator
Target Construct: Nested-name-specifiers used in pointers-to-members, specifically when the nested-name-specifier involves entering a context (like a class or namespace) for member access.
Application: This operator applies when a pointer-to-member declaration or expression uses a nested-name-specifier (e.g., ClassName::*). The mutation changes the nesting structure by altering the qualifier or introducing an additional level of qualification, focusing on contexts that might challenge the compiler's context entry logic during parsing or instantiation.
Changes: For a given pointer-to-member expression or declaration of the form 'A::*ptr', where 'A' is a class or namespace name, mutate it to 'B::A::*ptr' where 'B' is an existing enclosing namespace or class of 'A' from the seed program. If no such 'B' exists, mutate to 'A::C::*ptr' where 'C' is an existing nested class or namespace within 'A'. If neither case applies, no mutation is performed. Ensure that 'B' or 'C' are valid, pre-existing identifiers in the seed program to avoid undefined references.
Example: Original code has 'int MyClass::* mem_ptr;' and MyClass is defined within namespace N. Mutated code becomes 'int N::MyClass::* mem_ptr;'. Another example: Original code uses 'void (Base::*func)() const;' with Base having a derived class Derived. Mutate to 'void (Base::Derived::*func)() const;' only if Derived is an accessible nested class.
Rationale: This directly tests the compiler's handling of entering contexts for nested-name-specifiers in pointer-to-member constructs, which triggered the reported bug involving instantiation crashes in templates like STL algorithms. By altering qualification depth, it stresses context management during parsing and template instantiation, increasing coverage for frontend crashes.
