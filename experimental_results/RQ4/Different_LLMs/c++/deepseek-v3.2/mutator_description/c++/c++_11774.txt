Mutation operator:  
Introduce a spurious semicolon immediately after a namespace opening brace, within a nested namespace declaration sequence, without terminating the namespace prematurely. This targets compiler parsing of namespace definitions, particularly when multiple nested namespaces are declared across lines, as the bug report indicates a crash during parsing of nested namespaces.  

Where it applies:  
Apply to any namespace definition that is part of a chain of nested namespace declarations (e.g., namespace A { namespace B { namespace C {) where the opening braces are on separate lines or the same line. The mutation inserts an extra semicolon right after the opening brace of any namespace in the sequence, before any inner declarations.  

Changes to make:  
Locate a namespace opening brace that is followed by another namespace declaration or other content. Insert a semicolon token directly after that opening brace, ensuring the semicolon is placed before any subsequent tokens inside that namespace. Use only existing code structure; do not introduce new variables, types, or functions.  

Example in pseudo-code:  
Original seed code:  
namespace lsst {  
namespace meas {  
namespace multifit {  
  // some declarations  
}}  
}  
Mutated code:  
namespace lsst {;  
namespace meas {  
namespace multifit {  
  // some declarations  
}}  
}  
Here, a semicolon is inserted after the opening brace of namespace lsst. The mutation should similarly apply to any namespace in the chain, such as after namespace meas { or namespace multifit {, but only one mutation per operator application.
