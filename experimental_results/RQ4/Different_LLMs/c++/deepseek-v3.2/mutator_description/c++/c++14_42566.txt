mutation operator: Introduce a variable template partial specialization that depends on a SFINAE context inside a class template member function template, and trigger implicit instantiation via a nested class member of that type.

This mutation operator targets class templates that contain member function templates with SFINAE constraints using enable_if and variable templates. It applies when a class template has at least one member function template with a default template argument that uses enable_if<some_variable_template<T>>::type. The operator modifies the seed program by adding a variable template partial specialization that uses decltype on a function call that may be declared later (like foo). This creates a circular dependency during template argument deduction.

Specifically, locate a class template in the seed program. Within its public members, add a friend function declaration 'auto foo(ClassName obj);' where ClassName is the class template instantiation. Then, outside the class, add a variable template partial specialization: template<typename T> constexpr bool existing_variable_template<T, decltype(foo(T()))> = false;. Ensure existing_variable_template is already declared as a primary template (if not, declare it as template<typename T, typename = void> constexpr bool existing_variable_template = false;). Finally, create a struct that contains a member of the class template instantiated with a type that causes substitution into the member function template, triggering the SFINAE context.

Example steps for a seed program containing a class template 'Wrapper' with template parameter typename T: First, add a primary variable template if absent: template<typename T, typename = void> constexpr bool Var = false;. Inside the class template Wrapper, add a member function template: template<typename U, typename = typename enable_if<Var<U>>::type> explicit Wrapper(U);. Then add a friend function: friend auto foo(Wrapper w) { return 0; }. After the class, add a partial specialization: template<typename T> constexpr bool Var<T, decltype(foo(T()))> = false;. Finally, add a struct containing Wrapper<int> member. This constructs a scenario where instantiating the outer struct triggers implicit copy constructor generation, which performs overload resolution on the member function template, leading to substitution into Var partial specialization that depends on foo, which is defined in terms of Wrapper, causing a similar circular dependency as in the bug report.
