Mutation operator: Introduce invalid member access through comma operator in sizeof expression.

This mutation operator targets sizeof expressions that contain comma operators. It applies to any sizeof expression where the second operand of the comma operator is a struct or class type. The operator mutates the expression by introducing an additional comma operator that yields a non-struct type, then attempts member access on that result, creating an invalid construct similar to the bug report. Specifically, if the seed program contains a sizeof expression of the form sizeof(expr1, expr2) where expr2 is a struct/class type, we mutate it to sizeof(expr1, (expr2, expr3).member) where expr3 is a non-struct type (like an int) and member is a member name from expr2's type. The mutation uses existing elements: expr1 and expr2 come from the original expression; expr3 must be a variable or literal of a non-struct type (like int) that exists in the seed program; member must be a member name from the struct/class type of expr2. If no suitable non-struct variable exists, introduce a literal 0 of type int. The change is: replace sizeof(expr1, expr2) with sizeof(expr1, (expr2, expr3).member). This creates an invalid member access because the comma operator (expr2, expr3) yields expr3's type (non-struct), but the member access expects expr2's struct type. Example: Original code has struct S { int x; }; S s; int i; sizeof(0, s). Mutated to sizeof(0, (s, i).x). The comma operator (s, i) yields int type, but .x expects struct S, triggering a type error that may crash the compiler. This mutation targets compiler handling of invalid member access in sizeof contexts, which caused the crash in the bug report.
