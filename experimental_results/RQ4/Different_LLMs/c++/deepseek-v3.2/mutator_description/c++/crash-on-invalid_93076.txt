Mutation Operator: Introduce mismatched template arguments in a call to a function template with a parameter pack.

This mutation targets calls to function templates that use parameter packs (template <class... T>). It applies when the seed program contains at least one function template declaration with a parameter pack and a call to that template (or a similar template). The mutation alters the explicit template arguments provided in the call to create a mismatch with the actual function arguments.

The operator works as follows:
1. Identify a call expression that invokes a function template with a parameter pack, e.g., `func<Args...>(args...)`.
2. Change the number or types of explicit template arguments so they do not align with the number or types of the function arguments. For example, if the template expects a pack `a...` and the call provides arguments `(x, y)`, mutate the template arguments to be `func<T1, T2, T3>(x, y)` (adding an extra template argument) or `func<T1>(x, y)` (providing fewer template arguments). Alternatively, change the types to incompatible ones, like replacing `int` with a type not present in the arguments.
3. Use existing types and names from the seed program. If new types are needed, introduce them by using a fundamental type (e.g., `float`, `char`) or a type alias already defined in the program. Avoid introducing undeclared types.
4. Ensure the mutation does not create syntactically invalid code (like missing parentheses). The call should remain a valid expression but with a mismatched template argument list.
