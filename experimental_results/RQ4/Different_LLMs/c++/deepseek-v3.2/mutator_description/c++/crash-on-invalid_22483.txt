Mutation Operator: Replace lambda capture with invalid template argument type in sizeof context.

Target code construct: This mutation applies to lambda expressions used as arguments to template functions where the function body contains a sizeof operation on the template parameter.

Procedure: Identify a lambda expression passed to a template function. Replace the lambda capture with a type that is an incomplete or invalid template argument for a class template used within the lambda's context, such that taking sizeof on the template parameter leads to an ill-formed lambda type. Specifically, modify the lambda capture to capture an instance of a class template specialization where the template argument is a type that causes the class template instantiation to be invalid or incomplete, but the capture itself is syntactically valid. For example, if the seed contains `template <class T> class A;` (forward declaration), capture an `A<int>` object. Ensure the template class `A` is only forward-declared, not fully defined, making `A<int>` an incomplete type. Then, pass this lambda to a template function `F` that performs `sizeof` on its parameter `x`. The lambda's type becomes ill-formed because its closure type involves the incomplete `A<int>`, triggering layout computation during sizeof.

No new variables or types are introduced; use existing `A` and `B`. The mutation changes the lambda capture to `[a]() {}` where `a` is an `A<int>` object declared within `B`. Ensure `B` is defined with `A<int> a;` and `A` is only forward-declared. Then call `F([a]())`. This replicates the bug scenario where sizeof on the lambda parameter attempts to compute layout for an invalid decl.
