mutation operator

Target: This mutation operator applies to template functions or class member functions that contain at least one parameter pack. It introduces a lambda expression inside the function body that captures variables by reference and contains a fold expression over a comma operator. The lambda itself takes an auto-deduced parameter pack, and within the fold expression, another immediate lambda is introduced that references both the outer lambda's parameter pack and the original function's parameter pack.

Where it applies: In the body of a function template that has a template parameter pack (e.g., typename... Ts) and a corresponding function parameter pack (e.g., Ts... args). The function body must already exist; the mutation will insert new code into an existing compound statement (i.e., within curly braces {}). If the function body is empty, the mutation will create a compound statement to house the new lambda.

Changes: Within the function body, insert the following statement: (void)[&](auto... inner_pack) { ([&] { outer_pack; inner_pack; }, ...); };. Here, outer_pack must be replaced with the name of the function's parameter pack that is being captured. If the function has multiple parameter packs, select the first one. The inner_pack is a new name introduced for the lambda's parameter pack; it should be a unique identifier not already used in the function's scope (e.g., generate a name like __mut_pack). The statement is an expression statement that creates and immediately discards the lambda (via (void) cast) to avoid unused variable warnings. The mutation ensures that both outer_pack and inner_pack are used inside the innermost lambda to force their substitution and potential interaction.

Example pseudocode: Original function: template<typename... T> void func(T... params) { existing_body; }. After mutation: template<typename... T> void func(T... params) { existing_body; (void)[&](auto... __mut_pack) { ([&] { params; __mut_pack; }, ...); }; }. If the original function body is a single expression or empty, wrap it in braces if needed to form a compound statement before insertion.

Rationale: This directly mimics the structure that triggered the compiler crash: nested parameter packs (the outer function's pack and the inner lambda's auto pack) combined with a fold expression containing an immediate lambda that references both packs. Such complex nesting stresses the compiler's template instantiation and parameter pack expansion logic, potentially revealing assertion failures or crashes similar to the reported bug.
