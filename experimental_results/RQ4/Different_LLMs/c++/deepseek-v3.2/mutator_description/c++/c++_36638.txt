mutation operator
target code construct: variadic lambda expressions with trailing return types that depend recursively on the lambda's own type or capture context. this applies to lambda expressions defined with a trailing return type that uses decltype or other type deduction involving the lambda's captures or parameters, especially when the lambda is variadic and the return type references the lambda itself indirectly through template instantiation or type traits.

description: replace the trailing return type of a variadic lambda with a recursive type expression that references the lambda's own type via decltype on a call to itself or via type traits that inspect the lambda's signature. the mutation introduces a new trailing return type that forms a self-referential dependency, which may stress the compiler's ability to handle recursive type deduction during template instantiation.

changes: for each variadic lambda expression in the seed program that has a trailing return type (or could have one added), modify the trailing return type to be decltype(std::declval<decltype(*this)>()(std::declval<args>()...)), where args are the lambda's parameter types. if the lambda already has a trailing return type, replace it with this expression. ensure that any necessary includes for std::declval are present; if not, add #include <utility>. use the existing lambda parameters and captures; do not introduce new variables or types beyond the recursive reference.

example: given a seed lambda like [](auto&&... args) -> some_type { return expr; }, mutate it to [](auto&&... args) -> decltype(std::declval<decltype(*this)>()(std::forward<decltype(args)>(args)...)) { return expr; }. if the lambda is non-variadic, adapt the parameter pack accordingly. if the lambda has no trailing return type, add one. this mutation should be applied only when the lambda is defined within a context where such self-reference is syntactically allowed (e.g., not in an unevaluated context that prohibits lambda expressions).
