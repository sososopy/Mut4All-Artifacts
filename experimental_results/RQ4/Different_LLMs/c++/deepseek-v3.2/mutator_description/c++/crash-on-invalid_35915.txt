mutation operator Introduce Recursive Template Instantiation via Type-Dependent sizeof Expression within Lambda Body.
This mutation targets code constructs where a lambda expression is used inside a template class or function, and within the lambda body, a sizeof operator is applied to a type that depends on template parameters, potentially causing infinite recursion during template instantiation. It applies when a lambda is defined inside a template context and the lambda body contains a sizeof expression whose operand is a type that is itself dependent on template arguments, such as a nested template class or a type derived from template parameters. The mutation modifies the lambda body to include a sizeof expression that references a template-dependent type. For example, if the seed program contains a template class T with a member type U, the lambda body is changed from possibly empty or simple statements to include sizeof(T::U) or sizeof(decltype(t)) where t is a parameter of the lambda that depends on the template. The changes are made by inserting a sizeof expression into the lambda body. If the lambda already has a body, the sizeof expression is added as an additional statement; if the lambda body is empty, it is replaced with a compound statement containing the sizeof expression. The sizeof expression should use a type that is already present in the seed program, such as a template parameter type or a nested type within the template. If no such type exists, a new nested type can be introduced by adding a dummy struct inside the template class, for example, adding struct Dummy {}; inside the template, and then using sizeof(Dummy) in the lambda. This ensures the type is defined within the template and is dependent. The mutation aims to trigger deep recursion in the compiler's type evaluation logic, similar to the crash in getTypeInfoImpl observed in the bug report.
