Mutation Operator: UCN to Raw Character Mutation

Applies to: Universal character names (UCNs) within identifiers in user-written source code. This includes UCNs in variable names, function names, type names, and other identifiers. It does not apply to UCNs in string literals or character literals.

Description: Replace a universal character name (e.g., \uXXXX or \UXXXXXXXX) with the raw, unescaped Unicode character it represents, if that character is permitted in the source character set for identifiers according to the C++ standard. The mutation changes the lexical representation of the identifier while aiming to preserve its semantic meaning. This operator targets compiler logic for identifier lexing and processing of extended characters.

Implementation Steps:
1. Identify all universal character names (UCNs) in identifiers within the seed program.
2. For each UCN sequence (\uXXXX or \UXXXXXXXX), decode it to its corresponding Unicode code point.
3. Check if this code point is allowed in an identifier per the standard's grammar (e.g., it must be a Unicode letter or digit, or certain other connecting punctuation characters like underscore, and not a basic source character already).
4. If allowed, replace the UCN escape sequence directly with the UTF-8 encoded sequence (or other appropriate source encoding used) for that character. Ensure the replacement maintains the same logical identifier.
5. If the UCN represents a character not allowed in identifiers, skip mutation for that instance.

Example:
Seed code snippet: `int var_\u0041;` (where \u0041 is 'A')
Mutated code: `int var_A;`

Note: This mutation assumes the source file encoding supports the direct insertion of the character. Preference is given to this direct replacement. If a new encoding declaration is needed (e.g., `#pragma encoding` or similar), it should be added pragmatically only if the seed program does not already specify an encoding, and the added declaration should be a standard or widely supported form for the compiler under test. The use of existing identifiers from the seed is maintained; no new variables or types are introduced.
