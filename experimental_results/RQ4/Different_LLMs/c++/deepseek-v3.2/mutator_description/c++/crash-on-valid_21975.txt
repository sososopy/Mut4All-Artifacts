mutation operator: Insert a new lambda expression capture default that conflicts with explicit captures in existing lambda expressions within the same scope. This operator applies to C++ lambda expressions that have explicit captures. The mutation adds a capture-default (= or &) to the lambda's capture list when the lambda already contains one or more explicit captures, potentially creating a capture conflict that may trigger compiler crashes during capture analysis or code generation. The mutation uses only variable names already present in the enclosing scope of the lambda. If no variables exist in the scope, the mutation is not applied. Change: Locate a lambda expression with an explicit capture list (e.g., [var] or [&var]). Insert a capture-default before the explicit captures, producing [=, var] or [&, var]. If the lambda already has a capture-default, this mutation does not apply. Example: Original code: auto func = [x](){ return x; }; Mutated code: auto func = [=, x](){ return x; }; This introduces a potential redundancy or conflict as x is already captured explicitly, possibly exposing compiler bugs in capture resolution.
