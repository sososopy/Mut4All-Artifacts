Mutation Operator: Default Lambda Argument in Generic Lambda Duplication and Parameter Type Mutation

This mutation operator targets generic lambda expressions that contain default arguments. It applies when a seed program includes a lambda declared with auto parameters and at least one default argument provided for any parameter. The operator performs two modifications: first, it duplicates the lambda definition within the same scope, creating a second lambda with identical signature and body. Second, it mutates the parameter type specification in the original lambda by adding a const qualifier to the auto parameter that has the default argument. If multiple parameters have default arguments, the first one is chosen. The goal is to stress the compiler's handling of default argument instantiation and mangling for generic lambdas, which can lead to crashes or deadlocks as seen in the bug report.

The operator uses only elements present in the seed program. It does not introduce new data names, types, or variable names. The changes are made directly to the existing lambda definition and its duplicate.

Example in pseudo-code:

Original code in seed program:
auto func = [](auto param1, auto param2 = default_value) { /* body */ };

After mutation:
auto func = [](const auto param1, auto param2 = default_value) { /* body */ };
auto func_dup = [](auto param1, auto param2 = default_value) { /* body */ };

Changes made:
1. In the original lambda definition, the parameter type for 'param1' (the first parameter) is changed from 'auto' to 'const auto'. This targets the parameter that precedes the one with the default argument (param2), ensuring the default argument's context is affected.
2. A duplicate lambda definition is added immediately after, with the same signature and body as the original pre-mutation lambda. The duplicate uses a distinct variable name (func_dup) to avoid redeclaration conflicts; this name is generated by appending "_dup" to the original variable name. If such a name already exists, a numeric suffix is added (e.g., func_dup_2).
3. The default argument 'default_value' remains unchanged and must be a valid expression in the seed program. No new variables or types are introduced.

This operator increases coverage by creating multiple generic lambda instantiations with subtle type variations, potentially exposing compiler bugs in template argument deduction, const correctness, or internal symbol generation for default arguments.
