mutation operator: Change the type of a reference member in a class or struct to a reference to an array with a different bound than its initializer, within a constructor initializer list. This mutation applies when a class or struct has a reference member that is a reference to an array, and that member is initialized in the constructor's initializer list with an expression that yields an array type. The mutation modifies the reference member's array bound to a different value than the array bound of the initializer expression. Specifically, if the reference member is declared as `T (&var)[N]`, where N is a constant integer, and the initializer expression has type `T [M]` (or yields a pointer to such an array after conversions), change N to a value not equal to M, using another constant integer available in the seed program. If no other suitable constant integer exists in the seed program, introduce a new constant integer via a local constexpr variable inside the constructor body or as a static member, but preference is to use existing constants. The mutation must ensure the reference type remains syntactically valid; the change is solely in the array bound of the reference. Example: In the seed program, a struct has `int (&data)[2];` and constructor `array() : data(*new int[1][2]) {}`. The initializer `*new int[1][2]` yields an `int[2]` array type (since dereferencing a pointer to array of 2 ints gives an array of 2 ints). The mutation could change the member to `int (&data)[3];` if constant 3 is available, or to `int (&data)[1];` if constant 1 is available, creating a mismatch. The mutated code becomes: struct array { int (&data)[3]; array() : data(*new int[1][2]) { } }; This mismatch in array bounds during reference binding in the initializer list may trigger compiler crashes in constant evaluation or type checking phases.
