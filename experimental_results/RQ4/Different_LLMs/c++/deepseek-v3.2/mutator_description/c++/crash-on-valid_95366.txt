Mutation Operator: This mutation operator targets the use of GNU address-of-label extension within an expression. It mutates expressions that take the address of a label (using the && operator) by replacing them with a different expression that involves a pointer to a function or a pointer to void. The operator applies when the seed program contains a label address expression (e.g., &&label) used in an arithmetic or relational operation. The mutation replaces the label address expression with a function pointer or a void pointer from existing declarations in the seed program. If no such pointer exists, it introduces a new variable of type void* and assigns it a null pointer constant (e.g., ((void*)0)) to avoid undefined behavior. Specifically, for each occurrence of &&label in an expression, the mutation substitutes it with a pointer expression. For example, if the seed program has a function named func, then &&label can be replaced with &func (taking the address of the function). If no function is present, a new variable is added at the beginning of the function scope: void* ptr = ((void*)0); and then &&label is replaced with ptr. The goal is to create complex pointer arithmetic or comparisons that may trigger compiler assertion failures during constant evaluation, similar to the bug report where an LValue assertion failed. Example mutation: Original code: x() { &&e - &&b < x; } Mutated code: x() { void* ptr = ((void*)0); (ptr - ptr) < x; } Here, &&e and &&b are replaced with ptr, resulting in pointer arithmetic on void pointers, which is a GNU extension and may expose bugs in constant expression handling. Another example if a function exists: Original code: void foo() {} int main() { return &&lbl - &&lbl2; } Mutated code: void foo() {} int main() { return &foo - &foo; } This changes the expression type and may affect compiler's constant evaluation logic. The mutation should only apply to expressions containing &&label, and the replacement pointer must be of a type that allows pointer arithmetic (e.g., void* or function pointer) to mimic the original GNU extension behavior. This operator aims to test the compiler's ability to handle non-standard pointer operations during constant evaluation, potentially revealing crashes in the AST or constant expression modules.
