mutation operator: Replace function call with assignment to a variable of mismatched type, specifically when the function returns void but the call site expects a non-void type and assigns the result.

This operator targets call expressions where a void-returning function is called and its result is used in a context expecting a non-void type, such as an assignment, initialization, or as an operand to another operator. It applies to any function call expression `func(args)` where the function `func` is known to return void (or is later mutated to return void) but the surrounding context expects a value. The mutation changes the call to be used in an assignment or initialization that declares a new variable of a non-void type, or it changes an existing variable assignment to use the void-returning call incorrectly. For seed programs, if a void-returning function exists, locate a call to it (or mutate a non-void function to return void first, but that is a separate operator). Then, introduce an assignment where the left-hand side is a variable of a type available in the current scope (e.g., int, float, or a user-defined type from the seed). If no suitable type exists, use a basic type like int. The mutation should not introduce undeclared identifiers; if a variable of the chosen type does not exist, declare a new variable with that type in the same scope as the call. The change is to replace a statement containing the void function call with a declaration or assignment that misuses the void return.

Example in pseudo-code: Original code has a void function `void foo(int x);` and a call `foo(5);`. Mutated code could be `int unused = foo(5);` or if an int variable `result` exists, `result = foo(5);`. This mimics the bug-triggering pattern where a void function is called in a value context, potentially causing compiler confusion about cleanups or type checking, especially with templates or forwarding references.

Implementation steps: 1. Identify a function call expression where the called function returns void. 2. Determine the enclosing statement (e.g., an expression statement). 3. Replace that statement with an assignment or initialization statement that assigns the void function call to a variable of a non-void type. 4. Ensure the variable type is valid in the current scope; if not, declare a new variable of a basic type (e.g., int) at the start of the block. 5. If the function call is already part of an assignment, modify the assignment to use a mismatched type on the left-hand side.

Note: This mutation may produce invalid code that should be rejected by a correct compiler, but it can expose bugs in error handling or cleanup logic, as seen in the bug report where an unused parameter warning combined with fatal errors leads to an assertion about unaccounted cleanups.
