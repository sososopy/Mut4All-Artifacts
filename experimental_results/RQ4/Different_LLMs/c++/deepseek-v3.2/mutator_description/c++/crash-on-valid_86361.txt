mutation operator: Expand Nested Lambda Parameter Pack Capture by Adding Redundant Template Parameter Pack Expansion

This mutation operator targets lambda expressions that capture parameter packs from enclosing templates, specifically when those lambdas are nested and involve multiple parameter packs. It applies when a lambda inside a template function or method captures a template parameter pack (e.g., via `[&]` or `[=]`) and this lambda contains another inner lambda that also uses parameter packs, such as in fold expressions or nested captures. The operator modifies the inner lambda's capture clause to include an explicit expansion of the outer lambda's captured parameter pack, even if this expansion is redundant or syntactically unusual, potentially stressing the compiler's handling of nested pack expansions in lambda contexts.

The mutation changes an inner lambda capture from a simple capture (like `[&]`) to an explicit pack expansion capture of the outer lambda's captured pack. This is done by using a pack expansion inside the capture list, referencing the outer pack. Since the outer pack is already captured implicitly by reference in the outer lambda, this adds a layer of explicit expansion that may expose compiler bugs in pack deduction or lambda instantiation.

Where it applies: In a template function with a parameter pack `Ts... ts`, if there exists an inner lambda that captures `ts` (implicitly via `[&]` or `[=]`) and contains another lambda inside it (which could be in a fold expression or other nested context), mutate the innermost lambda's capture clause to include an explicit expansion of `ts`. Specifically, replace the capture clause of the innermost lambda with a pack expansion that captures each element of `ts`, even if `ts` is already captured by the outer lambda. This should be applied only when `ts` is a parameter pack in scope and the innermost lambda is syntactically allowed to capture it (though it may lead to redundant or complex expansions).
