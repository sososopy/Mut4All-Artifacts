Mutation operator: Replace a variadic function declaration with a non-variadic one, or vice versa, specifically targeting friend function declarations within class definitions that involve overloaded operators.

This mutation applies when a class contains a friend declaration of an overloaded operator, particularly the comma operator, with a variadic parameter list (ellipsis ...). It changes the variadic parameter list to a fixed parameter list, or introduces a variadic version where a fixed list exists, focusing on operators that can be used in contexts like static assertions or complex expressions.

For example, in a seed program where a class declares a friend operator with variadic parameters, mutate it to a non-variadic version. Conversely, if a non-variadic operator friend exists, add a variadic overload. The mutation must use existing class names, operator types, and parameter types from the seed program. If introducing a new declaration, ensure it is declared as a private or public friend within the same class, matching the existing structure.

Illustration: Original code snippet might have:
class SomeClass {
  friend void operator,(SomeClass, ...);
};
Mutated to:
class SomeClass {
  friend void operator,(SomeClass, void*);
};
Or vice versa, depending on the original. The change is made directly in the class definition, preserving other elements. This targets compiler bugs related to variadic operator parsing and overload resolution, especially in edge cases like static initializers or template contexts.
