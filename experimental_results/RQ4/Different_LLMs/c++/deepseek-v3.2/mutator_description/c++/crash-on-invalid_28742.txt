Based on the bug report involving a crash during variadic template instantiation with specific token parsing errors, the mutation operator targets template instantiation patterns that may trigger similar assertion failures in diagnostic highlighting logic.

Mutation Operator: Variadic Template Instantiation Argument Count Mutation

This mutation applies to variadic template class or function instantiations within the seed program. It modifies the number of arguments passed during instantiation, specifically by altering the argument count to create scenarios where template parameter packing may produce edge cases in diagnostic rendering.

Where it applies: Any line containing a variadic template instantiation (e.g., `TemplateName<Arg1, Arg2, ..., ArgN>`) where N ≥ 2. Focus on instantiations that already exist in the seed, using existing template names and argument types.

Changes: For a variadic template instantiation with K arguments, mutate to either:
1. Increase argument count by duplicating the last existing argument type once, producing K+1 arguments.
2. Decrease argument count by removing the last argument if K>2, producing K-1 arguments.

Preference: Use only existing types from the seed. If duplication is needed, reuse the same type identifier already present in the program. Do not introduce new types.

Example (pseudo-code):
Original: `SomeTemplate<int, double, char> instance;`
Mutated (increase): `SomeTemplate<int, double, char, char> instance;`
Mutated (decrease): `SomeTemplate<int, double> instance;`

Rationale: This alters template argument packing boundaries, potentially creating whitespace or token highlighting edge cases in diagnostic output that could trigger assertions like the one reported. It maintains validity by using existing types, ensuring compilable seeds while testing parser token tracking across varying argument counts.
