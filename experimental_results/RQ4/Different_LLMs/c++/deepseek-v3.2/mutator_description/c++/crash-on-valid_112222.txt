mutation operator: Add a redundant nested name specifier to the definition of a member function with a trailing requires clause. This mutation applies when a class template has a member function declared with a trailing requires clause inside the class, and a corresponding out-of-class definition is provided. The mutation modifies the out-of-class definition by inserting the class name as a nested name specifier between the return type and the function name, which should be redundant but may trigger parsing issues. The change uses only existing class and function names from the seed program.

Specifically, locate an out-of-class definition of a member function that includes a trailing requires clause. The definition typically has the form: 'void ClassName<TemplateArgs>::FunctionName() const requires (condition) {}'. Mutate it to: 'void ClassName<TemplateArgs>::ClassName::FunctionName() const requires (condition) {}'. This inserts 'ClassName::' after the '::' that already follows the class name, creating a nested specifier. Ensure the class name matches the one already present in the definition.

Example based on the bug report: Original out-of-class definition: 'void TExprBase<T<dim, rank>>::Curl() const requires (dim == 3u && rank == 1u) {}'. Mutated version: 'void TExprBase<T<dim, rank>>::TExprBase::Curl() const requires (dim == 3u && rank == 1u) {}'. The mutation adds 'TExprBase::' after the existing '::', making it 'TExprBase<T<dim, rank>>::TExprBase::Curl'. This uses the class template name 'TExprBase' already declared in the program. The mutation should be applied exactly once per eligible function definition, targeting the first such definition found in the code.
