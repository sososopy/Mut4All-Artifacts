Mutation Operator: Dependent Function Call in Non-Type Template Argument

This mutation operator targets template argument deduction for non-type template parameters, specifically when a dependent expression involving a function object is used as an argument to a template parameter declared with `auto`. The issue arises when the template argument depends on a member of a template parameter, and the expression's type classification or deduction fails.

Target: This applies to any template struct or class that has a non-type template parameter declared with `auto`, where the template argument is an expression that is dependent on a template parameter and involves a function call or function object.

Mutation: For each template with a non-type `auto` parameter, if the argument is a simple identifier or constant, replace it with a dependent function call expression that uses a function object (like a lambda or functor) and depends on a member of a template parameter. Specifically, introduce a new template type parameter `T` and use an expression like `f(T::member)`, where `f` is a function object available in the scope, and `member` is a static data member or type that `T` provides. If no suitable function object exists, declare a trivial lambda or functor locally (e.g., `auto f = [](int){};`) and use it. Ensure the expression is syntactically correct and depends on `T`.

Example: Given a seed program with:
template<auto X>
struct S {};

Mutate to:
struct Functor {
    void operator()(int);
} f;
template<typename T>
using Alias = S<f(T::value)>;

Here, `Functor` and `f` are introduced if not present, and `T::value` assumes `T` has a static member `value`. Use existing types and members from the seed where possible; if `T` is new, declare it as a placeholder struct with a static member (e.g., `struct T { static int value; };`). The mutation should be applied in a context where template instantiation is attempted, such as in an alias declaration or variable template.
