Based on the analysis of the bug report, C++ compiler bugs are more likely to be triggered by complex template structures, especially involving nested classes, template specializations, and template function instantiations within specialized class templates. The crash occurs during the instantiation of a template member function inside a nested class of a fully specialized template class, where the template argument is integral and used in a dependent context (like a std::array size). This suggests that mutations should focus on intricate template hierarchies and the substitution of non-type template arguments in dependent scopes.

mutation operator
This operator introduces a non-type template parameter into a member function of a nested class within a template class specialization. It targets code where a class template is fully specialized, and that specialization contains a nested class (or struct). The mutation adds a new template member function to this nested class, where the function's return type or a parameter depends on its non-type template parameter in a way that creates a dependent type context, such as using it as a template argument to another template (e.g., std::array). The goal is to stress the compiler's handling of template argument substitution in nested, specialized contexts.

Applicability: This applies when the seed program contains a template class (e.g., template<typename T> struct X) that is explicitly specialized for at least one type (e.g., template<> struct X<int>), and within that specialization, there is a nested class or struct definition (which could be empty or have existing members). If the nested class does not exist in the specialization, it is not mutated.

Mutation Procedure: First, identify all explicit specializations of class templates in the seed program. For each such specialization that contains a nested class definition (e.g., struct Inner), modify this nested class by adding a new public member function template. This function template should have a single non-type template parameter of integer type (int). The function should have a return type that is a template instantiation where the non-type parameter is used as an argument, such as std::array<int, N> (if std::array is already in scope via includes; otherwise, use another template from the seed, like std::integral_constant<int, N>). The function body should return a default-constructed value of that return type. If std::array or similar is not available, introduce a simple template like template<int I> struct dummy_array { }; in a new namespace to avoid conflicts, but only if no existing suitable template exists. Prefer using templates already present. The function is declared as public and within the nested class. Finally, add a call to this new function with a constant integer argument (e.g., 42) in an existing function (like main) or a new global function if needed, ensuring all identifiers are in scope.

Example: Given a seed with template<typename T> struct Outer { struct Nested; }; and template<> struct Outer<int>::Nested { };, after mutation, it becomes: template<> struct Outer<int>::Nested { public: template<int N> auto new_func() -> std::array<int, N> { return std::array<int, N>{}; } };. And a call Outer<int>::Nested{}.new_func<42>(); is added to an existing function.
