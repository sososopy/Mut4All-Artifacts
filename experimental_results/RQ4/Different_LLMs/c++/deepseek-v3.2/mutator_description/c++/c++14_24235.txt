Mutation Operator: Replace constexpr variable declaration with a forced compile-time evaluation attempt in a context that requires a constant expression but may trigger internal compiler evaluation logic.

Applies to: Any constexpr variable declaration within a valid C++14 program.

Change: For a constexpr variable declaration of the form:
constexpr type name = initializer;
Replace it with:
constexpr type name = initializer; static_assert(name == initializer, "");
The static_assert attempts to force the compiler to evaluate 'name' in a constant expression context. If the initializer is complex, this can stress the compiler's constexpr evaluation machinery, potentially exposing crashes like the one in the bug report where evaluateValue() is called internally.

Example Seed Code:
constexpr int size = 100;
Mutated Code:
constexpr int size = 100; static_assert(size == 100, "");
This uses only existing elements (the variable 'size' and its value). No new types or variables are introduced beyond the static_assert string literal, which is standard. The change is minimal and targets the constexpr evaluation pathway directly.
