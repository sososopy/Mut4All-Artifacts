Mutation Operator: Introduce Transparent Union Attribute on Existing Union Type

This mutation operator targets union type declarations in C++ programs. It applies when the seed program contains at least one union type definition that does not already have the `transparent_union` attribute. The operator modifies the union declaration by adding the GCC/Clang-specific `__attribute__ ((__transparent_union__))` to it.

The change is made by taking an existing union type definition from the seed program and appending the attribute specifier to its declarator. No new types, variables, or functions are introduced; only an existing declaration is altered. The operator selects a union definition that is at file or namespace scope, not within a class or function, to maximize the chance of triggering compiler internal logic related to attribute processing and layout computation.

For example, if the seed program contains:
union MyUnion {
    int x;
    float y;
};

The mutated version becomes:
union MyUnion {
    int x;
    float y;
} __attribute__ ((__transparent_union__));

The operator ensures the attribute is inserted correctly after the union body and before any variable declarator or semicolon. If the union is part of a typedef, such as `typedef union { ... } Alias;`, the attribute is placed after the alias name, as in the bug report example: `typedef union{union b u;} A __attribute__ ((__transparent_union__));`. This mutation directly mimics the code construct that triggered the assertion failure, focusing on the compiler's error recovery path when handling invalid or incomplete types within a transparent union.
