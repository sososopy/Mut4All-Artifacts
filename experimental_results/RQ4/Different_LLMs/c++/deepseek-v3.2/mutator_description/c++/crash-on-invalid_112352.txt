Mutation Operator: ExpandParameterPackInLambdaWithinTemplateInstantiation

This mutation targets the interaction between lambda expressions and unexpanded parameter packs during template instantiation, specifically within the context of C++20 variadic templates. It applies when a lambda expression is present inside a template function or class that uses parameter packs, and the lambda's body contains expressions that could potentially involve pack expansion but are not explicitly expanded.

The mutation modifies the lambda body to introduce an explicit pack expansion on a captured or accessible parameter pack variable that is already present in the enclosing template scope. The change involves replacing a statement or expression within the lambda with a fold expression or a pack expansion that uses the existing pack. If the seed program already contains a parameter pack named `args` in the template, and a lambda captures `args` or accesses it, the mutation will replace a generic expression inside the lambda with `(args + ...)` or `(args op ...)` where `op` is an operator already used in the seed program (like `+`, `*`, `&&`, etc.). If no operator is present, a simple addition fold is used. If the lambda does not capture the pack, it is modified to capture it by reference (e.g., `[&args...]`). This ensures the pack is referenced inside the lambda, potentially triggering the unexpanded pack detection logic during instantiation.

Example: Given a seed program with a template function `template<typename... Ts> void f(Ts... args)` containing a lambda `auto l = []{ return 0; };`, mutate to `auto l = [&args...]{ return (args + ...); };`. This introduces an explicit fold expression inside the lambda that expands the pack `args`, which may lead to assertion failures if the compiler's internal state for unexpanded packs is inconsistent. The mutation uses only existing names (`args`) and operators (`+` if present, otherwise introduced as `+`). It avoids introducing new types or variables beyond the pack expansion syntax.
