Mutation operator: Replace member access with ambiguous nested member access in class/struct/union bodies.

This mutation applies when a seed program contains a class, struct, or union definition with at least one member declaration (variable or function). It targets the internal lookup of member names during parsing. The operator modifies the body by introducing an additional member declaration that uses the same name as an existing member, but nested within a dummy scope to create ambiguity, specifically by adding a redundant named struct inside the class that reuses a member name.

Change: Inside the class/struct/union body, after an existing member declaration (e.g., `int x;`), insert a new internal struct declaration that duplicates a member name. For example, if the class has a member named `x`, add: `struct { int x; };`. This creates two distinct entities with the same name `x` within the class: the original member and a member of the anonymous struct. This can confuse member lookup logic.

Example: Original class body: `class C { int x; void f(); };` Mutated to: `class C { int x; struct { int x; }; void f(); };`.

If no member names are available, the mutation does not apply. The inserted anonymous struct uses a type that exists in the seed program (e.g., `int` if `int` is used elsewhere). If no suitable type exists, introduce a new type declaration before the class: `typedef int NewType;` and use `NewType` in the anonymous struct. The mutation only adds declarations; it does not modify existing ones.
