Mutation Operator: Replace Enum Underlying Type with Incomplete Forward Declaration

This mutation operator targets enumerated type (enum) declarations where an explicit underlying type is specified. It applies when the seed program contains an enum declaration with an explicitly defined underlying type, such as `enum MyEnum : underlying_type;` or `enum class MyEnum : underlying_type;`. The operator modifies the declaration by removing the underlying type specification, creating an incomplete forward declaration of the enum.

Specifically, for any line in the seed program that matches the pattern of an enum forward declaration or full declaration with an underlying type (e.g., `enum Name : Type;` or `enum Name : Type { enumerators };`), the operator will change it to `enum Name;`. This transformation is applied regardless of whether the original was a forward declaration or a complete definition. If the original was a complete definition with enumerators, those enumerators are removed, leaving only the incomplete forward declaration.

The operator should only use enum names, underlying types, and enumerators that already exist in the seed program. No new identifiers are introduced. The change is made directly to the source code line containing the enum declaration.

Example mutation for a forward declaration:
Original: `enum ForwardEnum : bool;`
Mutated: `enum ForwardEnum;`

Example mutation for a full definition:
Original: `enum Color : int { Red, Green, Blue };`
Mutated: `enum Color;`

The purpose of this mutation is to create scenarios where the compiler must handle an enum with an unknown underlying type or incomplete context, which can trigger inconsistencies in type deduction, static assertion checks, or cast operations, particularly in templates or constexpr contexts. This mimics the structure in the bug report where a forward-declared enum with an underlying type was involved in a static_assert, leading to a compiler assertion failure.
