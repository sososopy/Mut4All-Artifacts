Mutation Operator: Insert Unicode Escape Sequence in Identifier

This mutation operator targets identifiers within the source code, including variable names, function names, type names, and macro names. It applies to any valid identifier token encountered during lexical analysis. The operator modifies an identifier by inserting a Unicode escape sequence (specifically, a malformed or unexpected Unicode escape representation) directly into its character sequence. The goal is to stress the lexer's handling of identifier parsing, particularly for invalid Unicode inputs.

The change is made by selecting an existing identifier in the seed program. The identifier is altered by replacing one of its characters (often the first or a middle character) with a raw sequence representing a Unicode escape, such as `\u` followed by an incomplete or invalid hex digit sequence (e.g., `\u` alone, `\u{`, or `\u` with non-hex characters). Preference is given to using identifiers that already exist in the program to ensure context relevance. If no suitable identifier exists, a new identifier can be introduced in a declaration (e.g., a variable declaration), but this identifier must be defined with the mutated form from its inception; for example, `int \u{ = 0;` would be added as a new line. The mutation should not introduce undeclared types or variables without proper declaration context.

Example in pseudo-code: Original code has `int value = 10;`. Mutated code becomes `int \u{value = 10;` (inserting `\u{` at the start of the identifier). Another example: Original function call `func();` mutated to `\ufunc();`. The change is limited to the identifier token itself, preserving surrounding syntax where possible.

This operator aims to cover a wide range of program structures because identifiers are ubiquitous across declarations, expressions, and statements. It focuses on the lexical analysis phase, which is implicated in the crash-on-invalid bug report, by introducing an invalid token that may trigger parser or lexer failures.
