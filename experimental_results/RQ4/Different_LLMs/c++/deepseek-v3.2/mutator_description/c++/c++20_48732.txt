Mutation operator: Replace a lambda's template parameter pack with an explicit sequence of integer template arguments matching a surrounding index sequence expansion. This mutation applies when a lambda expression has a template parameter pack that is used to expand over an std::index_sequence or std::integer_sequence, and the pack size is known from the context (e.g., from a make_index_sequence or a compile-time constant). The mutation replaces the parameter pack with a list of explicit integer template arguments corresponding to the indices. For example, if the lambda is defined as [&]<std::size_t... Is>(std::index_sequence<Is...>) { ... } and is called with std::make_index_sequence<N>{}, where N is a constant expression, change the lambda to [&]<std::size_t I0, std::size_t I1, ..., std::size_t I_{N-1}>(std::index_sequence<I0, I1, ..., I_{N-1}>) { ... }. The mutation should use existing variable names and types from the seed program; if new template parameter names are needed, generate them by appending a numeric suffix to an existing identifier from the lambda's context (e.g., if the lambda uses 'Is', new names could be 'Is0', 'Is1', etc.). The mutation must ensure that all uses of the pack inside the lambda body are updated to use the explicit arguments, replacing pack expansion patterns with corresponding explicit lists. This mutation targets complex template instantiation scenarios involving lambda templates and index sequences, which are prone to compiler crashes as shown in the bug report.
