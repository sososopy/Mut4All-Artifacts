mutation operator
Target a specific code construct: template parameters with default arguments involving lambda expressions in C++20 concepts.

Where it applies: This mutation operator applies to template declarations that have a default argument for a template parameter, where the default argument is a lambda expression used within a concept constraint (such as std::convertible_to). The mutation modifies the default argument lambda to change its return statement, potentially altering the type compatibility with the concept constraint.

Changes to be made: For a template parameter default argument that is a lambda expression returning a value, mutate the return statement by replacing the returned expression with a different expression of a compatible type that exists in the seed program. If no such expression exists, introduce a new variable or function call that returns a type matching the expected return type of the lambda. The new element must be declared in the seed program prior to the mutation. Specifically, change the return statement inside the lambda from 'return Ret();' to 'return variable_of_type_Ret;' where variable_of_type_Ret is a variable of type Ret that is already present in the seed program or can be introduced by declaring a static variable of type Ret with default initialization.

Example in pseudo-code: Original code snippet: template <typename Ret, std::convertible_to<Ret (*)()> Default = decltype([] { return Ret(); })> void func() {} Mutated code snippet: template <typename Ret, std::convertible_to<Ret (*)()> Default = decltype([] { static Ret var{}; return var; })> void func() {} This mutation introduces a static variable of type Ret inside the lambda to replace the direct constructor call, potentially exposing compiler bugs related to lambda type deduction within template default arguments under concepts.
