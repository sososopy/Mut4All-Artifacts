Mutation Operator: Module Interface Unit Creation Without Implementation

Target: This operator applies when a program contains any global declarations (e.g., variables, functions, types) and is compiled under a C++20 or later standard that supports modules. The mutation inserts a module declaration to create a module interface unit for these declarations but does not provide a corresponding module implementation unit, leaving the interface isolated.

Procedure:
1. Identify the first global declaration in the source file (excluding any pre-existing module declarations). This could be a variable definition like `int a;`, a function declaration, a class definition, etc.
2. Insert a module interface declaration directly before this global declaration. Use a module name derived from the context; if no obvious name exists, use a placeholder like `M`. The inserted line should be: `export module M;`.
3. Ensure the global declaration following the module declaration remains unchanged and becomes part of the module interface.
4. Do not create any separate implementation file (a `.cpp` file with `module M;`). The mutated program consists solely of this single file with the module interface unit.

Example: For a seed program containing `int a;`, the mutated code becomes:
export module M;
int a;

Rationale: This mutation triggers scenarios where the compiler expects both interface and implementation units for a module but only receives the interface. It exploits the module handling logic, particularly around code generation decisions, which can lead to assertions like the one in the bug report where the compiler fails to determine which module to generate code for. The operator is widely adaptable as it only requires a global declaration and a C++20 module context, avoiding reliance on specific names or types.
