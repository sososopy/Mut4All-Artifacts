Mutation operator: Introduce a lambda that captures a local variable and uses it in a decltype within a generic lambda, then instantiate this lambda in a variadic template expansion context. This operator targets the combination of lambda captures, decltype expressions, generic lambdas, and variadic template instantiation, which are structures that trigger compiler bugs as seen in the crash-on-valid report. The operator applies when the seed program contains at least one local variable of any type and at least one template function that can be adapted to use a variadic pack.

Specifically, for a seed program that includes a function with a local variable, modify it by adding a generic lambda that captures this variable (by copy or reference) and uses decltype on the captured variable in its return type or trailing return type. Then, create or modify a variadic template function that instantiates this lambda for each type in a pack, ensuring the lambda is invoked within a fold expression or recursive template expansion.

Changes: In the seed program, identify a function with a local variable. Insert a generic lambda inside this function that captures the local variable and has a decltype expression referring to it. Then, modify an existing template function to become variadic or create a new one that takes a lambda and a pack of types, expanding the pack to instantiate the lambda for each type. Use a fold expression (if C++17 or later) or recursive template calls to perform the expansion.

Example: If the seed program has a function 'void foo() { int x = 0; }', transform it to 'void foo() { int x = 0; auto lam = [](auto) -> decltype(x) { return x; }; }'. Then, add a variadic template 'template<typename... Ts> void bar(auto f) { ((Ts{}, f(0)), ...); }' and call it from foo as 'bar<int, double>(lam);', ensuring the lambda is instantiated with different types.

Preference is given to using existing variables, types, and functions. If new elements are introduced, they should be declared with common names like 'lam' for lambdas and 'bar' for template functions, using basic types like 'int' or 'double' for the pack if necessary. Avoid introducing undefined symbols.
