Mutation operator: Alter the explicit return type specification of a lambda expression to a placeholder auto return type, while preserving the lambda's parameter list and body, and ensuring that any trailing return type specifiers are removed. This mutation targets lambda expressions defined within template contexts or generic lambda contexts, where the explicit return type interacts with template instantiation and capture analysis.

Target: Lambda expressions with an explicitly specified return type (e.g., -> void, -> int, -> SomeType) in C++20 mode, particularly those that are generic (using auto parameters) or are defined within template functions or classes. The mutation applies to lambda definitions where the return type is explicitly stated after the parameter list.

Procedure: Identify a lambda expression with an explicit return type. Replace the explicit return type with the placeholder auto, removing the arrow and the type. If the lambda body contains return statements, they must be consistent with the deduced return type; however, the mutation assumes the original body is valid for deduction. The parameter list and capture clause remain unchanged. For example, a lambda originally written as [&](auto b, auto e, std::unordered_set<int> s)->void{ ... } becomes [&](auto b, auto e, std::unordered_set<int> s){ ... }. This mutation should be applied only when the lambda is used in a context where the return type can be deduced from the body, such as when there are no return statements (void) or when all return expressions have a common type.

Rationale: This mutation exploits compiler bugs related to the handling of explicit return types in lambdas during template instantiation and capture analysis, as seen in the bug report where an explicit ->void on a generic lambda caused a crash. By removing the explicit return type, the compiler must deduce the return type, potentially triggering different internal pathways that may expose bugs in deduction, capture handling, or constraint satisfaction in C++20.
