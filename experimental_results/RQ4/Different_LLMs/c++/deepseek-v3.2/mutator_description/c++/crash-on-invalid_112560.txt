Mutation operator: Introduce incomplete in-class initializers in union member declarations.

This operator targets in-class initializers for member declarations within unions. It applies when a union type is declared and contains at least one member variable declaration. The mutation modifies a member's in-class initializer expression by replacing it with an incomplete expression that triggers parsing errors during initialization checking. Specifically, the mutation removes the right-hand side expression of the initializer, leaving only the assignment token and a semicolon, which creates a malformed initializer that the compiler may fail to handle gracefully.

To apply the mutation, for each union type found in the seed program, identify its member declarations. For each member that has an in-class initializer (i.e., an expression after '='), replace the initializer expression with nothing, resulting in a syntax like 'member = ;'. If the member does not already have an initializer, optionally add an incomplete initializer '= ;', but preference is given to modifying existing initializers to use existing variable names and types, avoiding introduction of new elements. The mutation should be applied to one member per union at a time to generate varied test cases.

Example transformation: If the seed contains 'union U { int x = 5; };', mutate to 'union U { int x = ; };'. If the seed contains 'union U { int x; };', mutate to 'union U { int x = ; };' but this introduces a new incomplete initializer, so it should be done cautiously to maintain validity of other constructs. The operator focuses on unions because the bug report indicates a crash during in-class initializer processing within a union context. This mutation is likely to expose similar unreachable code paths or assertion failures in the compiler's initialization logic for unions.
