mutation operator: replace template specialization with a nested template parameter in function signature

This mutation operator targets function template specializations. It applies when a seed program contains a function template specialization that uses a single template parameter. The operator modifies the specialization by introducing a nested template parameter, effectively creating a template parameter with depth greater than zero within the function signature context.

The change involves altering the template parameter list of the specialized function. Specifically, if the original specialization is for a template parameter `T`, it is replaced with a template parameter that itself is a template, such as `Template<T>`, where `Template` is a new template class. To avoid introducing undeclared types, the operator first checks if the seed program already contains a template class declaration that can serve as `Template`. If not, a simple template class is inserted before the specialization. This new class is a minimal template with one parameter, for example: `template<typename U> struct Wrapper {};`. Then, in the function specialization signature, the original type `T` is replaced with `Wrapper<T>`.

For example, if the seed code has:
template<> void func(int param) { ... }
After mutation, assuming `Wrapper` is introduced or exists:
template<> void func(Wrapper<int> param) { ... }
The function body remains unchanged, but the call or context may now involve a nested template parameter depth.

The operator clearly outlines the steps: 1. Identify a function template specialization in the seed. 2. Determine or declare a wrapper template class. 3. Replace the specialized type in the function parameter list with the wrapped type, keeping the same underlying type name but nested. This change is designed to trigger issues in template deduction logic involving depth, as seen in the bug report.
