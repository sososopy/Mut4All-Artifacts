mutation operator
This mutation operator targets lambda expressions inside template instantiations, particularly those that capture variables during the template substitution process. The bug report indicates an ICE during variable capture (clang::Sema::tryCaptureVariable) while instantiating templates involving lambdas. The mutation applies to lambda expressions that appear within template contexts, such as generic lambdas or lambdas inside templated classes or functions. The operator changes the capture method of a lambda from capturing a variable by reference to capturing it by value, or vice versa. Specifically, if the seed lambda captures a variable by reference (using & in the capture list), mutate it to capture by value (omit the &). Conversely, if it captures by value, mutate it to capture by reference. If the lambda uses a default capture (like [&] or [=]), mutate it to explicitly list the captured variables with the opposite capture method for one of them. For example, if a lambda uses [&] and captures variable x implicitly, change to [&, x] (keeping reference capture but making it explicit) or to [=, &x] (switching default to value but capturing x by reference). The operator only applies to lambdas that are syntactically valid in the seed program and capture at least one variable. It avoids introducing new variables or types; it only modifies existing capture clauses. For instance, given a seed lambda: [](auto param) { return captured_var + param; } where captured_var is captured by reference as [&captured_var], mutate to [captured_var] (by value). Or if the lambda uses [=], mutate to [&] for the default capture. This change alters the variable capture semantics during template instantiation, potentially exposing bugs in the compiler's capture analysis under complex template substitution scenarios.
