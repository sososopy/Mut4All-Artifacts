Mutation operator: Replace the condition expression in a `diagnose_if` attribute with a dependent expression that is an unexpanded parameter pack.

Target: This mutation applies to any `diagnose_if` attribute attached to a function or lambda expression where the first argument (the condition) is a compile-time evaluable expression. The goal is to replace that condition with an expression that is value-dependent due to being an unexpanded pack, specifically using a template parameter pack from the enclosing context.

Procedure: In a template context that declares a parameter pack (e.g., `template <typename... Ts>` or `template <bool... vals>`), locate a `diagnose_if` attribute. The attribute originally has a condition that is independent (e.g., `true`, `false`, `sizeof(T) == 4`). Change the condition to an expression that directly uses the pack without expanding it. For example, if the pack is `vals`, use `vals` alone (which is an unexpanded pack) as the condition. Ensure the pack is used in a way that remains value-dependent (i.e., not expanded via pattern in a fold expression or other pack expansion). This mutation should be applied only when the template is instantiated with an empty pack list (like `f<>()`), because that creates a scenario where the pack exists but has zero elements, making the unexpanded pack still dependent but potentially triggering internal compiler assertions during evaluation.

Example: Given a seed program with a template function `template <bool... vals> void h() { }`, introduce a lambda inside `h` with a `diagnose_if` attribute: `[] () __attribute((diagnose_if(vals, "message", "error"))) {}();`. Here `vals` is the unexpanded pack. If the seed already has a `diagnose_if` attribute with a condition like `true`, replace `true` with `vals`. If the seed does not have a `diagnose_if` attribute, add one to a lambda or function declaration inside the template, using the pack as the condition. The mutation must ensure the pack is not expanded; simply using the pack name suffices. The message and diagnostic type (e.g., "error") can be any string literal; use existing ones if present, or introduce simple ones like "msg" and "error". The mutated code should be placed such that it is instantiated when the template is called with an empty argument list.
