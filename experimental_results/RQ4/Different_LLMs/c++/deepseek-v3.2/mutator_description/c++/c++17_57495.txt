mutation operator: replace member access operator with dot after a namespace or class name with an arbitrary identifier to create a malformed member access that triggers parser recursion.

This mutation operator applies to code constructs where a namespace or class name is followed by a dot operator intended for member access, but the syntax is incomplete or incorrect. The operator targets situations where the parser expects a valid member name after the dot, but instead encounters unexpected tokens that may lead to infinite recursion or crashes in the compiler's parsing logic.

The mutation changes the token immediately after the dot operator to an arbitrary identifier that does not resolve to a valid member, but is chosen to be a plausible token that could be interpreted as a type or variable name, increasing the chance of confusing the parser's decision between parsing a type name or a declaration specifier.

To implement this mutation, locate instances where a namespace or class name (from the seed program) is followed by a dot operator. Replace the token after the dot with an identifier that is not declared as a member of that namespace or class. Use an identifier that is already present elsewhere in the seed program as a variable or type name to avoid introducing undeclared elements. If no such identifier exists, introduce a simple identifier like 'x', ensuring it is not declared in the relevant context.

Example: In the seed code 'std::vector.d', the token 'd' after the dot is replaced. If the seed program contains a variable named 'value', mutate to 'std::vector.value'. This creates a malformed member access because 'value' is not a member of std::vector, but the identifier 'value' might be valid elsewhere, potentially triggering the parser's lookup mechanisms and recursive checks as seen in the bug report.

This mutation aims to expose bugs in the compiler's handling of incorrect member access syntax, particularly in C++17 mode where such constructs might lead to crashes during parsing due to infinite recursion in the isCXXDeclarationSpecifier logic.
