mutation operator: Overload resolution with mismatched template arguments in function calls. This operator targets call expressions where a function template (like std::make_tuple) is used with explicitly provided template arguments that conflict with the types of the provided function arguments. The mutation changes the explicitly specified template arguments in the call to introduce a type mismatch, aiming to stress the compiler's overload resolution and template argument deduction logic during error handling, which is a known crash-prone area.

The operator applies to any call expression that explicitly provides template arguments (e.g., func<Type1, Type2>(args)). It modifies the explicitly specified template arguments by replacing them with types that exist in the seed program but are incompatible with the function arguments. The selection of replacement types follows a systematic approach: first, gather all named types (class/struct/union types, typedefs, and using aliases) that are currently in scope at the call site. From this list, choose a type that is distinct from the original template argument and is likely to cause a mismatch (e.g., if the original argument is an integral type, choose a non-integral type like a class type). If no suitable named type exists, the operator may introduce a simple placeholder type (like a forward-declared struct) by adding a declaration like struct MutatedType; in an appropriate scope (e.g., the global namespace) before the mutation point. However, preference is always given to using existing types to avoid introducing new declarations.

Example: In a seed program containing types int, double, and a user-defined struct S, a call like std::make_tuple<int, double>(1, 2.0) could be mutated to std::make_tuple<S, double>(1, 2.0), where S is an existing struct type. This creates a mismatch because the first argument 1 is of type int, but the explicitly specified template argument is S, leading to a potential overload resolution failure that may expose compiler crashes.
