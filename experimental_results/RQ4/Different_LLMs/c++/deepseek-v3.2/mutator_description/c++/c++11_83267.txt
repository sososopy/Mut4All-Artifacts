Summary of structures that C++ compiler bugs are more likely to trigger based on the bug report: The bug involves a lambda capture in a generic lambda, a decltype expression that extracts the result_type from a std::function constructed from that lambda, and then a template specialization of a member function (operator()) of that result_type, which incorrectly tries to access a variable (c) from the lambda's context within the specialization. This indicates bugs are likely in complex interactions between lambda captures, decltype, std::function type deduction, template specializations, and member function definitions of nested or dependent types, especially when referencing captured variables incorrectly across scopes.

Mutation Operator: Mutate Lambda Capture in Generic Lambda to Reference Capture Instead of Copy Capture. This operator applies when a lambda expression exists within the seed program that uses a copy capture (either by value or via capture list with copy syntax). The mutation changes a copy capture to a reference capture. Specifically, for a lambda capture that is written as [var] or [var=var] (copy capture), change it to [&var] or [&var=var] (reference capture). This should be applied to lambdas that are generic (i.e., have an auto parameter) or non-generic, but preference is given to lambdas that are used in contexts where their type is inspected (e.g., via decltype) or wrapped in std::function. The mutation only uses variables that are already declared in the enclosing scope of the lambda. Do not introduce new variables. Example: In a seed program snippet like: auto func = [x](auto a) { return x + a; }; mutate to: auto func = [&x](auto a) { return x + a; }; Or for a capture with initializer: auto func = [cap=capture](auto a) mutable { return cap + 1; }; mutate to: auto func = [&cap=capture](auto a) mutable { return cap + 1; }; The change is solely in the capture list, replacing a copy capture with a reference capture. This mutation aims to expose bugs related to lifetime, type deduction, and instantiation issues with reference captures in complex template contexts.
