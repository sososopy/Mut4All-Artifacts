mutation operator: Replace empty initializer list with explicit default constructor call for aggregate types containing non-aggregate members. This operator targets variable declarations that use empty braced initialization `= {}` for aggregate types (like arrays, structs, or classes with public members and no user-provided constructors) where at least one member type is non-aggregate (e.g., a class with a user-declared constructor, like many STL containers). The mutation changes the initialization to use direct initialization with an explicit default constructor call, which may trigger different code paths in the compiler's initialization logic, potentially exposing crashes similar to the reported issue where the compiler mishandles empty initialization of complex nested types.

The operator applies when a variable declaration has an initializer of the form `= {}` and the declared type is an aggregate that contains at least one member type that is non-aggregate. To determine this, the operator should check the seed program's type definitions: if the aggregate's member types include any class type with a user-declared constructor (including implicitly declared as deleted), defaulted constructor, or inherited constructor, then the member is considered non-aggregate. In practice, for testing, the operator can be applied heuristically when the aggregate type is a template instantiation known to be non-aggregate (e.g., `std::unordered_map`) or when the member type is a class with a constructor visible in the seed program.

The change replaces `= {}` with `= T()`, where `T` is the exact type of the variable being declared. This uses value-initialization instead of aggregate initialization. If the variable is an array type, the change applies to the entire array initialization. The operator should only use types and variables already present in the seed program; no new declarations are introduced.

Example: In the seed code `std::array<std::unordered_map<int, int>, 5> v = {};`, the type `std::array<std::unordered_map<int, int>, 5>` is an aggregate (since `std::array` is an aggregate), but its element type `std::unordered_map<int, int>` is non-aggregate (it has a user-declared constructor). Thus, the operator mutates it to `std::array<std::unordered_map<int, int>, 5> v = std::array<std::unordered_map<int, int>, 5>();`.

Another example: For a struct `S { std::vector<int> v; }` and declaration `S s = {};`, mutate to `S s = S();`, because `S` is an aggregate with a non-aggregate member `std::vector<int>`.

Note: The operator does not apply if the initializer is not empty (e.g., `= {1}`) or if the aggregate type has only aggregate members (e.g., `int arr[3] = {};` remains unchanged). This focuses on edge cases where empty aggregate initialization interacts with non-aggregate members, which can reveal compiler bugs in initialization sequence handling.
