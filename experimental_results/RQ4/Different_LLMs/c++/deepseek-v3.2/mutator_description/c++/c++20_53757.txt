Based on the bug report analysis, the crash occurs when deserializing a type alias that uses decltype on an unevaluated lambda within a precompiled header context. This suggests compiler bugs are more likely to be triggered by combinations of: 1) unevaluated contexts (decltype, sizeof, etc.), 2) lambda expressions, 3) template type aliases, and 4) serialization/deserialization scenarios (PCH, modules). The mutation operator targets this intersection.

Mutation Operator: Replace decltype on lambda expression with decltype on a lambda expression wrapped in an unevaluated operation.

This mutation applies when the seed program contains a decltype specifier whose operand is a lambda expression (e.g., decltype([]{})). The operator modifies this by embedding the lambda expression inside another unevaluated context, specifically by applying sizeof to the lambda expression. The sizeof operator is chosen because it is also an unevaluated context and may alter the compiler's internal handling of the lambda during type computation or serialization. The change is: replace 'decltype(lambda_expr)' with 'decltype(sizeof(lambda_expr))'. This creates a nested unevaluated operation: decltype operates on the result of sizeof, which itself operates on the lambda. This can stress different pathways in type deduction and serialization logic.

Example: If the seed code has 'using Alias = decltype([]{});', mutate to 'using Alias = decltype(sizeof([]{}));'. The lambda expression remains unchanged; only the outer structure is modified. The sizeof returns a size_t, so decltype(sizeof(lambda)) will yield the type size_t, which is a different resulting type, but the mutation's goal is to expose bugs in the processing of the lambda within decltype in serialization contexts, not to preserve semantic equivalence.

The mutation uses only existing elements: decltype, sizeof, and the lambda expression. No new variables or types are introduced. The change is purely syntactic and applies to any occurrence of decltype with a lambda operand, regardless of whether it's inside a template alias or other constructs. This mutation is designed to be widely applicable across seed programs that contain lambdas in decltype, increasing the chance of triggering similar serialization or deserialization bugs in the compiler.
