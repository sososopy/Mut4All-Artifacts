mutation operator: Overload Resolution with Mismatched Template Argument Explicit Specification

This mutation operator targets function calls where explicit template arguments are provided, and it changes those explicit template arguments to types that are present in the seed program but are mismatched with the actual function call arguments. This specifically applies to calls of function templates (like `std::make_tuple`) or other templated functions where the user can explicitly specify template parameters. The operator aims to trigger bugs in the compiler's overload resolution and template argument deduction logic when faced with conflicting explicit and deduced type information, which can lead to internal compiler errors like crashes.

The operator works by scanning for call expressions where explicit template arguments are provided (e.g., `func<Type1, Type2>(args)`). For each such call, it selects one of the explicitly specified template arguments and replaces it with another type that exists in the current scope (e.g., from a typedef, using alias, class name, or built-in type already used in the program). The replacement type should be chosen such that it is syntactically valid but semantically likely to create a mismatch or ambiguity with the types of the actual arguments passed to the function. Preference is given to using types that are already declared in the seed program to avoid introducing undeclared identifiers. If no suitable existing type is available, a simple built-in type (like `int`, `void`, `char`) that is not obviously compatible with the argument can be used.

Example: Original code has `std::make_tuple<int, double>(0, "test")`. The operator might change it to `std::make_tuple<int, std::string>(0, "test")` if `std::string` is already in scope (via includes). Another mutation could be `std::make_tuple<var_tuple, double>(0, "test")` if `var_tuple` (a type alias for `std::tuple<int, int>`) is present. The change should be made directly in the source code at the call site.
