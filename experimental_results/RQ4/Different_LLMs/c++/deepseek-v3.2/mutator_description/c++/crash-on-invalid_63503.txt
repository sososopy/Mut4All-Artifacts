mutation operator: Incomplete destructor specifier insertion

This mutation operator targets the declaration of a destructor for a class or struct. It applies when the seed program contains at least one user-defined class or struct type. The mutation modifies the destructor declaration to be incomplete by removing the class name after the tilde, leaving only the tilde and the parentheses. The operator should be applied to destructors that are already defined in the seed program; it does not introduce new destructors for types that do not already have one.

Specifically, for a destructor declaration of the form: ~TypeName() { ... } or ~TypeName();, the mutation changes it to: ~() { ... } or ~();. The body, if present, is kept unchanged. This creates a syntactically incomplete destructor specifier.

Example using pseudo-code: If the seed contains class MyClass { public: ~MyClass() {} };, after mutation it becomes class MyClass { public: ~() {} };. No new variables, types, or functions are introduced. Only the existing destructor's declarator is altered. The mutation should be applied only once per seed program, targeting one destructor declaration.

The operator aims to trigger internal compiler errors related to handling incomplete destructor specifiers during semantic analysis, particularly when the destructor is referenced, such as during variable destruction or explicit calls. The change is minimal and focuses on the declarator part, preserving the rest of the context to maintain compilation of other code parts.
