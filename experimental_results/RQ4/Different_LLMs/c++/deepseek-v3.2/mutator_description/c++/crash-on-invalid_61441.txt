Mutation Operator: Replace Lambda Parameter Type with Mismatched Integral or Floating Type

Target: This mutation applies to lambda expressions within function bodies (including template functions). Specifically, it modifies the declared parameter type of a lambda.

Description: The mutation replaces the explicit parameter type of a lambda with a different integral or floating type that is mismatched relative to the lambda's context or implicit expectations. The new type should be chosen from existing integral or floating types present in the surrounding scope (e.g., within the same function, its parameters, or visible global types). If no suitable type exists, introduce a simple fundamental type like `int` or `double`, ensuring it is declared appropriately. The goal is to create a type mismatch that may be invalid or problematic for lambda handling, potentially triggering crashes during template instantiation or lambda analysis.

Procedure:
1. Identify a lambda expression within a function.
2. Locate an explicitly declared parameter type in the lambda (e.g., `(__fp16)` in the example).
3. Select a replacement type:
   - Prioritize using an existing integral or floating type from the immediate context (e.g., a function parameter type, a local variable type, or a visible global type).
   - If no such type exists, introduce a fundamental type like `int`. Ensure this type is valid in the context (e.g., `int` is always available without additional declaration).
4. Replace the original parameter type with the selected type in the lambda declaration.

Example based on bug report context:
Original code snippet: `[&](__fp16) { return 0; };`
Assume the surrounding context has no other integral/floating types. Introduce `int`.
Mutated code snippet: `[&](int) { return 0; };`

Note: The mutation focuses on creating a mismatch, not on semantic correctness. The new type may be incompatible with the lambda's return expression or other implicit conversions, aiming to expose crashes in compiler frontend during invalid type handling.
