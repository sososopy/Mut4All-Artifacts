Mutation operator: Replace a non-generic lambda with a generic lambda in capture contexts.

This mutation operator targets lambda expressions that are not generic (i.e., do not have a template parameter list) and are within a scope where they could potentially capture a variable from an outer scope. The operator modifies such a lambda by adding a template parameter list to make it generic. Specifically, it changes a lambda expression that is written without a template parameter list into a generic lambda by inserting 'template <typename T>' (or a similar simple template parameter) before the lambda's parameter list, while ensuring the lambda body remains syntactically valid. This applies to any lambda expression that appears in code where capture is possible, such as inside another function or lambda. The change should use existing types or variables from the surrounding context to instantiate the template if needed; for example, if the lambda body uses a variable of a specific type, that type can be used as the template argument. The mutation aims to trigger compiler assertions related to capture-ready lambda checks, especially in nested lambda scenarios where the compiler must determine the nearest enclosing capture-capable lambda. For example, a seed code containing a non-generic lambda inside a function that captures a local variable is mutated to a generic lambda, potentially altering the capture analysis logic and exposing bugs like the one reported. The operator avoids introducing new data names or types; it reuses existing elements from the seed program. If the lambda body does not use any templated operations, the template parameter may be unused but still changes the lambda's classification. The mutation is applied directly to the lambda syntax in the source code.
