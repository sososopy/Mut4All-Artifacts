mutation operator: mutate enum class declaration to using enum statement without class keyword, targeting enum declarations in the seed program.

this mutation operator applies when the seed program contains an enum class or enum struct declaration. it transforms the enum declaration into a using enum statement that attempts to reference the enum without the class keyword, potentially triggering frontend parsing errors.

specifically, locate any enum class or enum struct declaration in the seed program. for example, if the seed contains: enum class name { member1, member2 }; replace it with: using enum name;. ensure that the enum name 'name' is exactly the same as the original enum identifier from the seed program. no new identifiers or types are introduced; the mutation uses existing enum names.

if the seed program has multiple enum class declarations, apply the mutation to each individually, generating separate mutated versions. the mutation should only be applied where the original declaration is an enum class or enum struct, not a plain enum. the using enum statement must be placed in the same scope where the enum class was originally declared, or in a scope where the enum name is accessible, typically the same namespace or function block.

example transformation: original code has enum class color { red, blue }; mutated code becomes using enum color;. this change removes the class keyword and converts the declaration into a using directive, which may cause compiler confusion if the enum was not previously defined as a plain enum.

the mutation operator aims to expose bugs in compiler frontend parsing of using enum statements, especially when referencing enum class types incorrectly, as seen in the bug report where using enum class triggers a crash.
