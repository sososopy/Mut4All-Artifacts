mutation operator: replace a default argument in a function parameter with a lambda expression that attempts to capture the parameter itself.

target: this mutation applies to function declarations (including member functions and free functions) where at least one parameter has a default argument. the default argument can be any expression. we replace that default argument with a lambda that uses the parameter's name inside its body, without an explicit capture list, causing an implicit capture attempt.

procedure: for each function declaration in the seed program, identify parameters with default arguments. select one such parameter. replace its default argument with a lambda expression of the form [] { return param_name; } or [] { param_name; } etc., where param_name is the name of the parameter being mutated. ensure the lambda body references that parameter directly. if the parameter type is a forward-declared class (only a struct/class name without a definition available), that is preferred to increase likelihood of layout computation attempts. the lambda should be placed as the new default argument. if the original default argument was complex, discard it. do not introduce new types or variables; use only the parameter name which is already declared. the lambda should have no capture-default (i.e., no [=] or [&]), forcing implicit capture analysis.

example: given a function declaration like void func(ForwardDeclaredType x = some_default); mutate to void func(ForwardDeclaredType x = [] { return x; }); if ForwardDeclaredType is a forward-declared class struct ForwardDeclaredType; earlier in the code. if the seed has no forward-declared classes, still apply the mutation using existing parameter types.

note: the mutation focuses on creating a situation where the compiler must analyze a lambda that implicitly captures a parameter from its enclosing function scope while potentially requiring type information (like layout) for a forward-declared class. this can trigger crashes during semantic analysis or layout computation.
