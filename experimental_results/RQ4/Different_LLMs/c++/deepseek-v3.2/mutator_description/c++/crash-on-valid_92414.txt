mutation operator Complex Template Argument Deduction in Nested Initialization Contexts. This operator targets situations where a template class constructor or deduction guide is invoked with an argument that is itself a template function call or a complex expression involving templates. It applies when a template class object is being constructed using list-initialization syntax `C{...}` or `C(...)` and the argument inside the braces or parentheses is a call to a template function or a dependent expression. The mutation changes the initialization argument to wrap it inside an additional pair of parentheses, creating a nested expression that may alter template argument deduction behavior. Specifically, for a construct like `C{ some_func<T>(arg) }`, mutate it to `C{ (some_func<T>(arg)) }`. If the existing argument is already a complex expression, such as `C{ some_func<int>(C{some_func<int>(0)}) }`, mutate the outer call to `C{ (some_func<int>(C{some_func<int>(0)})) }`. This introduces a parenthesized expression which can affect how template parameters are deduced, particularly for initializer_list constructors or user-defined deduction guides, potentially exposing compiler crashes during overload resolution or deduction. The operator uses only variables and functions already present in the seed program; no new declarations are introduced. The change is purely syntactic, adding parentheses around the entire argument expression within the initializer list. Example transformation: Original code `C{ some_func<int>(0) }` becomes mutated code `C{ (some_func<int>(0)) }`. Another example: Original `C{ some_func<T>(value) }` becomes `C{ (some_func<T>(value)) }`. This mutation is designed to trigger issues in template argument deduction, especially with initializer_list constructors and alias templates, as seen in the bug report where deduction fails or crashes occur.
