mutation operator: Nested name specifier substitution in trailing return type.

This mutation operator targets template functions with a trailing return type that uses a nested name specifier (NNS) to access a member. It applies when a function's trailing return type contains a qualified-id of the form `t.X::Y`, where `t` is a parameter, `X` is a template parameter used as a nested-name-specifier, and `Y` is a dependent name. The operator substitutes the nested-name-specifier component with a different, valid type from the context that could also be used as a qualifier, potentially creating a complex or unresolved nested name specifier chain.

Specifically, for a function template like `auto func(T t, U u) -> decltype(t.U::member)`, the operator will change the `U::` part. It first analyzes the seed program to collect all available class/struct/union types and template parameters in scope at the function declaration point. Then, it replaces `U::` with another collected type `Z::`, provided `Z` is a valid type name in that context. Preference is given to types that are template parameters of enclosing templates or base classes of existing types to increase the chance of creating a dependent name that requires intricate mangling. If no other suitable type exists, the operator may introduce a simple placeholder struct type (e.g., `struct _MutatedType {};`) declared just before the function, and use that as the qualifier (e.g., `_MutatedType::`).

The change is made only in the trailing return type; the function parameters and body remain unchanged. The goal is to generate nested name specifiers that may challenge the compiler's name lookup, dependency resolution, or mangling logic, particularly in the Itanium ABI mangling path where the bug manifested.

Example based on the bug report's code structures: Original code has `auto k(T t, U u, V v) -> decltype (t.U::template B<V>::MEM)`. The operator might change it to `auto k(T t, U u, V v) -> decltype (t.A<int>::template B<V>::MEM)`, substituting `U::` with `A<int>::`, since `A<int>` is a known type in the scope. Alternatively, if a new type is introduced, it could become `auto k(T t, U u, V v) -> decltype (t._MutatedType::template B<V>::MEM)` with `struct _MutatedType {};` added before the function.

The operator must ensure that the mutated code is syntactically valid C++ and respects template dependency rules (e.g., the `template` keyword is preserved if the member is a template). It avoids using unspecified or ambiguous types, and the new qualifier is explicitly declared or known.
