mutation operator: replace template parameter type with a different but convertible class type in template template parameter matching contexts.

applies when: a template template parameter expects a template with a specific non-type template parameter of class type T, and there exists another class type S in the current scope that is convertible to T via a constexpr constructor or conversion function.

procedure: for each template template parameter P of a template declaration D that has a non-type template parameter of class type T, if there exists a distinct class type S declared in the same scope (or accessible via inheritance) such that S is convertible to T via a constexpr constructor taking S or a constexpr conversion function in S, then mutate by creating a new template Q that is identical to an existing template R which is being passed as an argument to P, but change the non-type template parameter type of Q from T to S. then replace the argument R with Q in the instantiation of D.

example: given seed code with struct X {}; struct Y { constexpr Y(const X &) {} }; template<template<X> class> struct A {}; template<X> struct B;. the mutation identifies template<X> struct B; as matching the template template parameter of A. it finds Y is convertible to X via constexpr constructor. it creates a new template: template<Y> struct C; (or renames if conflicts) and then generates template struct A<C>;.

note: the new template C must be declared before use. if a template with the same signature already exists, use it; otherwise, declare a new template with a unique name by appending a suffix like _mut to an existing template name, ensuring no collisions with existing identifiers. the new template should have the same template body as the original template B if possible, but if the body uses the template parameter, adapt by using a placeholder or keep it empty to avoid undefined references. prefer to keep the body minimal (e.g., an empty struct) to avoid introducing new errors unrelated to the bug.
