mutation operator: Inline Attribute on Ambiguous Overload Call
Target: This mutation operator applies to any function call expression inside a template function where the called function name matches an overload set that includes at least one other function (a different overload or a different function with the same name from a different scope). The operator adds a compiler-specific always-inline attribute (e.g., [[clang::always_inline]] or [[gnu::always_inline]]) directly to that specific call expression, forcing inline expansion at that point, which may stress overload resolution during inlining.

Application: For a seed program containing a template function (or member function template) that makes a call to a function name which is overloaded, identify a call site within that template. The mutation adds the inline attribute to the call expression itself. The attribute must be placed immediately before the call, attached to the call, not the surrounding statement. Use an attribute syntax supported by the compiler under test (e.g., Clang or GCC). If the seed already uses such an attribute on a declaration, apply it to a different call site. Ensure the call remains syntactically valid; the called function and its arguments must be present in the seed.

Example: Suppose the seed contains:
void func(int) {}
template<typename T>
void caller(T x) {
    func(x);
    func(42);
}
A mutation could target the call func(x) inside the template, changing it to:
[[clang::always_inline]] func(x);
The function name 'func' must refer to an existing overload set (here, possibly just one function). The mutation introduces no new variables or types; it only adds an attribute to an existing call. If the compiler supports a different attribute for forced inlining (like __attribute__((always_inline))), use the appropriate syntax for the target compiler. The mutation should not be applied if the call is already decorated with such an attribute.
