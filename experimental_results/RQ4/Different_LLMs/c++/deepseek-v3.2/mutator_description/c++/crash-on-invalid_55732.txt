Mutation operator: Insert recursively nested reference type declarator qualifiers.

This mutation applies to any declarator in a function parameter list, variable declaration, or type alias declaration that includes a reference type. The mutation recursively inserts additional reference qualifiers (const and volatile) and reference operators (& or &&) in a nested pattern, increasing the nesting depth significantly. The target is to create a deeply nested reference type that may stress the parser's stack or recursion limits.

Specifically, for a given declarator D that is a reference (e.g., "int& var" or "const int&& var"), the mutation replaces D with a new declarator that wraps D in multiple layers of reference qualifiers and operators. The pattern alternates between adding a const qualifier and a reference operator, repeating this sequence to build depth. The mutation uses existing qualifiers and operators from the seed program; if no const or volatile is present, it introduces const qualifiers. The new declarator must be syntactically placed within the same context as the original.

For example, if the seed contains "void func(int& param)", the mutation could produce "void func(const int& const& volatile& const& param)" by recursively adding "const&" layers. The mutation algorithm selects a depth increment (e.g., 5 to 20 layers) based on random or heuristic choice to maximize stress. The changes are made directly to the declarator's type specification, ensuring the identifier remains unchanged.

The operator must avoid introducing undeclared types or variables; it only modifies the declarator's type construction. The resulting code is intentionally invalid in many cases (as const on a reference is invalid), but the goal is to trigger parser crashes like the reported bug. This operator targets the parser's handling of deeply nested type qualifiers and references, a structure shown to cause segmentation faults in the bug report.
