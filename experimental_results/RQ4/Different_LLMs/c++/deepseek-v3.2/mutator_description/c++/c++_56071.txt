Based on the bug report, the crash occurs when a lambda inside a template function captures a local variable by reference (implicitly via decltype) and is then instantiated through a variadic template expansion. The compiler fails during type casting in the instantiation process, indicating a bug in the compiler's handling of variable capture contexts during template instantiation, particularly with nested lambdas and variadic templates.

mutation operator: Replace a lambda's trailing return type that uses decltype on a local variable with decltype(auto) to force type deduction from the lambda body, potentially altering the capture semantics and instantiation order. This applies to lambdas defined inside template functions (including member functions of class templates) that have a trailing return type explicitly using decltype referencing a variable declared in the enclosing scope. The mutation changes the trailing return type from decltype(var) to decltype(auto). For example, if a seed program contains: template<typename T> void func() { int x; auto l = [](auto p) -> decltype(x) { return p; }; } mutate to: template<typename T> void func() { int x; auto l = [](auto p) -> decltype(auto) { return p; }; } The mutation should only be applied when the decltype expression consists solely of a single identifier naming a variable declared in the immediately enclosing function scope. If the lambda body returns a different expression, the semantics may change, which is intentional to test compiler robustness. Use existing variable names from the seed program. Do not introduce new variables or types.
