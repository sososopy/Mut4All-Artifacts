Mutation operator: CTAD with constrained template argument substitution.

This operator targets calls to function templates where Class Template Argument Deduction (CTAD) is used alongside template constraints (concepts or requires clauses). The mutation applies when a function template call uses CTAD for a class template, and that class template has constrained template parameters. The mutation modifies the call by replacing explicit template arguments with CTAD where possible, or by introducing CTAD for a constrained class template that was previously instantiated with explicit arguments.

Specifically, locate a function template call where the arguments include a class template specialization with explicit template arguments, and that class template has at least one constrained template parameter. Change the call to use CTAD by removing the explicit template arguments from the class template specialization, ensuring the constructor arguments are sufficient for deduction. If the class template is nested within another template, ensure the outer template arguments are preserved.

Example: In a seed program containing `std::tuple<int, double> t(1, 2.0);`, if `std::tuple` has constrained parameters (in practice, it might not, but assume a similar user-defined template), mutate to `std::tuple t(1, 2.0);` to trigger CTAD. For a more complex case with a constrained template like `template<std::integral T> class S { S(T); };` and a call `S<int> s(5);`, mutate to `S s(5);`.

Prefer using existing variables and types from the seed. If new elements are needed, such as a constructor call, use values that match the types of existing variables or literals present in the context. Avoid introducing undefined identifiers. The goal is to stress the compiler's handling of constraint checking during template argument deduction for CTAD, which the bug report indicates can lead to crashes.
