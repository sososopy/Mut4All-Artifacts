Mutation Operator: Introduce nested template template parameter in a concept requirement. This mutation targets the definition of concepts that involve template template parameters, specifically when they are used to constrain partial specializations. It applies to concept definitions that currently do not involve nested template template parameters. The mutation adds a nested template template parameter requirement within a concept. For a given concept definition that currently uses a simple type requirement or other requirement, replace or add a nested template template parameter requirement. Use existing types or templates from the seed program. If no suitable template template parameter exists, introduce a new template template parameter. The new template template parameter should be declared at the nearest enclosing namespace scope if not already present. The declaration should be a simple template template parameter that takes a template template parameter itself, mimicking the structure from the bug report. For example, if the seed program has a concept C defined as `template <class T> concept C = requires { typename T::type; };`, mutate it to `template <class T> concept C = requires { template <template <class> class> struct void_t {}; typename void_t<T::template nested>; };` where `void_t` is introduced if not present, and `nested` is a hypothetical nested template member of T. Ensure that the mutated concept is used to constrain a template, such as a class template or its partial specialization, to trigger compiler code paths similar to the bug.
