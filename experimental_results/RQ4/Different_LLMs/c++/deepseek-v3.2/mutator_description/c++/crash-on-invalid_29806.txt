mutation operator

Target: Unnamed struct or union declarations within Microsoft extension contexts, specifically when the compiler's Microsoft extensions flag is not enabled. This applies to code where a struct or union body is defined without a tag name, which is permissible under Microsoft extensions but invalid in standard C++.

Change: Insert an unnamed struct or union declaration into the seed program at a scope where such a declaration could syntactically appear, such as within a function body or at global scope, but only if the seed program does not already contain Microsoft extension syntax. This mutation forces the compiler to parse an extension-specific construct without the corresponding flag being set, testing the assertion check for `getLangOpts().MicrosoftExt`.

Procedure: Locate a position in the seed program where a variable declaration or a block of code can be modified, such as inside a function or at global scope. Replace an existing simple statement or add a new line with the following construct:
struct { int x; };
or
union { char a; int b; };
Use types and variable names that already exist in the seed program to avoid introducing undeclared elements. For example, if the seed program contains a type `int` and a variable name `x`, use `int x;` inside the struct body. If no suitable types or names exist, introduce a simple built-in type like `int` and a generic name like `data`, ensuring it is declared within the struct body only, not externally.

Example: In a seed program with a function `void f() { int y = 0; }`, mutate to `void f() { struct { int y; }; int y = 0; }`. This introduces an unnamed struct with a member `y` using an existing variable name and type.

Note: This mutation does not require the Microsoft extensions flag to be enabled in the compiler options. It aims to trigger a crash when the compiler asserts that the flag must be set for parsing such constructs, as seen in the bug report where the parser fails on an invalid token during struct body parsing.
