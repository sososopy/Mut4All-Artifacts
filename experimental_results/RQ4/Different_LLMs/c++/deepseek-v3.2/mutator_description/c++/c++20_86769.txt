From the bug report, we observe that the compiler crash occurs when processing a class template with a concept constraint and a friend declaration that also uses the concept. The crash is triggered during template argument deduction for a variable declaration with CTAD (Class Template Argument Deduction) in main. The issue involves concepts, constraints, friend declarations, and CTAD. Structures that are more likely to trigger C++ compiler bugs include: complex interactions between concepts and template constraints, friend declarations inside constrained templates, and CTAD with constrained templates. We design a mutation operator targeting such interactions.

Mutation Operator: Replace a constrained template parameter in a class template with a different constrained template parameter that uses the same concept but possibly from a different template, or introduce a friend declaration that references a constrained template parameter when the class itself is constrained. Specifically, we mutate the friend declaration in a constrained class template to use a different constrained parameter or to refer to the same concept but in a different context.

Target: This mutation applies to class templates that are constrained by a concept and contain a friend declaration that also uses a concept. The mutation changes the friend declaration's template parameter constraint or adds a new friend declaration with a different constraint.

Procedure: In a seed program, if there exists a class template with a concept constraint and a friend declaration that uses a concept, modify the friend declaration. For example, if the seed has: template <ConceptName T> class ClassName { template <ConceptName U> friend class AnotherClass; }; change it to: template <ConceptName T> class ClassName { template <DifferentConceptOrSameConceptButDifferentParameter U> friend class AnotherClass; } or add a second friend declaration: template <ConceptName T> class ClassName { template <ConceptName U> friend class AnotherClass; template <ConceptName V> friend class DifferentClass; }. Ensure that the new concept or constraint exists in the seed program; if not, introduce a simple concept that always evaluates to true (like the one in the bug report: concept X = true) using existing types. The introduced concept should be declared as: template<typename T> concept NewConceptName = true; and then used in the friend declaration.

Example: Original seed code snippet: template<typename T> concept C1 = true; template <C1 T> class MyClass { template <C1 U> friend class MyClass; }; Mutated code: template<typename T> concept C1 = true; template<typename T> concept C2 = true; template <C1 T> class MyClass { template <C2 U> friend class MyClass; }; Alternatively, add: template <C1 T> class MyClass { template <C1 U> friend class MyClass; template <C1 V> friend class OtherClass; }; where OtherClass is another template class present in the seed (if not, declare a simple template class: template<typename W> class OtherClass {};).

Changes: Add a new concept declaration if needed, using existing types or a dummy type. Modify the friend declaration's constraint to use the new concept, or add an additional friend declaration with the same or different concept constraint. This mutation should be applied only when the seed program already contains a class template with a concept constraint and a friend declaration involving a concept.
