Mutation operator: Replace a concept constraint in a constructor's requires clause with a different concept that is already defined in the seed program, or introduce a concept constraint that references a function with a different overloaded signature.

Target: This mutation applies to constructors (including templated constructors) that have a requires clause using a concept. The seed program must contain at least one concept definition and at least one overloaded function (or multiple functions with the same name) that can be referenced by a concept.

Change: Identify a constructor with a requires clause that uses a concept. If the seed program contains another concept, replace the concept in the requires clause with that other concept. If no other concept exists, create a new concept that references a different overloaded version of a function already present in the seed program. For example, if the seed program has a function named f with multiple signatures (e.g., f(T) and f(U)), modify the concept to use a different overload. Specifically, change the concept definition to use a different function signature, and then update the constructor's requires clause to use this modified concept. The new concept should be declared in the same namespace or scope as the original.

Example: In the bug report, the concept matches uses f(type<T>()). Suppose the seed program also has another function f with a different parameter type, such as f(constrained const &). Create a new concept, e.g., concept matches2 = f(constrained const &); and change the constructor's requires clause from requires matches<U> to requires matches2<U>. If the seed program lacks a second function f, introduce a new overload by adding a function declaration (e.g., a dummy function with a different parameter type) before defining the concept, but only if it does not cause undeclared identifier errors. Prefer using existing functions and types.
