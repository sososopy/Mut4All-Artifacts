Mutation operator: Lambda capture of structured binding with mismatched reference qualifier.

This mutation applies to lambda expressions that capture structured binding declarations from a surrounding scope. The operator modifies the lambda capture list by changing the reference type of the captured structured binding to mismatch its original declaration. Specifically, if the structured binding is declared as a non-reference (e.g., using auto), the mutation adds a reference capture. Conversely, if the structured binding is declared as a reference (using auto& or auto&&), the mutation removes the reference qualifier to create a non-reference capture.

The mutation targets the capture clause of a lambda that follows a structured binding statement. It uses the same variable names already present from the structured binding. No new data names, types, or variable names are introduced.

Example: Given a seed program containing:
auto& [a, b] = some_function();
auto lambda = [a, b] { return a + b; };

The mutation changes the lambda capture to:
auto lambda = [&a, &b] { return a + b; };

Alternatively, if the original structured binding uses auto without a reference:
auto [a, b] = some_function();
auto lambda = [&a, &b] { return a + b; };

This operator achieves coverage by exploiting compiler handling of structured bindings in lambda contexts, where reference mismatches may trigger internal inconsistencies during capture analysis. It uses existing variables and avoids undeclared elements.
