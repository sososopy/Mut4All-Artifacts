mutation operator
Target: Exception specification mismatch in function pointer declarations within nested struct/union/class bodies.
This mutation operator applies when a seed program contains a struct, union, or class definition (including anonymous types) that includes a member which is a function pointer or a function type (e.g., in a typedef). The operator modifies the exception specification (e.g., noexcept, throw()) of that function type to create a mismatch between the type and its associated TypeLoc size, potentially triggering assertion failures during AST construction.

The operator first identifies a function pointer or function type declaration inside a struct/union/class body. For example, if the seed has: struct S { void (*f)(int); }; it targets 'f'. The mutation changes the exception specification by either adding one if absent, removing one if present, or altering its form. Specifically, it replaces the function type with a version that has a different exception specification, ensuring the base type remains the same (same parameter types, return type). If the original has no exception specification, mutate to add 'noexcept'. If original has 'noexcept', mutate to remove it or change to 'noexcept(false)'. If original has dynamic exception specification like 'throw(...)', mutate to remove it or change to 'noexcept'.

When introducing new exception specifications, use only the keywords 'noexcept', 'noexcept(false)', or 'throw()', which are valid in C++ without additional declarations. Do not invent new types or variables. The mutation must preserve existing variable names and types; only the exception specification part of the function type is altered. For example, given: union U { typedef void Func(int); }; mutate to: union U { typedef void Func(int) noexcept; }. Or given: class C { void (*p)(double) noexcept; }; mutate to: class C { void (*p)(double); }.

The change is applied directly to the source code at the location of the function type within the struct/union/class body. Ensure the mutated code remains syntactically valid C++ (e.g., if removing 'noexcept', the syntax still compiles). This mutation aims to expose bugs where the compiler incorrectly handles TypeLoc size updates for exception specifications in nested type contexts, particularly at end-of-file parsing scenarios.
