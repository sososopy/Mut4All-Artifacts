Mutation Operator: Replace concept definition with self-referential requires clause containing the concept itself.

This mutation operator targets C++20 concept definitions. It applies to any concept declaration that includes a requires clause. The mutation changes the requires clause to introduce a parameter that is declared using the concept being defined, creating a self-referential dependency. This mimics the bug report's structure where a concept C uses (C auto x) within its own definition.

The operator scans the seed program for concept declarations. For each concept declaration that has a requires clause, it modifies the requires clause by adding a parameter that uses the concept's own name. Specifically, within the requires clause's parameter list, replace an existing parameter or add a new parameter with the form: the concept's name followed by auto and a parameter name. If the requires clause currently has no parameters, insert one. Use the concept's own identifier as the type constraint. For example, if the concept is named ConceptName, change the requires clause to include (ConceptName auto param). The parameter name should be chosen from existing variable names in the seed program to avoid introducing undeclared identifiers. If no suitable variable name exists, introduce a new parameter name such as 'x', but ensure it does not conflict with existing names in the scope.

Changes: Locate a concept declaration. Identify its requires clause. Alter the parameter list inside the requires clause to include a parameter typed with the concept itself using auto. For instance, if the original concept is: template<typename T> concept C = requires(T t) { t.foo(); }; mutate to: template<typename T> concept C = requires(C auto x, T t) { t.foo(); }; or if the requires clause originally had no parameters, mutate from: template<typename T> concept C = requires { typename T::value; }; to: template<typename T> concept C = requires(C auto x) { typename T::value; };. The mutation should preserve the original requires expression body (the part inside {}) unchanged. This creates a self-referential constraint that may trigger compiler assertion failures during constant expression evaluation, similar to the reported bug.
