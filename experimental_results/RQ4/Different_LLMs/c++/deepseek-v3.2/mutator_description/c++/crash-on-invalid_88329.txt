Mutation operator: Replace template non-type parameter with a pointer dereference in a deduced context.

This mutation operator applies to template declarations that have a non-type template parameter with type auto. It targets situations where a template parameter is used within a template argument list, specifically when the template argument is formed by applying an operator to the parameter. The mutation modifies the template argument expression to include a pointer dereference on the parameter, which can trigger issues in auto type deduction when the parameter is not a pointer.

To apply this mutation, examine the seed program for any template that has a non-type template parameter declared as auto. For each such template, look for instances where the template parameter is used directly as a template argument, or within an expression that serves as a template argument. The mutation changes the template argument expression from using the parameter directly to applying the unary * operator to it, forming *T. This should be done in contexts where T is expected to be deducible, such as in the return type of a function template or within a nested template specialization.

If the seed program contains a template like: template <auto T> struct S {};, and there is a function or another template that uses T as a template argument, mutate that usage to *T. For example, if there is a function template: template <auto T> S<T> f() { return {}; }, change it to: template <auto T> S<*T> f() { return {}; }. Ensure that T is already declared in the template parameter list. No new variables or types are introduced; only the expression is altered by adding the dereference operator.

This mutation is designed to expose bugs in the compiler's handling of auto deduction when the template argument is a dereferenced non-type parameter, which may lead to incorrect classification of expressions and assertion failures, as seen in the bug report. It focuses on template metaprogramming constructs where auto parameters are used in complex expressions, increasing the likelihood of triggering crashes in the type deduction system.
