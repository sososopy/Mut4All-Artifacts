mutation operator: Replace an unconstrained template member declaration within a class with a constrained template member declaration using a concept that references a template type parameter from an outer class template. This mutation targets class templates with nested templates, particularly inner class templates or member templates, and applies when a template member (like a member function, class, or alias) is defined without constraints. The mutation introduces a requires clause that uses a concept which depends on a template parameter from the enclosing class template. For example, if a seed program contains a class template S with a template parameter T and an inner member template function f with its own template parameter U, the mutation adds a requires clause to f that uses a concept C referencing T. The concept C must be declared in the seed program or introduced if not present. If not present, declare concept C as a template that accepts a type and evaluates to true, such as template<typename X> concept C = true;. Use existing template parameter names from the seed program. Avoid introducing ambiguous or invalid types. For instance, change: template<typename T> struct S { template<typename U> void f(); }; to: template<typename T> struct S { template<typename U> requires C<T> void f(); }; where C is either already defined or added as a trivial concept. Ensure the concept uses T, the outer template parameter, to create a dependency that may stress constraint checking during instantiation.
