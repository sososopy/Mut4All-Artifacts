Mutation operator: Replace constrained template function return type deduction with explicit return type using decltype on constraint expression.

This mutation applies to C++20 or later code containing a constrained function template that uses auto return type deduction. Specifically, it targets functions with a requires clause that includes a decltype expression, where the return type is auto. The mutation changes the auto return type to an explicit type derived from the decltype expression used in the constraint.

The mutation modifies the function signature by replacing 'auto' with the type obtained from the decltype expression within the requires clause, ensuring the type already exists in the context. For example, if the original function is: template<typename T> auto func(auto x) requires (some_constraint<decltype(x)>) { return x; }, it becomes: template<typename T> decltype(x) func(auto x) requires (some_constraint<decltype(x)>) { return x; }. The decltype(x) must refer to a parameter or expression already present in the function prototype.

In practice, for the given bug pattern, the original create_unique function uses auto return type. The mutation would change it to explicitly use the Type alias already defined within the function body, making the return type explicit. However, to adhere to the rule of using existing elements, the mutation will use the decltype expression from the constraint directly if it is valid as a return type. For instance, the mutated code becomes: template<class Base, template<class...> class S> inline std::remove_cvref_t<decltype(S{std::forward<decltype(args)>(args)...})> create_unique(auto&&... args) -> std::unique_ptr<Base> requires(std::derived_from<std::remove_cvref_t<decltype(S{std::forward<decltype(args)>(args)...})>, Base>) { using Type = std::remove_cvref_t<decltype(S{std::forward<decltype(args)>(args)...})>; return std::make_unique<Type>(std::forward<decltype(args)>(args)...); }. Here, the return type before the arrow is changed from auto to the explicit decltype expression that appears in the constraint, which is already used in the function body. This mutation stresses the compiler's handling of complex decltype expressions in return types when combined with template constraints, potentially exposing crashes in name mangling or type deduction.
