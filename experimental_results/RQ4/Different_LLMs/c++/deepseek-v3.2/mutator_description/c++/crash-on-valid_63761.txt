Mutation operator: Mutate constexpr loops modifying containers by altering iteration counts to probe boundary conditions in container reallocation logic.

This operator applies to constexpr functions containing loops that call mutating member functions of standard library containers (like std::vector, std::string). The operator mutates the loop's iteration count to values near and including container growth boundaries. Specifically, for a loop that repeatedly inserts elements into a container, replace the original loop count with a set of values designed to expose potential off-by-one errors in container capacity management during constant evaluation.

To implement, identify a constexpr function containing a loop where each iteration calls a container's mutating operation (e.g., insert, push_back, emplace_back). Use the existing loop counter and container variable. For the loop's upper bound expression, replace it with a sequence of mutations. For instance, if the original loop is `for (int i = 0; i < N; ++i) container.insert(...);`, generate mutated versions where N is replaced by: 1) N-1 (one less iteration), 2) N (original, but preserved for context), 3) N+1 (one more iteration), 4) 2*N (double the iterations), and 5) a value like 57 (as in the bug report, which may relate to a specific internal capacity threshold). The mutation must only use existing variables and constants; no new types or functions are introduced. The loop counter type and variable names remain unchanged.

Example: Given the seed code `constexpr bool test() { std::vector<int> v; for (int i = 0; i < 10; ++i) v.push_back(i); return true; }`, the mutation would create versions with loops like `for (int i = 0; i < 9; ++i) ...`, `for (int i = 0; i < 11; ++i) ...`, `for (int i = 0; i < 20; ++i) ...`, and `for (int i = 0; i < 57; ++i) ...`. Each mutated loop uses the same container variable `v` and operation `push_back`. This targets potential compiler bugs in handling container reallocation at specific sizes during constexpr evaluation.
