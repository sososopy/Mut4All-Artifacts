mutation operator
This mutation operator targets the instantiation of templated member functions of templated classes, specifically when default arguments are involved. The operator modifies how a templated member function with a default argument is specialized or called, focusing on mismatches between the default argument type in the primary template and the specialized version. It applies when a templated class contains a templated member function with a default argument, and there exists an explicit specialization (full or partial) of that member function or its enclosing class.

The operator performs the following changes: For a templated class with a template template parameter, if it has a templated member function where the parameter type uses that template template parameter and has a default argument, and there is an explicit specialization of that member function for a specific template argument, modify the specialization to have a different parameter type than expected by the primary template's default argument. Specifically, change the parameter type in the specialization to a type that is not compatible with the default argument from the primary template, while keeping the function signature otherwise consistent. If the seed program does not have such a specialization, create one by introducing an explicit specialization of the member function for a specific instantiation of the outer class template. Use existing template names and types from the seed program. For example, if the seed has a structure like: template <template <typename> class T1> class A1 { public: template <typename T2> void b(T1<T2> = T1<T2>()); }; then introduce an explicit specialization such as: template <> template <typename T2> void A1<SomeImpl>::b(SomeImpl<T2>*) {} // Changed parameter to pointer type, mismatching the default argument. Ensure the specialization is defined outside the class. Then, in code that uses the class, call the member function without providing an argument to rely on the default argument, e.g., A1<SomeImpl> a; a.b<int>();. This creates a scenario where the compiler must reconcile the default argument from the primary template with the specialized function signature, potentially exposing crashes in template instantiation or overload resolution logic.

The key is to create a mismatch that the compiler might not handle gracefully during the parsing or semantic analysis of the call. The mutation should use types and names already present in the seed; if a new type is needed, it should be a simple variant like adding a pointer or reference to an existing type. Avoid introducing entirely new types unless absolutely necessary, and if so, declare them as trivial structs. The goal is to trigger crashes similar to the bug report, where the compiler fails when compiling templated methods in templated classes with default arguments in specialized contexts.
