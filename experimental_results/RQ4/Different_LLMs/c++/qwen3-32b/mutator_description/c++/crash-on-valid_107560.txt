Mutation Operator: Add a nested forwarding helper function call in perfect forwarding scenarios to increase template instantiation depth.  
Target: Functions using std::forward<T> with variadic templates or complex template parameters.  
Implementation:  
- Declare a helper function within the same scope as the original code (using existing types/variables).  
- Modify the call to std::forward<T> by wrapping it with the helper function, e.g.,:  
  Original: forward<_Arg>()  
  Mutated: helper_forward<_Arg>(forward<_Arg>())  
- Define helper_forward as:  
  template<class T>  
  constexpr T&& helper_forward(T&& arg) { return static_cast<T&&>(arg); }  
- Apply this mutation to all instances of std::forward in templated contexts.  
Example:  
Before: return forward<_Arg>();  
After: return helper_forward<_Arg>(forward<_Arg>());  
Coverage: Affects variadic templates, template metaprogramming, and perfect forwarding patterns commonly found in standard library implementations.  
Rationale: Increases template instantiation depth and exposes issues in the compiler's handling of nested forwarding expressions during template substitution. The helper function introduces additional indirection layers that may replicate the crash path observed in the original bug report.
