Mutation operator: Add explicit template arguments to a non-template function call in a constexpr context  
Applies to: Function calls within constexpr expressions, particularly those involving decltype or template-like syntax  
Illustration:  
Original code:  
return std::tuple_size<decltype(static_cast<Tuple&>(*this)._data)>;  

Mutated code:  
return std::tuple_size<decltype(static_cast<Tuple&>(*this)._data)>();  

Changes required:  
1. Locate any non-template function call within a constexpr evaluation  
2. Append angle brackets with arbitrary parameters (e.g., <1> or <int>) to the function identifier  
3. Ensure the function remains non-template (no prior template declaration)  
4. Maintain valid syntax structure by matching argument count  
5. Prefer applying to functions already used in template contexts in the seed program  
6. The mutation must preserve the function's original parameter list while introducing the template syntax error  

Example mutation mechanism:  
For function calls like `f(a,b,c)` in constexpr expressions, replace with `f<invalid_template_arg>(a,b,c)` where `invalid_template_arg` is either:  
- An undefined type name from the seed program's current scope  
- A literal value (e.g., 42, "string", true) not matching any template parameter constraints  
- A mix of both in the template argument list
