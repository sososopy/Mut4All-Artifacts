Mutation Operator: LambdaFoldPackCapture  
Applies to: Fold expressions over parameter packs within lambda expressions. Specifically targets code where a parameter pack is expanded in a fold expression inside a lambda capture, or where a lambda is part of a pack expansion that uses a fold.  

Action: Replace a simple fold operation (e.g., + ... or && ...) over a pack with a lambda that captures pack elements and explicitly performs the equivalent operation inside the lambda body. For example:  
Original fold: `(a + ... + 0)`  
Mutated form: `([a] { return a + 0; }() + ...)`  

This forces the compiler to instantiate a lambda for each pack element and evaluate the folded lambda expressions, exercising complex interactions between lambda captures and pack expansion semantics. The mutation uses existing pack parameters and operations from the seed program, ensuring compatibility with programs already using fold expressions or lambdas.  

Example in pseudo-code:  
Before: `auto result = (expr * ...);`  
After:  `auto result = ([expr]{ return expr * 0; }() * ...);`  

The change leverages existing variables (`expr`) and operations (*), avoiding new declarations. This mutation is likely to expose bugs in template instantiation or AST traversal logic when handling nested lambdas in pack contexts.
