Mutation Operator: Template Typedef with Nested Lambda Instantiation
Applies to template classes taking a non-type parameter that is a callable object (like a lambda) and using it in a dependent type alias. Targets template instantiation logic when substituting types in decltype expressions involving operator().

Modifications:
1. In an existing template struct/class with a non-type parameter Lambda (callable type), add a nested template type alias that uses decltype(Lambda.operator()<T>(...)) with T being the template parameter of the nested alias.
2. Ensure the outer template is instantiated with a local lambda defined in main() or another function scope, not a template parameter type.

Example:
Original code snippet with template struct Foo<T>:
struct Foo {
   using Type = int;
};

Mutated code:
template <auto F>
struct Foo {
   template <typename T>
   using Type = decltype(F.template operator()<T>(0));
};
auto lambda = [](auto x) { return x; };
using T = Foo<lambda>::Type<int>;

This creates a scenario where the compiler must:
1. Substitute the local lambda into the template parameter
2. Resolve the nested template operator() with a type parameter
3. Evaluate decltype on the result during alias instantiation
