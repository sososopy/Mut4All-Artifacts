Mutation operator: Add consteval conversion function to a user-defined type with a consteval constructor. Apply this to any struct/class that already has a consteval constructor but no conversion operator. The mutation inserts a consteval conversion operator returning a built-in type (e.g., int, bool, float) to force evaluation during initialization. This creates a scenario where the compiler must handle nested consteval evaluations, potentially exposing assertion failures in type construction logic.

Example:
Original:
struct X {
   consteval X() {}
};

Mutated:
struct X {
   consteval X() {}
   consteval operator int() { return 0; }
};

int main() {
   int y = X{};  // Forces evaluation of the conversion function
}

This creates the same evaluation path as the bug report by combining consteval constructor with consteval conversion, triggering potential flaws in how the compiler handles nested constant evaluation contexts during type construction.
