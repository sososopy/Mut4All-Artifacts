Mutation Operator: Vararg Operator Overload Conflict  
Target a class or struct definition that includes at least one operator overload. Insert two new friend operator declarations: (1) a non-vararg operator with a first parameter matching the class type and a specific second parameter type, and (2) a vararg operator with the same first parameter but ellipsis (...) as the second parameter. Place them in the class scope with distinct accessibility (e.g., one public, one private). The mutation should trigger ambiguous overload resolution when the operator is invoked in an expression where the second argument is of the specific type but the vararg variant exists.  

Example:  
Original code:  
class MyClass {  
public:  
  friend void operator,(MyClass, int);  
};  

Mutated code:  
class MyClass {  
public:  
  friend void operator,(MyClass, int);  
private:  
  friend void operator,(MyClass, ...);  
};  

const char* s = (MyClass(), 1, "test");  

This mutation creates a conflict between the specific `int` overload and the vararg ellipsis overload, forcing the compiler to resolve an ambiguous comma operator usage. The vararg variant may trigger internal compiler errors or incorrect overload selection, exposing front-end bugs in overload resolution logic.
