Mutation operator: Replace a constructor with a parameterless version in a class that requires arguments for initialization, creating a mismatch between constructor calls and available definitions.

Applies to: Classes with explicit constructors taking at least one parameter in their definition.

Example: For a class originally defining `class X { X(T); }`, change to `class X { X() {} };` while retaining existing code that attempts to construct X with arguments like `X x = f();`.

The mutation alters only the constructor signature, ensuring existing code using the class with arguments will trigger the compiler's initialization sequence handling where the parameter count mismatch causes assertion failures in template instantiation or implicit constructor generation. This targets the compiler's type-checking during template instantiation and constructor selection, particularly in complex template scenarios where constructor parameter validation may be error-prone.

Existing code structure required: A class declaration with a user-defined constructor that takes type parameters, and at least one location where the class is constructed with arguments in the program. No new variables or types need to be introduced.
