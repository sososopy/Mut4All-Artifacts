Mutation Operator: Add nested-name-specifier to pointer-to-member in template function arguments  
Applies to: Pointer-to-member declarations in function templates or template instantiations  
Target structure: Use of nested-name-specifier (e.g., Scope::) in pointer-to-member expressions within template argument lists  

Example:  
Original code:  
template <typename T>  
void func(T* ptr) { ... }  
Call: func<SomeClass>(&SomeClass::member);  

Mutated code:  
template <typename T>  
void func(T* ptr) { ... }  
Call: func<SomeClass>(SomeBase::SomeClass::&member);  

Changes required:  
1. Take an existing pointer-to-member argument (e.g., &SomeClass::member) from the seed program  
2. Insert redundant nested-name-specifier before the class name using an accessible base class or namespace from the program  
3. Add scope resolution operator (::) between the class and member name if missing  
4. Ensure all referenced classes/namespace have been previously declared in the seed program  

The mutation forces compiler to parse nested-name-specifier in pointer-to-member context during template instantiation, exploiting potential parsing ambiguities between scope resolution and member pointer syntax. This directly targets the crash-on-valid bug by creating complex nested scope resolution patterns in standard library template instantiations.
