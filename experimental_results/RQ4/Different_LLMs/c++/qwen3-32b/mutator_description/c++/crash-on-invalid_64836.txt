Mutation Operator 1: Objective-C++ Class Member with Dependent Type after Syntax Error  
Applies to: C++ class definitions in Objective-C++ mode when the class body contains a syntax error followed by a member with a dependent type derived from an invalid or undeclared static function.  

**Mechanism**:  
1. Insert a syntax error (e.g., misplaced token, incomplete declaration) within a class body.  
2. Add a class member that uses a template or decltype referencing a static function that is either:  
   - Not declared in the class, or  
   - Has incomplete/invalid syntax.  

**Example Mutation**:  
```cpp  
class B {  
  p   // syntax error (undefined identifier)  
  static void foo() {}  // Existing or newly declared function  
  C<int, decltype(foo)> c;  // Depends on foo()  
};  
```  

**Impact**:  
- Forces the compiler to parse a dependent type (`decltype(foo)`) even when a prior syntax error exists in the class body.  
- Triggers assertion failures in token handling if the parser incorrectly processes the dependent type after an error.  

**Implementation Notes**:  
- Prefer reusing existing static functions in the class (e.g., `foo`). If none exist, declare a minimal `static void foo() {}` in the class.  
- The syntax error must appear before the dependent type member to ensure early error detection.  
- Does not require new types or external dependencies.
