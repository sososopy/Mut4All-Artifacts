Mutation Operator: AddNonTypeTemplatePackToFunctionTemplate
Applies to function templates with at least one type parameter. Adds a non-type template parameter pack to the template parameter list, but does not expand the pack in the function body. This forces the compiler to instantiate the function with an unevaluated parameter pack, triggering template instantiation logic that may expose crashes.

Example transformation:
Original function template:
template <typename T>
void example(T x) { ... }

Mutated version:
template <typename T, auto... P>
void example(T x) { ... }

The mutation:
1. Adds a new non-type template parameter pack 'P' of type 'auto'
2. Preserves all existing parameters and function body
3. The parameter pack 'P' is never expanded in the function body

Key properties:
- Uses existing function templates from the seed program
- Requires no new declarations (works with any existing template parameter)
- Creates an invalid but syntactically valid template (compiler should reject but may crash)
- Forces template instantiation with complex parameter pack handling

This mutation exploits the fact that compilers often have special-case handling for parameter packs that may not be robust when the pack is present but unexpanded. The undefined behavior in template instantiation combined with the compiler's error recovery code can expose crashes in the Sema::InstantiateFunctionDefinition path.
