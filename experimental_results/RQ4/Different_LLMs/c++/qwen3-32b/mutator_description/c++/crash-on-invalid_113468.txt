Mutation Operator: InsertBreakInInvalidContext  
Applies to: Compound statements (statement expressions) within conditional expressions in constexpr functions. Targets locations where a compound statement is used as a subexpression (e.g., if conditions, return expressions) and introduces a break statement inside the compound statement.  

Example:  
Original code:  
constexpr int f() { return (0); }  

Mutated code:  
constexpr int f() {  
  return ( { int x; x = 0; if (x) break; } );  
}  

This creates a compound statement with a break in a context where it is invalid (outside a loop/switch). The mutation uses existing variables (e.g., x) from the seed program or introduces minimal new variables if necessary. The compound statement is placed within a constexpr return value to force constant expression evaluation during compilation.  

The mutation triggers assertion failures in the compiler when processing invalid control flow constructs during constexpr evaluation. It avoids using complex or ambiguous constructs, relying instead on standard C++ statement expressions (valid in GCC/Clang) that expose internal state handling issues in Clang’s constant evaluator.
