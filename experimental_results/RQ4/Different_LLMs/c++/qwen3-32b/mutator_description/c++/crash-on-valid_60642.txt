MutationOperator: NestedConceptLambdaEval
Applies to code with a template concept definition using a requires clause on a lambda's operator<>, and a separate concept that is always true. The mutation involves creating a second concept that applies the first concept to a lambda with a template parameter constrained by the simple concept, then asserting the second concept.

Examples:
Before:
template<auto Q> concept C = requires { Q.template operator()<int>(); };
template<class> concept D = true;

After:
template<class> concept E = C<[]<D>{}>;
static_assert(E<int>);

The mutation replaces existing concepts/static_asserts with this nested pattern, using the existing 'C' concept and 'D' concept from the seed program. No new variables or types are introduced, only reusing the existing concepts and creating a new concept E that composes the evaluation of C's requires clause within a concept parameter. This creates a nested constraint evaluation scenario that triggers the ICE in the constraint satisfaction path of the compiler.
