Mutation Operator: ReorderEmbedParamsWithInvalidFirst  
Applies To: #embed directives that contain multiple parameters (at least one valid and one invalid).  
Changes: For an #embed directive with multiple parameters, reorder the parameters so that an invalid (unrecognized) parameter precedes a valid one. If the directive lacks an invalid parameter, introduce one by altering a valid parameter's name to an invalid form (e.g., appending "X" to its identifier) and then reordering the parameters to place the modified invalid parameter before a valid one.  

Example:  
Original:  
#embed __FILE__ limit(2) clang::offset(3)  

Mutated:  
#embed __FILE__ limitX(2) clang::offset(3)  

In this example, the parameter "limitX(2)" is invalid (unrecognized by the compiler), and it is placed before the valid parameter "clang::offset(3)". This reordering triggers the assertion failure described in the bug report.  

If the seed program already contains an invalid parameter in the #embed directive, the mutation simply moves it to precede a valid parameter. If not, the mutation introduces an invalid parameter by modifying an existing valid one and reorders the parameters accordingly.
