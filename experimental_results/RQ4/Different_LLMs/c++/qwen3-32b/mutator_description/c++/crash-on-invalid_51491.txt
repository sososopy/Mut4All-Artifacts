Mutation Operator 1: Insert export before template specialization outside module context  
Applies to: Template specializations (e.g., class member functions, member variables, or full specializations of templates) that exist in non-module code.  
Action: For an existing template specialization that is not within a module interface unit, add the `export` keyword before the template declaration.  

Example mutation:  
Original code:  
```cpp  
template <class T>  
class C {  
public:  
    static int value;  
};  
template <class T> int C<T>::value = 0;  
```  

Mutated code:  
```cpp  
template <class T>  
class C {  
public:  
    static int value;  
};  
export template <class T> int C<T>::value = 0;  // Invalid use of 'export' outside module context  
```  

Rationale: The `export` keyword is only valid in module interface units for template declarations. Adding it to a specialization in non-module code creates invalid syntax that should trigger a diagnostic rather than a crash. This targets the compiler's error recovery and AST parsing mechanisms, which may fail when handling `export` in unexpected contexts.  

Mutation Constraint: Only applies to specializations that are explicitly defined in the same translation unit where the template is declared. If the seed program does not use modules, this mutation will always create an invalid construct that should be rejected with a diagnostic but may instead cause a crash.
