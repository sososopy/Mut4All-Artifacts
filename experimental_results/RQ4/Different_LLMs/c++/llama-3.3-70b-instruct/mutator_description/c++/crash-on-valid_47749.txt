Mutation operator: TemplateInstantiationOperator
This operator targets code constructs that involve template instantiation, particularly those with generic lambda functions and template classes. It applies to template classes that are instantiated with local generic lambda functions, which could potentially trigger bugs related to template instantiation and type deduction.

The mutation involves replacing the template parameter type with a different type, such as a fundamental type or a user-defined type, to test how the compiler handles different type instantiations. For example, given a template class like `Factory<lambda>`, the mutation operator might change it to `Factory<int>` or `Factory<std::string>` to see how the compiler responds to different template arguments.

This mutation operator is designed to achieve high coverage across different program structures and features, especially those related to template metaprogramming and generic programming. By applying this operator to various parts of the code, we can test the compiler's ability to handle complex template instantiations and identify potential bugs in the process.

To apply this mutation operator, the following steps can be taken:
1. Identify template classes and functions in the code.
2. Determine the template parameters and their types.
3. Replace the template parameters with different types, such as fundamental types or user-defined types.
4. Compile the mutated code to see if it triggers any compiler errors or crashes.

For example, consider the following code:
```c
template <auto Lambda>
struct Factory {
  template <typename T>
  using Instance = decltype(Lambda.template operator()<T>(0));
};

int main() {
  auto lambda = [](auto){};
  using T = Factory<lambda>::Instance<int>;
}
```
The TemplateInstantiationOperator could mutate this code to:
```c
template <auto Lambda>
struct Factory {
  template <typename T>
  using Instance = decltype(Lambda.template operator()<T>(0));
};

int main() {
  using T = Factory<int>::Instance<int>;
}
```

By applying the TemplateInstantiationOperator to this code, we can test the compiler's ability to handle different template instantiations and identify potential bugs related to template metaprogramming.
