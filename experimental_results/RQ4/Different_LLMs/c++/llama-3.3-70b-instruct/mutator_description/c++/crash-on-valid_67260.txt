Mutation operator: ChangeTemplateInstantiationOrder
This mutation operator targets template metaprogramming constructs, specifically focusing on the order of template instantiation. It applies to any code that utilizes C++ templates, especially those involving complex template instantiations and recursive template metaprogramming. 

The goal of this operator is to alter the order in which template instantiations occur, which can lead to exposing bugs related to the compiler's handling of template instantiation, such as those resulting in out-of-bounds access or incorrect type handling.

To apply this mutation, the following steps are taken:
1. Identify all template instantiations within the given code.
2. For each identified template instantiation that involves dependent types or recursive instantiations, reorder the sequence of instantiations. This can be achieved by swapping the order of template parameter packs, altering the recursive instantiation patterns, or changing the way template specializations are defined and used.
3. Ensure that the mutated code still compiles and runs, but with a different template instantiation order.

Example in natural language: Consider a code snippet involving a recursive template metaprogramming idiom where a template `A` depends on another template `B`, which in turn depends back on `A`. The mutation would involve altering the definition orders of `A` and `B`, or changing how their template parameters are ordered, to see if the compiler correctly handles the changed instantiation sequence.

This mutation targets the bug labeled as "crash-on-valid" and is relevant because it can trigger issues related to how the compiler manages template instantiations, potentially leading to crashes or incorrect behavior when dealing with valid but complex template metaprogramming constructs.
