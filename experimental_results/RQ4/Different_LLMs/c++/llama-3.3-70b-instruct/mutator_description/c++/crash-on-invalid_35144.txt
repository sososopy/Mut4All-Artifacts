Mutation Operator: TemplateLambdaNesting
This operator targets code constructs involving recursive template instantiations and lambda functions, aiming to expose bugs related to type location and class handling in the compiler. 
It applies to code sections where a template function invokes a lambda function, which in turn calls the same template function, creating a recursive nesting of template instantiations and lambda expressions.
To apply this mutation, locate a template function that takes a type parameter and contains a lambda function. 
Then, modify the lambda function to call the same template function, passing a newly defined lambda function as an argument, thus creating a recursive template and lambda call chain. 
For example, consider a template function that takes a type and returns a lambda function, which in turn calls the same template function with another lambda function as its argument. 
This operator prefers using existing variables, types, and functions in the seed program, introducing new elements only when necessary, with clear and unambiguous declarations. 
The goal is to achieve high coverage of different program structures and features, particularly focusing on the interaction between template metaprogramming and lambda expressions. 
By applying this mutation operator, the tester can increase the likelihood of triggering bugs similar to the one described in the bug report, related to the handling of recursive template instantiations and lambda functions in the compiler.
