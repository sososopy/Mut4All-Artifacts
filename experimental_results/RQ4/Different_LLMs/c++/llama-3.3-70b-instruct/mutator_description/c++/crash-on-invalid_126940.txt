Mutation Operator: ReorderEmbedParameters
This mutation operator targets the #embed directive in C++ source code, specifically when it contains multiple parameters. It reorders the parameters in a way that a known parameter comes after an unknown parameter, which is similar to the scenario described in the bug report. 

The operator applies to any #embed directive with at least two parameters, where one of them is not recognized by the compiler. 

To apply this mutation, first identify #embed directives in the code. For each directive found, check if it contains more than one parameter. If so, attempt to identify a known parameter (like limit, offset) and an unknown parameter (like bla in the bug report). Then, if such parameters exist and are not already in the order of unknown followed by known, reorder them to place the unknown parameter before the known one. 

For example, given the original directive #embed __FILE__ limit(2) bla(3), this mutation operator would transform it into #embed __FILE__ bla(3) limit(2), mirroring the structure that triggered the assertion failure in the bug report. 

This operator is designed to test the compiler's ability to handle #embed directives with mixed known and unknown parameters, specifically focusing on the scenario where an unknown parameter precedes a known one, which the bug report indicates can cause a crash.
