Mutation Operator: Modify Structured Binding Declaration in Lambda Capture
This mutation operator targets C++17 code that uses structured bindings in lambda expressions. It applies to any lambda expression that captures variables introduced by a structured binding declaration.

The mutation involves replacing the capture of structured binding variables in a lambda expression with a capture of the original structured binding object. For example, given a structured binding declaration like "auto& [x, y] = get_point();" and a lambda expression that captures x and y, the mutation would result in the lambda expression capturing the object that x and y are derived from, effectively changing the capture from "[x, y]" to the object that was bound, such as "auto& point = get_point();" and then capturing "point".

To apply this mutation, first identify structured binding declarations where the bound variables are captured by a lambda expression. Then, replace the lambda capture of these variables with the capture of the original object that was used in the structured binding declaration. If necessary, adjust the lambda body to access the original object's members instead of the captured variables.

For instance, given:
struct Point { int x; int y; };
Point get_point() { return { 1, 2 }; }
int main() {
    auto& [x, y] = get_point();
    bool b = [x, y] { return x > y; }();
    return b;
}
The mutation could result in:
struct Point { int x; int y; };
Point get_point() { return { 1, 2 }; }
int main() {
    auto point = get_point();
    bool b = [point] { return point.x > point.y; }();
    return b;
}
This mutation operator is designed to test the compiler's handling of structured bindings in lambda expressions, aiming to expose bugs similar to the one described in the crash-on-invalid bug report. By modifying how variables are captured and accessed within lambda expressions, it stresses the compiler's frontend, particularly its ability to correctly process and validate C++17 features.
