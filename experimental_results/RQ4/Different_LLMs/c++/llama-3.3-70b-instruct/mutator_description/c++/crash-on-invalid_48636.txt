Mutation Operator: InvalidFunctionCall
The InvalidFunctionCall mutation operator targets function calls in the source code and modifies them to pass an incorrect number or type of arguments, which can trigger bugs related to error handling and recovery in the C++ compiler. This operator applies to all function calls in the code.

To apply this mutation, the following steps are taken:
- Identify a function call in the source code.
- Determine the number and types of arguments the function expects.
- Modify the function call to pass either the wrong number of arguments or arguments of incorrect types.

For example, consider a function declared as "void foo(int x, int y)". An example of applying the InvalidFunctionCall mutation could result in changing the function call from "foo(1, 2)" to "foo(1)" or "foo(1, 2, 3)" or even "foo('a', 2)", where the number or types of arguments do not match the function's declaration.

This mutation operator is designed to test how the compiler handles invalid function calls, which can lead to error recovery paths being executed, potentially exposing bugs like the one described in the bug report. By preferring the use of existing variables, types, or functions in the seed program, this mutation minimizes the introduction of new, potentially ambiguous elements.
