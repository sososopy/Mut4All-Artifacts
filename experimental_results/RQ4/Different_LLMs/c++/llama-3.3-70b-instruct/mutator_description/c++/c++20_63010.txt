Mutation Operator: Loop_Init_Modification 
This mutation operator targets the initialization part of range-based for loops and traditional for loops in C++ code, aiming to expose potential compiler bugs related to loop initialization, particularly those involving conditional expressions or complex syntax.

The operator applies to any loop that has an initialization part, which can include range-based for loops and traditional for loops. The goal is to modify the initialization expression, potentially altering the loop's behavior or the compiler's parsing logic.

To apply this mutation operator, follow these steps:
1. Identify all for loops (both range-based and traditional) in the given C++ code.
2. For each loop, locate the initialization part. In range-based for loops, this would be the expression before the colon (:), and in traditional for loops, it's the first part of the for statement.
3. Modify the initialization expression by applying one of the following changes:
   - If the initialization involves a conditional expression (ternary operator), swap the true and false branches of the condition.
   - If the initialization is a simple variable declaration or assignment, change the assigned value to a different constant or a variable that exists in the scope.
   - If the initialization involves a function call, replace the function call with a different function that exists in the code or with a constant value.
4. Ensure that any modifications made do not introduce new variables or types that are not already declared in the scope. If new elements need to be introduced for the mutation to make sense, specify their declarations clearly, avoiding ambiguity.

Example (in pseudo-code form):
Original Loop: 
for (auto x = condition ? value1 : value2 : collection);

Mutated Loop (swapping true and false branches):
for (auto x = condition ? value2 : value1 : collection);

This mutation operator is designed to stress the compiler's handling of loop initializations, especially in cases where conditional expressions or complex syntax are involved, by making targeted modifications to the code. The aim is to expose any compiler bugs that might exist in parsing or executing such loops, particularly under the C++20 standard.
